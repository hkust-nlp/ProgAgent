You are managing a network of public EV charging stations and need to produce a comprehensive dynamic pricing and availability forecast for the next twenty-four hours.

Begin by examining the available configuration and data files. You will find a YAML file that defines the pricing policy, including a reference timestamp that anchors the start of your twenty-four-hour forecast window, base electricity rates for each charger type, peak hour definitions expressed as clock hours, surcharge and discount amounts, and thresholds for utilization-based pricing adjustments. A JSON file contains grid tariff tier definitions that map predicted grid demand percentage ranges to price multipliers. Another JSON file specifies maintenance impact rules that determine surcharges applied to the remaining chargers in a zone whenever maintenance reduces the zone's available capacity by a certain percentage. A CSV file maps stations to zones and provides geographic coordinates. For each station listed in that mapping, a separate CSV file holds historical hourly usage data with twenty-four rows corresponding to clock hours 0 through 23, including an average utilization rate column needed for computing the utilization-based surcharge. The station usage filenames follow the pattern station_<STATION_ID>_usage.csv, where the station identifier matches the station_id column in the mapping file.

Retrieve the full list of chargers through pagination. For every charger, obtain its schedule of active charging sessions, confirmed reservations, and scheduled or in-progress maintenance windows that fall within the twenty-four-hour forecast window. Also retrieve the grid demand forecast for each zone and the count of active chargers per zone.

For each charger and each hour offset from 0 through 23, where offset 0 corresponds to the reference time and offset 23 corresponds to twenty-three hours later, determine the availability status using the following priority. If the charger is not active, the status is "offline" for every hour. Otherwise, if any scheduled or in-progress maintenance window overlaps the hour slot, the status is "maintenance". If no maintenance overlaps but an active charging session does, the status is "occupied". If neither maintenance nor a session overlaps but a confirmed reservation does, the status is "reserved". In all remaining cases the status is "available". An event overlaps an hour slot when the event's start time is strictly before the slot's end and the event's end time is strictly after the slot's start. Each hour slot runs from the reference time plus the offset in hours to the reference time plus the offset plus one hour.

For pricing, compute a dynamic rate for each charger-hour combination whose availability is neither "offline" nor "maintenance". Start with the base rate for the charger's type from the pricing policy. If the clock hour of that slot appears among the peak hours listed in the pricing policy, add the peak surcharge; otherwise subtract the off-peak discount. Multiply this adjusted base by the demand multiplier, which is found by looking up the predicted demand percentage from the grid forecast for the charger's zone at that hour offset in the tariff tier table. To that product, add the utilization surcharge for the charger's station at the relevant clock hour: compare the station's historical average utilization rate at that clock hour against the thresholds in the pricing policy and select the corresponding surcharge level. Then subtract the renewable energy discount if the forecast renewable percentage for that zone and hour offset exceeds the renewable discount threshold defined in the pricing policy. Finally, add a maintenance zone surcharge calculated as follows: for the charger's zone and that hour, determine what fraction of the zone's total active chargers are under maintenance, express it as a percentage, look up the matching bracket in the maintenance impact rules, and apply that surcharge to every non-maintenance charger in the zone during that hour. Round the final price to exactly two decimal places.

Save the availability forecast as `availability_matrix.csv` with columns `charger_id`, `hour_0`, `hour_1`, and so on through `hour_23`. Each row represents one charger, rows sorted by charger_id in ascending order, and each cell contains exactly one of the five strings: `available`, `occupied`, `reserved`, `maintenance`, or `offline`. Save the pricing forecast as `pricing_matrix.csv` with the identical column layout. Each cell contains either the computed price as a number with exactly two decimal places or the literal string `N/A` for hours where the charger is offline or under maintenance.

Once both files have been written, report three summary metrics in your final response. Each metric must appear on its own line in exactly the format shown. Write `total_available_slots: ` followed by the integer count of cells in the availability matrix whose value is "available". Write `peak_pricing_hour: ` followed by the integer hour offset (0 through 23) whose column has the highest average price across all chargers with valid (non-N/A) prices in that column. Write `estimated_max_revenue: ` followed by the sum, computed over every cell where availability is "available", of that cell's price multiplied by the charger's power rating in kilowatts, with the final sum rounded to two decimal places.
