A national health authority has just released a set of updated clinical trial safety guidelines for the current year. These new guidelines, documented in a YAML configuration file named `new_guidelines_2026.yaml`, introduce requirements across several categories including adverse event reporting, dosage monitoring, informed consent, biospecimen handling, patient monitoring, and data integrity. Each guideline specifies which trial phases and therapeutic areas it applies to, along with its severity classification and whether it mandates a consent form update.

Your task is to produce a comprehensive compliance action plan by cross-referencing these new guidelines against all currently active clinical trials. For each active trial whose phase and therapeutic area fall within the scope of a new guideline, you must compute a priority score and determine the appropriate amendment type and compliance deadline. The resulting action plan must be saved as `compliance_action_plan.csv` with the following columns in this exact order: `trial_id`, `trial_name`, `site_id`, `guideline_code`, `guideline_category`, `severity`, `priority_score`, `amendment_type`, `deadline_days`.

The priority score for each trial-guideline pair is the sum of several components. First, a severity weight derived from the scoring matrix found in `severity_matrix.json`, which maps guideline severity levels to numeric weights. Second, an audit penalty calculated from the site's audit history: for each audit finding at the trial's site, look up the penalty in the matrix using the finding's resolution status and severity, then sum all penalties and cap the total at the maximum specified in the matrix. Third, a consent penalty based on the status of the trial's most recent consent form by approval date, using the penalty values from the matrix; if no consent form exists for the trial, apply the separate no-consent penalty from the matrix. Fourth, a phase-specific bonus from the phase requirements table in `phase_requirements.csv`, which maps each trial phase to a bonus value. Fifth, a site risk penalty: if an inspection report exists for the trial's site and the overall risk score stated in that report exceeds the threshold defined in the matrix, add the site risk penalty from the matrix. Sixth, a deviation penalty: if a trial dossier file exists for the trial and the protocol deviation count recorded in it exceeds the threshold in the matrix, add the deviation penalty from the matrix.

Amendment types follow a precedence order defined in `amendment_priority_rules.yaml`. If the guideline requires a consent update and the trial's latest consent is either expired or missing, the type is `urgent_consent_revision`. Otherwise, if the guideline requires a consent update but the consent is current or pending review, the type is `consent_and_protocol_update`. If neither of those conditions holds but the site has any open or overdue critical-severity audit finding, the type is `site_remediation_protocol`. In all remaining cases, the type is `standard_protocol_revision`. The deadline in days is determined by the priority score brackets in the same rules file: use the first bracket whose minimum score the computed priority meets or exceeds.

The action plan CSV must be sorted in descending order by priority score. Where two entries share the same priority score, sort them by trial identifier in ascending alphabetical order, and if those also match, by guideline code in ascending alphabetical order.

Separately, you must produce a consent update report saved as `consent_update_report.json`. This is a JSON array of objects, one per trial that is affected by at least one guideline requiring a consent update. Each object must contain the fields `trial_id`, `trial_name`, `current_form_version` (the version string of the trial's most recent consent form by approval date, or the string `none` if no consent exists), and `affected_guideline_codes` (a sorted list of the guideline codes that require consent updates for that trial). The array itself must be sorted by trial identifier in ascending order.

Once both files are written, provide a brief summary stating how many entries appear in the action plan, how many distinct trials are affected, how many distinct guidelines are involved, and how many trials require consent form revisions.
