You are a warehouse operations analyst responsible for generating optimized batch pick lists for the current shift. The warehouse contains a number of pending customer orders, each composed of multiple items stored in different zones across the facility. Your objective is to assign every pending order to an active picker and produce a route-optimized pick list for each assigned picker.

Begin by identifying all orders that are currently in pending status. Each order carries a priority level — urgent, express, or standard. Orders must be considered for assignment in priority order: all urgent orders first, followed by express, then standard. Among orders sharing the same priority level, process them in ascending order by their order identifier.

For every pending order, retrieve its constituent items. Each item references a particular SKU; look up each SKU to learn its per-unit weight in kilograms, per-unit volume in liters, and the warehouse zone where it is stored. Alongside these tool-based lookups, you must consult the batch manifest files found among your available data files, as each manifest row records a special handling designation for every order — one of "none", "fragile", "cold_chain", or "hazmat". This designation is only available in those manifest files and cannot be obtained through tool queries.

Separately, identify all currently active pickers and retrieve the capacity and current zone location for each one. A policy configuration file specifies operational limits for batches: a maximum batch weight in kilograms, a maximum batch volume in liters, and a maximum number of individual items per batch. For each picker, the effective weight limit for their batch equals whichever is smaller — the picker's own maximum weight capacity or the policy's batch weight limit. The same logic applies to volume. The policy's maximum items per batch is an additional hard constraint.

A certifications file maps each picker to two boolean flags indicating whether they hold cold-chain certification and whether they hold hazmat certification. Any order whose special handling is "cold_chain" may only be assigned to a picker who is cold-chain certified. An order designated "hazmat" must go to a hazmat-certified picker. Orders marked "fragile" or "none" carry no certification requirement.

To assign orders, iterate through the priority-sorted order list. For each order, compute the order's total weight as the sum of per-unit weight multiplied by quantity across all its items, and total volume likewise. Identify every eligible picker — one who is active, possesses any required certification, and whose remaining batch capacity in weight, volume, and item count can still accommodate the order. Among eligible pickers, select the one whose remaining weight capacity is greatest. If two or more pickers tie in remaining weight capacity, select the one with the lexicographically smallest picker identifier.

After all assignable orders have been placed, determine the pick route for each picker who received orders. A zone map file provides x and y coordinates for every zone. Starting from each picker's current zone, apply a nearest-neighbor traversal using Manhattan distance — the sum of absolute differences in x and y coordinates — to choose the next unvisited zone at each step. When two candidate zones share the same Manhattan distance, visit the one with the lexicographically smaller zone identifier first. Assign a one-based sequence number to each zone in the order it is visited.

For every picker with assigned orders, save a file named `pick_list_{picker_id}.csv`, substituting the picker's identifier (for example, `pick_list_P001.csv`). The file must contain exactly these columns in this order: `sequence`, `zone_id`, `zone_name`, `sku_id`, `sku_name`, `order_id`, `quantity`, `item_weight_kg`, `item_volume_liters`, `shelf_position`. The value of `item_weight_kg` equals the SKU's per-unit weight multiplied by the line-item quantity, rounded to exactly two decimal places. The value of `item_volume_liters` follows the same rule. Rows must be sorted by `sequence` ascending, then by `shelf_position` ascending, then by `sku_id` ascending as a final tie-breaker.

Produce a second file named `batch_summary.csv` containing one row per picker who has orders. Its columns must be `picker_id`, `picker_name`, `num_orders`, `num_items`, `total_weight_kg`, `total_volume_liters`, `num_zones`, `route_zones`. Here `num_items` is the sum of all item quantities in the picker's batch, `total_weight_kg` and `total_volume_liters` are each rounded to two decimal places, and `route_zones` is a semicolon-separated list of zone identifiers in visit order with no spaces. Sort the rows by `picker_id` ascending.

In your final response, state the result in exactly this format: "Total orders assigned: X. All constraints satisfied." where X is the integer count of orders that were successfully assigned across all pickers.
