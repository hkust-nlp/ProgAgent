You are a monetization analyst for a free-to-play game studio. The studio maintains a tiered player progression system and regularly runs limited-time events to drive engagement and spending. Your goal is to identify players who are significantly under-spending relative to what their engagement level and tier would predict, then produce a targeted promotion campaign list for the marketing team.

Begin by reading the configuration files that define the tier structure, the criteria for classifying a player as under-monetized, the available promotions, and the rules governing campaign assignment. A YAML file describes each tier's expected monthly spending in USD and an engagement weight, along with an analysis period expressed in months. A separate JSON file specifies the under-monetized definition: a spending ratio threshold below which a player qualifies, a minimum engagement score, a minimum spending-willingness rating, and the required account status. That same JSON file contains the engagement score formula, which combines three normalized components — playtime hours, event participation count, and total virtual currency earned — each divided by a respective cap and multiplied by a weight, then scaled by one hundred and capped at one hundred. A CSV catalog lists every available promotion with its identifier, name, type, eligible tiers, target game mode, discount percentage, and minimum gap ratio. Finally, a Markdown document explains the eligibility, matching, priority, and sort-order rules for campaign construction.

Once you understand the parameters, retrieve a complete roster of all players through the available listing tool, paginating as needed. For every player whose account status matches the required status in the segment criteria, query their total spending and compare it against the expected spending for their tier over the configured analysis period. Expected spending equals the tier's monthly rate multiplied by the analysis period in months. The spending ratio is the player's actual spending divided by that expected total. Only players whose spending ratio falls strictly below the threshold proceed to the next filter.

For each candidate that passes the spending filter, retrieve their engagement data — playtime hours, event participation count, and total currency earned — and compute the engagement score using the formula and constants from the criteria file, rounding the resulting score to two decimal places. Discard any candidate whose engagement score is below the minimum.

Player survey responses are distributed across multiple JSON batch files. Each record contains a player identifier, a preferred game mode, a spending willingness rating on a one-to-five scale, a device type, a region, and a feedback score. Collect all survey batches and look up each remaining candidate. If a candidate has no survey record or their willingness rating is below the minimum, they are excluded.

For every player that survives all filters, calculate the spending gap (expected minus actual), the gap ratio (gap divided by expected, rounded to four decimal places), and the priority score according to the formula in the criteria file (gap ratio times engagement score times willingness, divided by one hundred, rounded to two decimal places).

Next, assign each eligible player exactly one promotion from the catalog. Among all promotions whose target tiers include the player's tier or are marked as universal, whose target game mode matches the player's preferred game mode or is universal, and whose minimum gap ratio does not exceed the player's gap ratio, select the promotion with the highest discount percentage. Break ties by choosing the promotion whose identifier comes first alphabetically. If no promotion matches at all, assign the Gem Rush Deal as a fallback.

Save the final campaign list as `campaign_list.csv` with exactly these columns in order: `player_id`, `username`, `tier`, `actual_spending`, `expected_spending`, `spending_gap`, `gap_ratio`, `engagement_score`, `willingness`, `priority_score`, `assigned_promo_id`, `assigned_promo_name`. Sort rows by priority score descending; break ties by player identifier ascending.

Separately, write a `campaign_summary.json` file containing three keys: `total_under_monetized` (integer count of campaign entries), `tier_breakdown` (an object mapping each tier name to the number of players in that tier among the campaign list), and `total_potential_revenue` (the sum of all spending gaps across campaign entries, rounded to two decimal places).

In your final response, state the total number of under-monetized players identified, list the top five player identifiers by priority score, name the most common tier among the under-monetized group, and report the total potential revenue recovery figure.
