You are tasked with producing verified financial statements for every active fundraising campaign managed by the organization. Each campaign carries a tier designation that governs its fee schedule, and financial activity flows in from several independent channels that must all be merged before a final statement can be issued.

Revenue for each campaign arrives through two channels. The first is online payment gateway transactions recorded in the system, retrievable by campaign; only deposits marked as cleared should contribute to revenue. The second channel consists of offline deposits such as checks, cash, and wire transfers that have been logged in CSV batch files found among the available data files. Each batch file contains rows with a campaign identifier, deposit date, amount, payment method, and donor reference. Every CSV batch file whose content matches this structure must be read and incorporated.

In-kind contributions are tracked in the system with a base appraised value, a condition grade, and a category for each donated item. Some of these items have subsequently received an independent certified appraisal that replaces the original base figure. These certifications are stored in JSON files among the available data, each holding an array of records keyed by donation identifier with a certified value field. When a certification exists for a given donation, its certified value must be used instead of the base appraised value from the system. After selecting the appropriate base or certified amount, every in-kind donation must be adjusted by multiplying the value first by the condition multiplier for its grade and then by the weight for its category. Both sets of factors, along with other reconciliation parameters such as the fee discrepancy tolerance and rounding precision, are documented in a JSON configuration file stored alongside the data files.

Platform fees charged against each campaign are captured in YAML files among the data files. Each YAML file contains a list of fee records specifying a campaign identifier, fee type, and the charged amount. To arrive at net fees for a campaign, sum all fee records for that campaign across every YAML fee file, then subtract the total of any fee waivers or credits recorded in the system for that same campaign.

Expenses originate from two sources. The system holds individual expense entries with an approval status; only entries marked as approved should be counted. Additional approved expenses are recorded in pipe-delimited text files among the data files, each line carrying a campaign identifier, date, category, amount, vendor, and notes. All entries from these supplemental text files count toward the total.

Once every figure has been gathered, compute gross revenue for each active campaign as the sum of its total deposits and its adjusted in-kind donations. Net balance equals gross revenue minus net fees minus total expenses. Write the consolidated results to a file named "financial_statements.csv" containing columns in exactly this order: campaign_id, campaign_name, tier, gateway_deposits, manual_deposits, total_deposits, adjusted_in_kind, gross_revenue, platform_fees, fee_waivers, net_fees, approved_expenses, supplementary_expenses, total_expenses, net_balance. Rows must be sorted by campaign_id in ascending order, and every monetary value must be expressed with exactly two decimal places.

Separately, verify whether the platform fees actually charged to each active campaign are consistent with the rate dictated by its tier. A YAML configuration file among the data files maps each tier to its applicable rate, which should be multiplied by total deposits to yield the expected fee. Compare expected fees against actual platform fees from the fee files. If the absolute percentage discrepancy, defined as the absolute difference divided by expected fees times one hundred, exceeds the tolerance percentage specified in the reconciliation rules configuration, the campaign must be flagged. Campaigns whose expected fees are zero should not be evaluated for discrepancy. Write every flagged campaign to a file named "discrepancy_report.txt" with one line per campaign, sorted by campaign_id ascending, in the format "Campaign {campaign_id} ({campaign_name}): expected_fees={value with two decimals}, actual_fees={value with two decimals}, discrepancy={percentage with one decimal}%". If no campaigns exceed the threshold, create the file but leave it empty.

After writing both output files, end your response with a line stating "Grand Total Net Balance: " followed by the sum of net_balance across all active campaigns, formatted to exactly two decimal places.
