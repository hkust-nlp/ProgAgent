A backlog of orders flagged for review has been accumulating and each one needs a thorough risk assessment before the fulfillment team can proceed. Every order currently sitting in "pending_review" status must be evaluated by pulling together signals from multiple sources and computing a composite fraud risk score.

For each pending order, start by examining the IP geolocation analysis. If the IP address country does not match the customer's registered country, this constitutes a mismatch. Separately, any detection of proxy or VPN usage on the connection is an additional signal, though both proxy and VPN together count only once toward the score. Next, look at the response from the card issuer. Each issuer response code carries a severity value defined in a reference file among your available data files, and that severity becomes the card risk component, capped at the maximum specified in the scoring configuration for card issuer risk. The address verification system provides a numeric score that falls into one of several tiers, each mapped to a corresponding risk point value in a tiers reference file; the resulting points are likewise capped at the maximum specified for address verification in the configuration.

Beyond these per-order checks, two families of batch files hold information you will need. Customer risk profile batches are CSV files containing each customer's previous fraud incident count, chargeback history, total historical orders, average order value, account age in days, and an assigned risk tier. Transaction pattern batches are JSON files recording, for each order, whether it was flagged for rapid ordering, an unusual transaction amount, or use of multiple shipping addresses. Both sets of batch files must be read in full, as any given customer or order could appear in any batch.

A scoring configuration file in YAML format lays out the exact point values for each risk factor: how many points an IP mismatch is worth, how many for proxy or VPN detection, the multiplier applied to each previous fraud incident and each chargeback on the customer's record, the bonus added when a customer's account is younger than a specified number of days, and the point values for each transaction pattern flag. It also specifies the high-risk and medium-risk thresholds and a maximum score cap. The composite risk score for an order is the sum of IP geolocation points, card issuer severity (capped per configuration), address verification tier points (capped per configuration), customer history points computed from fraud count multiplied by its multiplier plus chargeback count multiplied by its multiplier plus the new-account bonus when applicable, and transaction pattern points from any flagged anomalies. The total is then capped at the stated maximum.

An order qualifies as HIGH risk when its score meets or exceeds the high-risk threshold, and as MEDIUM risk when it meets or exceeds the medium-risk threshold but falls below the high one. Only orders at these two levels enter the final review queue.

A procedures document describes verification actions keyed to specific risk conditions. Each action is tied to a particular indicator or threshold, covering IP mismatch, proxy or VPN detection, card severity at two threshold levels, AVS risk points at two threshold levels, previous fraud history, chargeback counts above a stated limit, and each of the three transaction pattern flags. For each order in the queue, collect every action whose triggering condition is satisfied, joining them with "; " as a separator in the order they appear in the procedures document.

Save the resulting queue as `fraud_review_queue.csv` with columns in this exact sequence: `order_id`, `risk_score`, `risk_level`, `ip_risk`, `card_risk`, `avs_risk`, `history_risk`, `pattern_risk`, `recommended_actions`. Rows must be sorted by `risk_score` descending, with ties broken by `order_id` in ascending lexicographic order. Risk scores should be recorded as integers.

Once the file is written, provide a summary stating the total number of pending orders reviewed, how many were classified HIGH risk, how many MEDIUM risk, and the three highest-scoring order IDs with their scores, formatted as "ORDER_ID: SCORE" and separated by commas.
