You are assisting an audit manager in performing a comprehensive coverage gap analysis for the current year's financial statement audit. The engagement team has assembled audit program checklists, catalogued prior year findings with their remediation statuses, recorded current year general ledger activity across all audit areas, and collected client-provided support documents. Your job is to cross-reference all of these sources, determine which audit areas carry the highest composite risk, and identify every instance where the current testing program falls short of what is required.

Begin by retrieving the full roster of audit areas along with their inherent risk classifications and departmental assignments. You will need to page through all available areas to ensure nothing is missed. Once you have the complete list, turn to the configuration files that govern how composite risk scores are computed. A YAML file describes the risk scoring policy, including points assigned for each inherent risk level, adjustments triggered by unremediated prior year findings of various severities, additional points when general ledger activity in an area exceeds the department's materiality threshold, and a further adjustment when no client support documentation is on file for the area. The thresholds that separate composite High, Medium, and Low risk are also specified in that same policy file. A separate JSON file provides the materiality dollar thresholds broken out by department, and a second YAML file lays out which audit procedure types are mandatory at each composite risk level.

For every audit area, you must gather its prior year findings through the appropriate tool call and also retrieve the general ledger summary showing total amounts booked. Using the risk scoring policy, compute each area's composite risk score by starting with the inherent risk points, then adding adjustments for any unremediated finding whose severity matches one of the adjustment rules (count each severity level at most once per area regardless of how many findings at that level exist), adding points if the area's total GL amount exceeds its department materiality threshold, and adding points if the area has no support documentation. Compare the final score against the composite risk thresholds to classify each area as High, Medium, or Low composite risk.

Separately, parse every client support document file available in the working directory. These files come in several formats and each one identifies the audit areas it covers along with a coverage quality assessment. You will need to read them all and build a mapping from each area to whatever support documentation exists for it, noting the stated quality. Areas with no support files at all, or where every available file rates the coverage as Limited or Partial, represent a support deficiency.

Once composite risk levels are established, focus on all areas classified as High composite risk. For each such area, retrieve its checklist of audit procedures through the tool. Compare the procedure types present in the checklist against the required procedures for the High risk level as specified in the required procedures configuration file. Any required procedure type that does not appear in the area's checklist constitutes a procedure gap. Additionally, review the area's prior year findings: any finding with severity Critical or High whose remediation status is neither Remediated nor Not Applicable constitutes an unremediated finding gap that demands follow-up testing. Check whether the area has adequate client support documentation based on your earlier parsing; if no documents exist or if all documents carry only Limited or Partial quality, record a support deficiency gap. Finally, if the area's total GL activity exceeds its department materiality threshold and the checklist does not include a detail_testing procedure, that is a materiality untested gap.

Compile every identified gap into a single CSV file named `coverage_gap_report.csv`. The file must contain exactly these columns in this order: `area_id`, `area_name`, `composite_risk_level`, `gap_type`, `gap_description`, `severity`, `recommendation`. The gap_type column must use one of these exact labels: PROCEDURE_GAP, UNREMEDIATED_FINDING, SUPPORT_DEFICIENCY, or MATERIALITY_UNTESTED. For procedure gaps, the gap_description should state the missing procedure name. For unremediated finding gaps, it should reference the finding identifier and its severity and current remediation status. For support deficiency gaps, it should note whether documentation is missing entirely or merely insufficient. For materiality untested gaps, it should state the GL total and the materiality threshold. The severity column should be Critical for findings originally rated Critical, High for most other gaps, and Medium for support deficiencies where documentation exists but is of low quality. The recommendation column should prescribe a concrete remediation action. Sort all rows first by area_id ascending, then by gap_type ascending within each area.

On top of this, your final response must include an executive summary stating the total number of high-risk audit areas identified, the total number of coverage gaps found, and a breakdown of gap counts by type: how many procedure gaps, how many unremediated finding gaps, how many support deficiency gaps, and how many materiality untested gaps. List the area identifiers of all high-risk areas in your response as well.
