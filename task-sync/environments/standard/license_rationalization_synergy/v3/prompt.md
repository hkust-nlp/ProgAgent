Apex Digital and Nexus Technologies have recently completed a merger, and the combined IT integration team has been tasked with rationalizing the enterprise SaaS portfolio across both legacy organizations. Each company independently procured its own suite of cloud software subscriptions over the years, and there is strong reason to believe that many of these subscriptions overlap or serve functionally equivalent purposes. Your job is to conduct a thorough license rationalization analysis that identifies every redundant subscription pair, determines which contract to retain in each case, calculates the projected cost after consolidation, and produces a detailed plan together with the total annual savings.

Begin by examining the full catalog of software contracts held by each company. You will find contract records for both Apex Digital and Nexus Technologies that include each subscription's name, vendor, category, per-seat pricing, current seat count, and total annual cost. Not all overlaps are immediately obvious from the product name alone. A configuration file describing functionally equivalent software pairs is available among your reference materials; you must consult it to discover overlaps where the two companies use different products that serve the same purpose within the same software category. Both direct name matches and these declared equivalences count as overlap groups that require rationalization.

Once you have identified all overlap groups, you must decide which contract to retain for each. A policy document among your reference materials specifies the rules governing this decision. The primary criterion is per-seat price: retain whichever contract charges less per seat annually. If two contracts share exactly the same per-seat price, the tie is broken by keeping the one with more total seats currently allocated. Should that also be equal, retain the contract whose software name comes first in alphabetical order.

The consolidated seat count for each overlap group is not simply the sum of the two current seat totals. Instead, you must determine how many employees genuinely need the software going forward. Among your reference materials you will find per-user access records that report, for each employee who accessed a given piece of software at least once, the number of sessions they logged in the past thirty days. A rules document specifies a minimum session threshold below which a user is considered underutilized; any employee whose recorded sessions fall below that threshold, or who does not appear in the access records at all, should be excluded from the consolidated seat count. Separately, employee roster documents describe each employee's employment type. Only employees whose employment type is listed as eligible in the rules document should be counted toward the post-merger seat allocation. An employee must satisfy both conditions, appearing in the access records with sessions at or above the threshold and holding an eligible employment type, to be counted.

After determining the consolidated seat count for each overlap group, apply volume discount schedules to calculate the projected annual cost. A discount reference file maps each vendor to a tiered pricing schedule based on seat count brackets. Look up the retained contract's vendor, find the tier that matches the consolidated seat count, and reduce the retained per-seat price by the indicated percentage. The projected annual cost equals the consolidated seat count multiplied by this discounted per-seat price. The annual savings for the overlap group equals the sum of both current annual costs minus the projected annual cost. All monetary values must be rounded to two decimal places throughout.

Save the full rationalization plan as `rationalization_plan.csv` with the following columns in this exact order: `overlap_group`, `software_a`, `company_a`, `software_b`, `company_b`, `retained_software`, `retained_vendor`, `eliminated_software`, `current_annual_cost`, `projected_annual_cost`, `annual_savings`. For overlap groups where both companies use the same product, the overlap group identifier should be that product name. For groups involving functionally equivalent but differently named products, use the format where the Apex Digital product name comes first, followed by a space-slash-space, followed by the Nexus Technologies product name. Sort the rows by annual savings in descending order.

Additionally, save a summary as `savings_summary.json` containing a field `total_annual_savings` with the grand total of all annual savings, a field `num_overlap_groups` with the count of overlap groups, and a list called `groups` where each entry has `overlap_group` and `annual_savings`.

In your final response, state the total projected annual savings as a dollar amount with exactly two decimal places.
