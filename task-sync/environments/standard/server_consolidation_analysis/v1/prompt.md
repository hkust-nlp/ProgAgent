You have been brought in as an infrastructure optimization consultant to evaluate a data center fleet for server consolidation opportunities. The goal is to identify servers that are consistently underutilized over a ninety-day observation window and produce a structured decommissioning schedule with migration priorities.

Start by locating and reviewing the consolidation policy configuration file, which defines the thresholds that determine whether a server qualifies as underutilized. Two conditions must both be met for a server to be flagged: its ninety-day average CPU utilization must fall strictly below the configured CPU threshold percentage, and its ninety-day average power draw must fall strictly below the product of its rated power capacity and the power utilization factor specified in the policy. Only servers whose current status is active should be evaluated. Server specification files distributed across the working directory provide the rated power wattage for each server, so you will need to cross-reference every active server's identifier against these files to obtain its rated capacity.

Once the underutilized servers have been isolated, compute a migration priority score for each one. A separate rules document in the working directory describes the scoring methodology in detail. In essence, the score begins at zero and accumulates weight from three sources. First, every service running on the server contributes a weight determined by its criticality tier, with the exact mapping found in the consolidation policy. Second, the service dependency map files in the working directory must be consulted: for each service hosted on the server, count how many services anywhere in the entire fleet directly list it as a dependency, and multiply that count by the dependency weight from the policy. Third, if the server's type is recorded as a virtualization host, add the VM host penalty from the policy. The sum of these three components is the migration priority score.

Assign each underutilized server to a decommission phase using the phase threshold values in the consolidation policy. A server whose total score equals the phase one maximum belongs to phase one, a score above that value up to and including the phase two maximum belongs to phase two, a score above the phase two maximum up to and including the phase three maximum belongs to phase three, and any score above the phase three maximum places the server in phase four.

Separately, compute the estimated annual cost savings that would result from retiring each underutilized server. A datacenter configuration file in the working directory provides the Power Usage Effectiveness ratio and the electricity cost per kilowatt-hour for each datacenter location. For a given server, annual savings in US dollars equals its rated power in kilowatts, multiplied by the PUE of its datacenter, multiplied by the electricity cost per kilowatt-hour, multiplied by 8760 hours.

Once all calculations are complete, save the full decommissioning schedule as `decommissioning_schedule.csv` containing these exact columns in this order: `server_id`, `hostname`, `datacenter`, `avg_cpu_pct`, `avg_power_watts`, `rated_power_watts`, `service_count`, `migration_priority_score`, `decommission_phase`, `estimated_annual_savings_usd`. All decimal values must be rounded to exactly two decimal places. Sort the rows first by `decommission_phase` in ascending order, then by `migration_priority_score` in ascending order, and finally by `server_id` in ascending order as a tiebreaker.

In your final response, state the total count of underutilized servers identified in the form "Total underutilized: N", provide a breakdown showing how many servers fall into each decommission phase as "Phase K: M servers" for every phase that has at least one server, and report the combined estimated annual savings as "Total annual savings: $X.XX" with the dollar amount rounded to two decimal places.
