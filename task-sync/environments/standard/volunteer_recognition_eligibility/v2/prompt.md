You are assisting a volunteer program coordinator who needs to compile a quarterly commendation list recognizing outstanding volunteers. The organization tracks volunteer activity across several systems, and your job is to pull everything together, apply the award criteria, and produce a final deliverable.

Start by locating the policy configuration file named `award_policy.yaml`, which specifies the evaluation quarter, the date range that defines it, eligibility prerequisites, and the tier structure. Each tier has minimum thresholds for four dimensions: total hours logged during the quarter, number of distinct specialized certification categories held, average peer feedback score received during the quarter, and count of event leadership roles held during the quarter. A volunteer qualifies for the highest tier whose thresholds they satisfy across all four dimensions simultaneously. The tier priority ordering is also listed in the policy file, from highest to lowest. If a volunteer does not meet even the lowest tier's requirements, they receive no award and should be excluded from the output entirely.

Separately, consult the file `specialized_certs.json` to determine which certification categories the organization considers "specialized." Only active certifications falling into one of those categories should be counted, and you must count the number of distinct specialized categories represented, not individual certificates. For instance, if a volunteer holds three active certificates but two of them belong to the same specialized category, that counts as two distinct specialized certification categories.

The eligibility section of the policy file specifies two preconditions. First, a volunteer must have the required status. Second, they must have joined the organization on or before the date given in the policy. Volunteers failing either check are ineligible regardless of their performance metrics.

Hours data is spread across a series of CSV files whose names follow the pattern `hours_log_part_NNN.csv`. Each file contains rows with a volunteer identifier, a log date, hours worked, and an activity type. You must read all of these files, filter to entries whose dates fall within the evaluation quarter's start and end dates (inclusive), and aggregate total hours per volunteer. Be careful: these files also contain entries from outside the evaluation quarter that must be excluded.

Certification records, peer feedback entries, and event leadership roles are not stored in files. Instead, retrieve them through the available tools by querying for each volunteer individually. When retrieving peer feedback and leadership roles, filter by the evaluation quarter identifier found in the policy file. Compute the average of all feedback scores returned for each volunteer during that quarter. If a volunteer has no feedback entries for the quarter, treat their average as zero, which will likely disqualify them from most tiers.

Once you have assembled all four metrics for every eligible volunteer, apply the tier thresholds. Assign each qualifying volunteer to their highest eligible tier. Then produce a CSV file named `commendation_list.csv` containing one row per awardee. The file must include these columns in exactly this order: `volunteer_id`, `full_name`, `department`, `total_hours`, `specialized_cert_categories`, `avg_feedback_score`, `leadership_count`, `award_tier`. The `full_name` column should combine the volunteer's first and last names separated by a space. Format `total_hours` to one decimal place and `avg_feedback_score` to two decimal places. Sort the rows first by tier in priority order (the highest tier first), then by total hours in descending order within the same tier, and finally by volunteer_id in ascending order to break any remaining ties.

After writing the file, provide a brief summary stating the total number of awardees and the count of volunteers in each tier that appears in the list.
