You are a pricing analyst at a consumer goods company that tracks competitor activity across multiple product categories. Your company maintains an internal product catalog, cost sheets, and historical pricing records accessible through a set of data retrieval tools, while a web-scraping pipeline deposits daily competitor price snapshots as CSV files in your working directory. Several configuration files in the same directory define alert classification rules, category-specific thresholds, a price adjustment policy, and competitor reliability tiers. Your job is to cross-reference all of these sources and produce an actionable alert dashboard along with a structured summary.

Begin by reading every scraped price file available. Each file is named in the pattern `scrape_competitor_<id>_<date>.csv` and contains columns for the competitor SKU, product name, listed price, currency, and a timestamp. When the same competitor SKU appears in files from different dates, only the observation with the most recent timestamp should be retained for analysis.

For each retained competitor SKU, use the catalog mapping lookup tool to resolve it to an internal product identifier. SKUs that have no mapping should be silently discarded. Once you have the internal product identifier, retrieve the product's category and the full internal cost sheet, which includes the unit cost, overhead rate, target margin, floor price, and current selling price. You will also need the competitor's profile, specifically the reliability score, which determines the competitor's tier.

Consult the competitor tier definitions in the working directory. Only competitors whose reliability score places them in Tier A or Tier B should be retained. Any entries associated with a Tier C competitor must be excluded from the dashboard entirely.

Next, compute the price gap percentage for every surviving entry using the formula found in the pricing rules configuration file. Using the category-specific thresholds from the alert thresholds configuration, classify each entry into one of three alert levels: critical when the price gap percentage falls below the negative of the category's critical threshold, warning when the gap is negative but not beyond the critical threshold, and watch when the gap is non-negative yet still below the category's watch threshold. Entries whose gap equals or exceeds the watch threshold generate no alert and should be omitted.

Once alerts have been classified, calculate the recommended price for each entry according to the adjustment policy document. Critical entries receive a recommended price equal to the competitor's latest scraped price multiplied by 0.98, floored at the product's minimum viable price, which is the unit cost times one plus the overhead rate. Warning entries receive the simple average of the floor price and the competitor's scraped price, again floored at the minimum viable price. Watch entries carry a recommended price equal to the product's current selling price. Compute the adjustment percentage as the change from the current price to the recommended price, expressed as a percentage of the current price.

Save the resulting alert dashboard as `alert_dashboard.csv` with the following columns in this exact order: `product_id`, `product_name`, `category`, `competitor_id`, `competitor_name`, `latest_scraped_price`, `floor_price`, `price_gap_pct`, `alert_level`, `recommended_price`, `adjustment_pct`. All monetary values and percentages must be rounded to exactly two decimal places. Sort the rows first by alert level priority in ascending order, where critical is 1, warning is 2, and watch is 3, then by price gap percentage in ascending order within each level.

Separately, produce a file called `pricing_summary.json` containing the following keys. `total_alerts` is the integer count of all rows in the dashboard. `by_level` is an object with keys `critical`, `warning`, and `watch`, each holding an integer count. `by_category` is an object whose keys are the category names that appear among the alerts, each mapping to an object of the same three level counts. `average_price_gap_pct` is an object with keys `critical`, `warning`, and `watch`, each holding the mean price gap percentage for that level rounded to two decimal places, or 0.0 if no alerts exist at that level. `total_recommended_adjustments` is the count of alerts at the critical or warning level, since watch-level entries carry no actual price change.

In your final response, state the total number of alerts generated, the count broken down by each alert level (critical, warning, watch), and identify the single product by its product identifier that represents the most severe competitive threat, meaning the first row of the sorted dashboard. Also report the total number of products that require price adjustments.
