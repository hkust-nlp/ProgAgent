You are the scheduling coordinator for a school that needs to finalize student timetables for the upcoming semester. Every student must be placed into exactly six course sections, one for each time slot in the daily schedule. Some of these courses are mandatory core requirements dictated by the student's academic program and grade level, while the remaining slots should be filled with elective courses drawn from each student's preference survey.

The data you need is split across two sources. Course catalogs, section offerings, student rosters with academic records, and teacher-to-section assignments are all accessible through the provided query tools. Meanwhile, the files available to you contain complementary information that cannot be obtained from the tools: each student's elective preference rankings, each teacher's current contracted availability by time slot, the mapping of core course requirements to each program and grade combination, the scheduling policy that governs how conflicts and priorities are resolved, and a set of enrollment rules describing the full procedure.

Begin by reading the enrollment rules document and the scheduling policy configuration carefully, as they define the exact algorithm you must follow. Students must be processed in descending order of GPA; when two students share the same GPA, the one whose student identifier comes first alphabetically takes priority. For each student, first assign all core courses required by their program and grade. Each core course may be offered in multiple sections across different time slots. When choosing among eligible sections for a core course, select the one with the largest remaining capacity; if two sections are tied in remaining capacity, choose the one with the smaller section identifier. A section is only eligible if it is active, meaning the teacher assigned to it is listed as available during that section's time slot in the current teacher schedule records. Sections whose assigned teacher is not available in the relevant time slot must be excluded entirely from consideration.

Once all core courses have been placed, fill the student's remaining open time slots with elective courses. Consult the student's preference survey, which ranks elective courses from most to least preferred. Attempt each preference in ascending rank order: for the preferred course, look for an active section that falls in one of the student's still-unoccupied time slots and has remaining capacity. Apply the same section-selection rule as for core courses. If no suitable section exists for a given preference, skip it and try the next one. Continue until all six time slots are filled or all preferences have been exhausted. If a time slot cannot be filled, leave it empty for that student.

After processing every student, save the complete timetable as `timetable.csv`. This file must contain exactly these columns in this order: `student_id`, `student_name`, `time_slot`, `course_id`, `course_name`, `section_id`, `teacher_id`. Each row represents one student-slot assignment. The rows should be sorted by student identifier in ascending order, and within each student by time slot in ascending numerical order.

Once the file is written, report the following four summary statistics in your final response. State the total number of students who appear in the timetable as `total_students_scheduled: N`. State how many of those students have all six time slots filled as `fully_scheduled_students: M`. State the total number of assignment rows in the timetable as `total_assignments: K`. Finally, compute the average preference rank of all elective assignments across all students, rounded to two decimal places, and report it as `avg_elective_preference_rank: X.XX`. An elective assignment's preference rank is the rank the student gave that course in their survey; core course assignments are excluded from this calculation.
