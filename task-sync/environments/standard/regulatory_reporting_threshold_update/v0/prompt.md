A recently enacted regulation, identified as FRT-2024 and titled the Financial Reporting Threshold Reform Act of 2024, has lowered reporting thresholds for monitored transaction types across multiple jurisdictions. Your task is to determine which clients are impacted by this change and produce a structured disclosure report capturing every affected client-transaction type combination along with the appropriate urgency classification.

Begin by reading the regulation update file, which is formatted in YAML and outlines the regulation's effective date, the reporting period under review, the scope of the assessment, and the criteria for determining impact. The regulation applies only to active clients whose transactions fall within the stated reporting period. Inactive and suspended clients must be excluded entirely from the analysis.

For each active client, you must retrieve their transaction history for the reporting period and aggregate transaction amounts by type. To determine whether a particular transaction type triggers an impact for a given client, look up the applicable regulation clause using the client's jurisdiction code, client type, and transaction type. The clause will provide both the old threshold and the new, reduced threshold. A client-transaction type pair is considered impacted when the aggregated in-period amount for that type meets or exceeds the new threshold, provided that the client also has a previously filed report for the same transaction type whose applied threshold matches the old threshold specified in the clause. Only the most recent previous report for each client and transaction type combination should be considered when checking the threshold match.

Separately, certain clients may be exempt from updated disclosure requirements even if they would otherwise be flagged as impacted. An exemption policy document describes the conditions under which a client is excluded. You will find supplementary client data spread across a series of portfolio files in JSON format, each containing fields such as risk rating, compliance tier, and AML flag status for a batch of clients. These portfolio attributes are essential for evaluating exemption eligibility and are not available through the query tools. The exemption policy details two independent paths to exemption, one based on a combination of risk rating, compliance tier, and AML status, and another based on the client's registration date relative to the regulation's effective date. Any client satisfying either complete exemption path must be removed from the impacted list.

Once the set of non-exempt impacted client-transaction type pairs has been determined, each must be assigned a disclosure priority. A priority matrix file in CSV format maps combinations of the client's risk rating and the gap ratio to a priority level. The gap ratio is computed as the difference between the total in-period transaction amount and the new threshold, divided by the new threshold. Match the risk rating and gap ratio against the ranges specified in the matrix to obtain the correct priority classification, which will be one of critical, high, medium, or low.

On top of this, a format specification document describes precisely how the output file should be structured. The deliverable is a file named `impacted_clients.csv` containing columns in the following exact order: `client_id`, `client_name`, `jurisdiction_code`, `transaction_type`, `total_amount`, `old_threshold`, `new_threshold`, `gap_amount`, `previous_report_id`, `disclosure_priority`. The gap amount is defined as the total in-period transaction amount minus the new threshold, rounded to two decimal places. All monetary values in the file must be formatted with exactly two decimal places. Rows must be sorted first by disclosure priority in descending urgency, meaning critical entries appear first followed by high, then medium, then low. Within the same priority, sort by gap amount in descending order. If both priority and gap amount are identical, use client identifier in ascending order as the final tiebreaker.

After producing the CSV file, provide a summary stating how many unique clients are impacted, the total number of impacted rows (client-transaction type combinations), and a breakdown of how many entries fall under each priority level.
