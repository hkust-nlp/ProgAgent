You have been tasked with preparing a seven-day cash-position forecast for a company's primary operating account. The goal is to project daily opening and closing balances across the upcoming week, accounting for every material outflow category, and to determine whether additional funding must be arranged before any projected shortfall materializes.

Begin by locating the forecast configuration file that specifies the reference date marking the start of the forecast window, the number of days to project, and a set of day-of-week expense weights. These weights adjust the baseline operating-expense estimate for each calendar day to reflect the natural ebb and flow of spending across weekdays and weekends. A separate policy file in YAML format defines the minimum acceptable balance the operating account must maintain, the target buffer percentage above that minimum, and a tiered schedule of funding methods ordered by maximum amount, each carrying its own lead-time requirement. There is also a JSON file containing variance-adjustment factors keyed by expense category; each factor inflates or deflates the historical average to produce a forward-looking estimate.

Retrieve the list of all company departments using the available tools, and for each department pull the full payroll roster. Every employee record indicates a pay frequency — weekly, biweekly, or monthly — along with the relevant scheduling field. Weekly employees are paid on the weekday indicated by their pay-day-of-week value (where 0 is Monday and 6 is Sunday). Biweekly employees share the same weekday indicator but also carry an anchor date; they are paid only when the number of days between the anchor and the calendar date in question is an exact multiple of fourteen. Monthly employees carry a pay-day-of-month and are paid when the calendar day matches that number. Sum the base salaries of every employee whose pay event falls on a given forecast day to obtain that day's payroll outflow.

Separately, retrieve all vendor categories and then pull the full vendor list for each category. Only active vendors (where the active flag is 1) should be included in projections. Weekly vendors pay on their designated weekday. Monthly vendors pay on their designated day of the month. Quarterly vendors pay on their designated day of the month but only during the first month of each calendar quarter — January, April, July, and October. Aggregate each day's qualifying vendor payments into a single vendor-outflow figure.

For taxes, query all pending tax liabilities whose due dates fall within the seven-day forecast window. Group the returned amounts by due date to obtain the tax outflow for each day.

Operating expenses require a historical analysis. For each department, retrieve expense records covering the thirty calendar days immediately before the reference date. Across all departments, count the number of distinct dates present in the returned history and compute, for each expense category, the sum of actual amounts divided by that distinct-date count to obtain an average daily figure. Multiply each category's average by the corresponding adjustment factor from the variance-adjustments file, then sum the adjusted category averages to arrive at a single base daily operating-expense estimate. For each forecast day, multiply this base by the appropriate day-of-week weight to produce the final operating-expense value.

Projected inflows are derived from the historical weekly-inflow CSV files found alongside the configuration files. Each file covers one calendar week and lists individual receipts with a date, source, and amount. Read every such file, tally inflow amounts by weekday, and count the number of distinct dates observed for each weekday across all files. Divide each weekday's total by its date count to get an average daily inflow for that weekday. Assign each forecast day the average corresponding to its weekday.

Once all components are assembled, build the daily projection starting from the current operating-account balance, which is available through the account-balance inquiry. For each day in sequence: the opening balance equals the prior day's closing balance (or the current balance on the first day); add the projected inflows; subtract the payroll outflow, vendor outflow, tax outflow, and operating expense; the result is the closing balance. Round every monetary value to two decimal places.

Save the projections as `daily_projections.csv` with exactly these columns in this order: `date`, `opening_balance`, `projected_inflows`, `payroll_outflow`, `vendor_outflow`, `tax_outflow`, `operating_expense`, `total_outflow`, `closing_balance`. The file must contain exactly seven data rows, one per forecast day, with all amounts rendered to two decimal places.

After constructing the projections, examine whether the minimum closing balance across the week falls below the policy's minimum-balance threshold. If it does, the recommended funding amount equals the target balance (minimum balance multiplied by one plus the target buffer percentage) minus that lowest closing balance, rounded to two decimal places. The funding must arrive no later than the day before the first shortfall occurs; if the shortfall appears on the very first forecast day, use that day as the funding date. Select the funding method from the policy tiers: choose the first tier whose maximum amount is greater than or equal to the recommended funding amount; if none qualifies, use the last tier. If no day's closing balance breaches the minimum, the recommended amount is zero, the funding date is "N/A", and the method is "none".

Save the recommendation as `funding_recommendation.json` with exactly these keys: `recommended_amount` (number), `funding_date` (YYYY-MM-DD string or "N/A"), `funding_method` (string), and `min_projected_balance` (number, the lowest closing balance observed).

In your final response, state the forecast period, the starting balance, the total outflow summed across all seven days, the lowest projected closing balance, and whether funding is required. If funding is required, include the recommended amount, the method, and the target funding date.
