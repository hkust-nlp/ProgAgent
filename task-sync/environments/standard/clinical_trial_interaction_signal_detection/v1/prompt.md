You are a clinical data analyst responsible for producing a safety signal report for an ongoing multi-cohort clinical trial. The trial enrolls participants across several cohorts, each assigned to a specific investigational study drug, and spans multiple reporting weeks. Many participants are simultaneously taking concomitant medications prescribed for pre-existing conditions, and certain combinations of these medications are known to interact in ways that can alter drug exposure or amplify adverse effects. Your task is to systematically identify every instance in which a participant is concurrently taking two concomitant medications that constitute a recognized drug-drug interaction pair, and to determine whether clinical evidence from that participant's record suggests the interaction may be manifesting during a given reporting week.

A reference file available in the data directory catalogues all recognized interaction pairs, specifying for each pair the two drug names, the type of interaction, the risk classification, and the minimum dose of each drug required for the interaction to be clinically relevant. You must cross-reference every participant's medication list against this catalogue to identify which pairs could apply. An interaction pair is considered active for a participant in a particular reporting week only when both drugs are being taken during that week, meaning each drug's prescribed period covers the week in question, and the effective dose of each drug meets or exceeds the minimum interaction dose specified in the reference. The effective dose of a drug may differ from the originally prescribed dose if a dose adjustment has been recorded for that participant and drug at or before the reporting week under consideration. Dose adjustment records are distributed across several site-level report files in the data directory; for any given participant and drug, if multiple adjustments exist, the one with the latest adjustment week that does not exceed the current reporting week should be used. When a dose adjustment results in a higher dose than originally prescribed and the adjusted drug is part of an active interaction pair, the risk level of that pair for that participant-week entry should be elevated by one tier according to the hierarchy low, moderate, high, where high remains high if already at the top tier. Whether this elevation rule is active is specified in the flagging configuration file.

For each active interaction pair, you must then assess whether clinical signals corroborate a potential adverse interaction. A participant-week entry qualifies for flagging if at least one of two conditions holds. The first condition is that the participant reported at least one adverse event during that reporting week whose severity grade meets or exceeds the phase-specific threshold assigned to the participant's current trial phase. Phase-specific thresholds and their associated parameters are defined in a phase configuration file in the data directory. The second condition is that the participant has at least one pharmacokinetic sample taken during that week whose measured concentration falls outside the acceptable range for the study drug, as determined by reference concentration ranges and a phase-specific deviation multiplier. The precise method for computing concentration anomalies, including how the acceptable bounds are derived and how the deviation percentage is calculated, is documented in an assessment guidelines document available in the data directory.

Once all flagged entries have been identified, save the results to a file named `weekly_ddi_report.csv` containing one row per flagged participant-week-interaction combination. The file must contain exactly these columns in this order: `week`, `participant_id`, `cohort_id`, `drug_a`, `drug_b`, `risk_level`, `max_ae_severity`, `pk_deviation_pct`, `flag_reason`. The two interacting drugs in `drug_a` and `drug_b` must appear in alphabetical order. The `max_ae_severity` column holds the highest severity grade among adverse events reported by the participant in that week, or zero if no adverse events exist. The `pk_deviation_pct` column holds the maximum deviation percentage across all pharmacokinetic samples for the participant in that week, rounded to one decimal place, or zero if no anomaly was detected. The `flag_reason` column should contain `AE` when only the adverse event condition was met, `PK` when only the pharmacokinetic anomaly condition was met, or `AE+PK` when both conditions were met. Rows in the file must be sorted first by week, then by cohort identifier, then by participant identifier, and when multiple interaction pairs are flagged for the same participant in the same week, additionally by the alphabetically earlier drug in the pair.

Separately, produce a file named `cohort_flags.json` that summarizes which cohorts are flagged in each reporting week. A cohort is considered flagged in a week when the number of distinct participants flagged within that cohort during that week meets or exceeds the cohort flagging threshold defined in the flagging configuration. The JSON structure should be a dictionary keyed by the week number as a string, where each value is itself a dictionary keyed by the cohort identifier as a string. Each inner entry should contain three fields: `flagged_count` giving the number of distinct flagged participants, `participant_ids` as a sorted list of the flagged participant identifiers, and `total_risk_score` computed as the sum of risk-level weights for all flagged entries in that cohort-week combination, with the per-level weights taken from the flagging configuration.

In your final response, state the total number of flagged entries in the weekly report, the total number of distinct cohort-week combinations that met the flagging threshold, and the cohort with the highest cumulative risk score across all weeks, reporting both its identifier and the score. Format these exactly as `total_flagged_entries: N`, `total_cohort_week_flags: M`, and `highest_risk_cohort: C with score S`.
