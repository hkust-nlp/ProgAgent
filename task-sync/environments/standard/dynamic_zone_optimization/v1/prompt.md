You are working as a logistics analyst for a delivery company that operates across a metropolitan area divided into numerous delivery zones. Your task is to produce an optimized daily zone assignment map that dispatch teams will use to route drivers and vehicles to clusters of zones for package delivery.

Several data files are available in your working directory. A configuration file in YAML format defines the key parameters governing how zones should be clustered, including the maximum number of zones allowed per cluster, a load buffer percentage that adds a safety margin to capacity requirements, multipliers for different package priority levels, certification thresholds that determine driver eligibility, and the target date for which the assignment must be produced. A set of CSV files contain historical performance metrics for each driver, including average delivery time, success rate, customer ratings, on-time percentage, and a composite performance score. JSON files provide demand forecast factors for each zone, containing a numeric multiplier and a trend label. Text files serve as real-time traffic bulletins, listing per-zone, per-shift congestion adjustments in the format "Zone ZXXX | Shift: morning | Adjustment: +0.12" on each line. A vehicle availability file in CSV format indicates which vehicles are operational today and which are undergoing maintenance, with columns for vehicle identifier, availability status, and a maintenance note. A policy document in Markdown format describes the rules for driver certification requirements, driver selection priority, vehicle selection strategy, and the handling of zones without packages.

Beyond these files, you have access to tools that let you query the company's operational database. You can retrieve a paginated list of delivery zones with their names and regions, pull a summary of package demand for any zone on a given date including breakdowns by priority level and delivery window, look up traffic congestion patterns for any zone during a specific shift and day of the week, search for drivers by their shift assignment, inspect individual driver profiles, browse the vehicle fleet with pagination, and examine specifications for any particular vehicle.

Begin by identifying every zone that has packages scheduled for delivery on the target date found in the configuration. For each such zone, determine which shift period (morning, afternoon, or evening) receives the greatest number of packages; when two or more shifts are tied, prefer morning over afternoon and afternoon over evening. This becomes the zone's primary shift. Next, calculate a weighted load for each zone by summing, for every package on the target date in that zone, the product of the package's weight in kilograms and the priority multiplier corresponding to that package's priority level as defined in the configuration. Then obtain the demand forecast factor for the zone from the forecast files, defaulting to 1.0 if the zone is not listed. Retrieve the base traffic congestion index from the database for that zone's primary shift on the appropriate day of the week corresponding to the target date. Also retrieve the congestion adjustment from the traffic bulletins for the same zone and shift, defaulting to 0.0 if not listed. Compute an effective congestion value by adding the base congestion index to the bulletin adjustment, then clamping the result to the range zero through one. The zone's adjusted demand equals its weighted load multiplied by the forecast factor and then by one plus the effective congestion value.

With per-zone metrics established, partition the active zones into clusters. Group all zones by their region and primary shift. Sort these groups first by region name alphabetically and then by shift in the order morning, afternoon, evening. Within each group, sort zones by adjusted demand from highest to lowest, breaking ties by zone identifier in ascending alphanumeric order. Form clusters by taking consecutive zones from each sorted group, placing up to the configured maximum number of zones per cluster. Assign cluster identifiers sequentially as C001, C002, C003, and so on, across all groups in the order just described.

Once clusters are formed, assign a driver and a vehicle to each cluster, processing clusters in order of their identifier. For each cluster, compute the total raw load as the sum of all package weights in kilograms across the cluster's zones for the target date, rounded to two decimal places. The required vehicle capacity equals this total load multiplied by one plus the load buffer percentage divided by one hundred. Evaluate the certification requirement by examining each zone in the cluster: if any zone has a proportion of urgent packages strictly exceeding the expert certification threshold from the configuration, the cluster requires an expert-certified driver; otherwise if any zone's combined proportion of express and urgent packages strictly exceeds the advanced certification threshold, the cluster requires at least an advanced-certified driver; otherwise basic certification suffices. From the pool of drivers whose shift matches the cluster's primary shift and whose certification level meets or exceeds the requirement and who have not already been assigned to another cluster, select the driver with the highest performance score found in the driver performance files. If performance scores are tied, choose the driver with the alphanumerically earliest identifier. From available vehicles whose maximum load capacity meets or exceeds the required capacity and that have not been assigned to another cluster, choose the vehicle with the smallest maximum load capacity to maximize utilization, breaking ties by the alphanumerically earliest vehicle identifier.

Save the results as a file named zone_assignment_map.csv containing the columns zone_id, zone_name, cluster_id, shift, driver_id, driver_name, vehicle_id, estimated_packages, estimated_load_kg, and utilization_pct. Each row represents one zone. The estimated_packages value is the count of packages for that zone on the target date. The estimated_load_kg is the sum of those packages' weights rounded to two decimal places. The utilization_pct for each row equals the cluster's total load divided by the assigned vehicle's maximum load capacity multiplied by one hundred, rounded to one decimal place. Rows must be sorted by cluster_id ascending and then by zone_id ascending.

Separately, save a file named dispatch_summary.json containing a date field with the target date, a total_clusters integer, a total_zones_assigned integer, a total_packages_scheduled integer, a clusters array where each element contains cluster_id, region, shift, zone_ids as a sorted list, driver_id, vehicle_id, total_packages, total_load_kg rounded to two decimal places, vehicle_capacity_kg, and utilization_pct rounded to one decimal place. Include an average_utilization_pct field at the top level computed as the mean of all cluster utilization percentages, rounded to one decimal place.

In your final response, state the total number of clusters formed, the average utilization percentage across all clusters rounded to one decimal place, and the total number of packages scheduled for delivery on the target date.
