You are a food safety analyst tasked with determining which product lot codes must be placed on immediate hold. Your investigation spans four separate data streams that together paint a picture of potential contamination and mishandling across a cold-chain distribution network. None of the streams alone is sufficient; reaching a correct conclusion requires you to cross-reference information obtained through the available query tools with the reference and configuration files stored in the working directory.

Start by reading the configuration and reference files that have been prepared for you. A YAML configuration file describes the temperature thresholds that apply to each product storage category and the rules that define when a temperature excursion has occurred. A product catalog in CSV format maps every product identifier to its human-readable name and its storage category. A facility registry, also in CSV format, lists each facility along with its name and type. A supplier directory provides each ingredient supplier's certification status and expiry date. A JSON file defines the set of symptom codes used in consumer complaints, including each code's severity rating. Finally, a criteria document written in Markdown lays out the exact conditions under which a lot must be flagged, the point values associated with each criterion, how the risk score is calculated, and the precise format required for the deliverable files and your final response. Read that criteria document carefully before you begin any analysis, because it specifies every threshold, every column name, every sort key, and every formatting rule you must follow.

Temperature sensor data is available through the query tools. You can retrieve paginated listings of all lots and all shipments, including summary statistics such as the maximum recorded temperature for each shipment. When a shipment's peak temperature suggests a possible excursion relative to the product's threshold, you should pull the full set of individual sensor readings for that shipment and evaluate the excursion rules defined in the temperature policy.

Sanitation audit findings are recorded in a set of CSV report files stored alongside the other reference data. Each record identifies the inspected facility, the violation category, its severity, and whether it has been resolved. You will need to tally unresolved critical-severity violations per facility and then determine which lots are linked to those facilities, both through their production origin and through the transit routing captured in the shipment manifest files. The manifests are JSON files that map each shipment to its origin and destination facilities, among other logistics details.

Consumer complaint records can be queried by lot code, and an aggregate count of complaints per lot is available as well. The complaint detail files in JSON format tie each complaint identifier to a symptom code and a narrative description. Cross-reference the symptom codes against the severity definitions to decide whether a lot's complaint pattern meets the cluster threshold laid out in the criteria document.

Ingredient genealogy is queryable per lot: for each lot you can obtain the list of ingredient lot codes along with their supplier identifiers. A reverse-lookup tool lets you discover every product lot that shares a particular ingredient lot code. Combine this with the supplier directory's certification status to evaluate whether any lots are at risk through shared ingredients linked to suppliers whose certifications have lapsed or been withdrawn.

Once you have evaluated all four criteria independently, compile the results. Produce a file named `hold_report.csv` following exactly the column order, sort rules, and formatting conventions specified in the criteria document. The columns must be `lot_code`, `product_name`, `facility_name`, `hold_reasons`, and `risk_score`. Your final response must also include a single line listing every held lot code in the exact prefix format described in the criteria document.
