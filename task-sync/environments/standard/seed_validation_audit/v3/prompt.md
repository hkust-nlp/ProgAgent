You are tasked with auditing a professional tournament bracket to identify potential seeding errors that warrant manual review by the tournament committee. The organizers suspect that some players may have been incorrectly seeded based on discrepancies between independent power assessments, historical surface-specific performance, and qualifying-round form, and they need a thorough, data-driven audit across every bracket match.

Your analysis should evaluate three categories of potential seeding anomalies. First, consider whether each seeded player's actual tournament seed aligns with independent expert power assessments available in the regional data files stored in your working directory. Every player listed in those files carries a power index representing an independent strength evaluation. To check for mismatches, rank all seeded players globally by their power index in descending order to produce a power rank for each seeded player. When a seeded player's power rank differs from their actual seed number by more than the threshold specified in the seeding rules configuration file, that bracket match should be flagged. If both players in a match are seeded and both exhibit a mismatch, one flag entry per match is sufficient as long as it captures the player with the larger divergence. The seeding rules configuration also specifies separate thresholds distinguishing high-severity from medium-severity mismatches.

Second, examine head-to-head dynamics on the tournament's playing surface for each bracket matchup involving at least one seeded player. The tournament's surface type is recorded in the tournament information file. For any such match, look up the surface-specific win-loss record between the two players from the surface head-to-head data files in your working directory. Separately, retrieve the overall career head-to-head totals between the pair through the head-to-head query tool. A match should be flagged when the lower-seeded player, meaning the one with the higher seed number or the unseeded player if only one is seeded, has accumulated a surface-specific win rate meeting or exceeding the dominance threshold defined in the configuration, provided that the number of surface-specific encounters also meets or exceeds the minimum stated there and the overall career meeting count retrieved through the tool meets or exceeds its own separately stated minimum. Severity is determined by a higher win-rate tier also specified in the configuration.

Third, assess whether any seeded player entering a bracket match shows signs of poor qualifying-round performance combined with declining competitive form. Retrieve each seeded player's qualifier round results through the qualifier performance tool and compute their average performance rating across all rounds. The configuration file defines three seed tiers, each with its own minimum expected average performance rating. Additionally, form-trend values for every player can be found in the qualifier detail files in your working directory. A match is flagged under this category when the seeded player's average qualifier performance rating falls below the threshold for their seed tier and their form trend simultaneously falls below the form-trend threshold stated in the configuration. If both players in a match are seeded and both meet the flagging criteria, a single flag entry for the match is sufficient. The severity level for this category is determined by the seed tier of the flagged player, as mapped in the configuration file.

Once you have completed the analysis across every bracket match, produce a single output file named `flagged_matches.csv`. Each row represents one flagged match under one specific flag category. The file must contain exactly these columns in this order: `match_id`, `round`, `player1_id`, `player1_name`, `player2_id`, `player2_name`, `flag_type`, `severity`, `details`. Use the flag type identifiers `RANK_SEED_MISMATCH`, `H2H_SURFACE_DOMINANCE`, and `QUALIFIER_FORM_CONCERN` exactly as written. Severity values must be `high`, `medium`, or `low`. The details column should contain a concise explanation referencing the relevant numeric values. Sort the output first by severity in descending priority order where high comes before medium and medium before low, then by ascending round number, and finally by ascending match identifier to break remaining ties.

After saving the file, provide a summary stating the total number of flagged entries broken down by flag type and by severity level.
