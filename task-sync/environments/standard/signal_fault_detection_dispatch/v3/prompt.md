The city's traffic management bureau needs a comprehensive assessment of every traffic signal in the network to identify those that are malfunctioning or performing below acceptable standards. You have access to several complementary data sources: pedestrian push-button activation logs recording how quickly each signal responds to button presses, signal phase change telemetry capturing planned versus actual phase durations and flagging anomalies, real-time congestion alerts aggregated from popular navigation applications, citizen complaint filings organized into weekly batch reports, and field inspection notes compiled by maintenance crews after on-site visits. A separate set of planned outage schedules lists signals that are already slated for maintenance work and must therefore be excluded from your dispatch recommendations.

Before analyzing any individual signal, review the scoring configuration file and the district priority mapping file that are available to you. The scoring configuration specifies the point weights assigned to each of five malfunction indicators, the detection thresholds that govern when an indicator triggers, the urgency tier boundaries with their associated recommended actions, and the minimum dispatch threshold. The district priority file maps each district name to a numeric multiplier that adjusts a signal's raw score to reflect the relative criticality of that district's traffic flow. These parameters govern every aspect of the methodology described below and must be applied exactly as specified.

Restrict your analysis to signals whose operational status is active. For each active signal, evaluate five malfunction indicators using the corresponding threshold from the configuration. For any indicator where the measured value meets or exceeds the full threshold, assign the full point weight defined in the configuration for that indicator. Where the measured value is at least half the threshold but falls below the full threshold, assign exactly half the point weight. Where the measured value is below half the threshold, or where no data exists for that indicator, assign zero points.

The first indicator is button malfunction. Determine the average pedestrian push-button response time in milliseconds for the signal and compare it against the button average response time threshold. The second indicator is phase anomaly. Determine the fraction of phase telemetry records flagged as anomalous for the signal and compare it against the phase anomaly rate threshold. The third indicator is congestion impact. Count the total number of congestion alerts associated with the signal and compare that count against the congestion alert count threshold. The fourth indicator is complaint severity. Collect all citizen complaint records from the weekly complaint report files, count how many unresolved complaints have been filed against the signal, and compare that count against the unresolved complaint count threshold. The fifth indicator is inspection findings. Read through all field inspection report files and determine whether the signal appears with a documented fault code. If a fault code is documented, assign the full inspection findings weight; if not, assign zero. The half-threshold rule does not apply to this binary indicator.

Sum the five indicator scores to obtain a raw urgency score, then multiply by the district priority multiplier corresponding to the signal's district, rounding the result to exactly two decimal places. Exclude any signal whose identifier appears in the planned outage schedules, regardless of its computed score. Among the remaining signals, retain only those whose final urgency score meets or exceeds the dispatch threshold specified in the configuration. Assign each retained signal an urgency tier by selecting the highest tier whose minimum score the signal's urgency score meets or exceeds, and use that tier's recommended action.

Determine each signal's primary issue by identifying which of the five indicator components contributed the highest individual score. In the event of a tie among components, select the one that appears earliest in this fixed ordering: button_malfunction, phase_anomaly, congestion_impact, complaint_severity, inspection_findings.

Save the result as `dispatch_list.csv` containing the columns `rank`, `signal_id`, `intersection_name`, `district`, `urgency_score`, `primary_issue`, `recommended_action` in exactly that order. Sort rows by urgency_score in descending order, breaking ties by signal_id in ascending order. The rank column is a sequential integer beginning at one. Format every urgency_score value with exactly two decimal places. Do not include any signal whose urgency score falls below the dispatch threshold.

In your final response, state the total number of signals on the dispatch list, then present each dispatched signal on its own line formatted as "rank. signal_id | intersection_name | urgency_score | recommended_action", ordered by rank.
