You are responsible for routing all pending technical support tickets to qualified engineers. The support system contains tickets submitted by customers who have encountered various errors in their production environments. Each pending ticket has a corresponding text file that contains the full description of the issue, including the specific error code the customer observed. You will need to read every one of these ticket files and extract the error code from the narrative description found within.

Once you have the error codes, cross-reference them against the support portal log files, which are CSV-formatted records of error occurrences. Each log entry links an error code to the product SKU it belongs to and the severity level of that error. These logs are the authoritative source for determining which product a given error code maps to and how severe the problem is. There may be multiple log files covering different time windows, and you should search through all of them to locate the relevant error code entries.

After identifying the product SKU for each ticket's error, use the product lookup function to retrieve the product's category. The routing configuration file specifies the minimum certification level an engineer must hold for each severity tier: critical-severity errors require the highest certification level (level 3), high-severity errors require at least level 2, and medium or low severity errors require at least level 1. A separate shift schedule file indicates which shift is currently active, along with a reference date that determines whether certifications are still valid. Only engineers who are marked as active and who are assigned to the current shift may receive ticket assignments. Furthermore, an engineer whose current queue depth already equals their maximum queue capacity must not be given additional tickets.

For each pending ticket, determine which on-shift active engineers hold a non-expired certification in the matching product category at or above the required level. Among those qualified candidates, select the one whose current queue depth is the lowest. If two or more engineers are tied at the same queue depth, select the one whose engineer ID is numerically smallest. Record each assignment through the system's ticket assignment function so that the database reflects the new routing, and note that doing so will update that engineer's queue depth for subsequent decisions.

The order in which you process tickets is critical because each assignment alters the queue landscape. Process all pending tickets from highest priority to lowest, where P5 represents the highest priority and P1 the lowest. When multiple tickets share the same priority level, process them in ascending order of ticket ID.

After completing all assignments, save the full results to a file named `assignments.csv`. This file must contain exactly these columns in this order: `ticket_id`, `error_code`, `product_sku`, `product_category`, `severity`, `required_cert_level`, `assigned_engineer_id`, `assigned_engineer_name`. Each row represents one routed ticket. In your final response, state the total number of tickets you routed and confirm that all assignments have been recorded in the system.
