A large health plan is entering its annual contract renegotiation cycle and needs to focus limited negotiation capacity on the providers whose cost performance and member experience are simultaneously out of line with expectations. Your assignment is to produce a targeted review list of providers who exhibit both above-benchmark costs and below-threshold member satisfaction, enriched with referral leakage information, so the network management team can prioritize renegotiation or termination discussions.

Begin by reading the configuration files that govern the analysis. A YAML file named `review_criteria.yaml` specifies the cost ratio threshold above which a provider is considered high-cost, the satisfaction floor below which a provider is considered low-satisfaction, the minimum number of approved claims a provider must have to be eligible for evaluation, the referral leakage threshold, and a set of composite weights for scoring. A second YAML file, `satisfaction_weights.yaml`, contains the weights to apply to each satisfaction dimension when computing a provider's weighted satisfaction score. A JSON file called `network_tier_config.json` maps each network tier to a rate multiplier that must be applied when computing expected claim costs. Finally, a CSV file named `specialty_benchmarks.csv` provides the benchmark cost ratio for each medical specialty, which is used to normalize a provider's raw cost ratio against its peers in the same specialty.

There is also a markdown document, `exclusion_list.md`, that lists providers who must be excluded from the review entirely due to recently initiated contracts. Any provider whose identifier appears in that document must be skipped regardless of their cost or satisfaction profile.

To evaluate each provider's cost performance, retrieve all approved claims for that provider using the available tools. For each claim, look up the base fee rate for the claim's service code from the fee schedule, then multiply that base rate by the rate multiplier associated with the provider's network tier (from the tier configuration file) and by the cost adjustment factor recorded for that claim in the supplemental claims detail CSV files (these files are named with a prefix `claims_detail_` and contain columns `claim_id`, `diagnosis_group`, and `cost_adjustment_factor`). The product of those three values is the expected cost for that claim. Sum the actual paid amounts across all approved claims and divide by the sum of expected costs to obtain the provider's raw cost ratio. Then divide the raw cost ratio by the specialty benchmark from the benchmarks CSV to arrive at the adjusted cost ratio. A provider whose adjusted cost ratio exceeds the cost ratio threshold stated in the review criteria is classified as high-cost.

To evaluate satisfaction, retrieve the satisfaction survey records for each provider. The tool returns an overall rating per survey. Supplement those overall ratings with the dimension-level scores found in JSON files prefixed `survey_responses_`, which contain `survey_id`, `communication_score`, `timeliness_score`, and `outcome_score` for each survey. Compute each survey's weighted satisfaction as the sum of the overall rating times its weight, the communication score times its weight, the timeliness score times its weight, and the outcome score times its weight, where all weights come from the satisfaction weights configuration. Average the weighted satisfaction across all of a provider's surveys to get the provider's final weighted satisfaction. A provider whose weighted satisfaction falls below the satisfaction floor is classified as low-satisfaction.

To assess referral leakage, retrieve outgoing referral records for each provider. Cross-reference each referral's identifier with the urgency annotations found in pipe-delimited text files prefixed `referral_annotations_`, which contain `referral_id` and `urgency_level` columns separated by a pipe character. Only non-urgent referrals (those whose urgency level is not "high") count toward the leakage calculation. Among those non-urgent referrals, compute the proportion that went out of network. That proportion is the provider's referral leakage rate. A provider whose leakage rate exceeds the referral leakage threshold is flagged for high leakage.

A provider qualifies for the targeted review list only if it is both high-cost and low-satisfaction, has at least the minimum number of approved claims specified by the review criteria, has at least one satisfaction survey on record, and does not appear on the exclusion list. For every qualifying provider, compute a composite score equal to the cost excess weight times the positive difference between the adjusted cost ratio and the cost ratio threshold, plus the satisfaction deficit weight times the positive difference between the satisfaction floor and the weighted satisfaction, plus the referral leakage weight times the referral leakage rate. All three weights come from the composite weights section of the review criteria.

Save the final review list as a CSV file named `review_list.csv`. The file must contain exactly these columns in this order: `provider_id`, `provider_name`, `specialty`, `network_tier`, `adjusted_cost_ratio`, `weighted_satisfaction`, `referral_leakage_rate`, `composite_score`, `high_leakage_flag`. The `adjusted_cost_ratio`, `referral_leakage_rate`, and `composite_score` columns must be rounded to four decimal places. The `weighted_satisfaction` column must be rounded to two decimal places. The `high_leakage_flag` column should contain `True` or `False`. Rows must be sorted by composite score in descending order, with ties broken by provider identifier in ascending lexicographic order.

Once the file is written, respond with a summary stating how many providers appear on the review list and listing the top three providers by composite score, including each one's identifier, name, and composite score value.
