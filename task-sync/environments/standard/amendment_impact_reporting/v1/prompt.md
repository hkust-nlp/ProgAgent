You are tasked with producing a comprehensive contract amendment impact report. The organization maintains master service agreements with various vendors, and there are currently active change order requests that propose modifications to specific clauses within those agreements. Your job is to cross-reference the change orders against the agreement clauses, vendor compliance certifications, and project milestone payment schedules to determine which change orders are non-compliant and to identify the required signatories for each.

Begin by reviewing the configuration files available to you. A YAML file named `compliance_rules.yaml` defines the thresholds and parameters governing non-compliance determinations, including maximum allowable schedule impact days categorized by priority level, a risk rating threshold for payment-related non-compliance, minimum certification levels per compliance category, and an escalation threshold for prior amendment counts. A JSON file named `signatory_matrix.json` maps cost impact ranges to required signatory levels, along with descriptive titles for each level. An additional policy document named `amendment_policy.md` describes the four types of non-compliance and explains how signatory levels are determined, including escalation and legal review adjustments.

Retrieve all contracts from the system and, for each contract, gather its associated MSA clauses and any active change orders. You will also need to collect overdue milestone payments for each contract, particularly those linked to specific clauses. Separately, read the change order reviewer notes from the JSON files whose names begin with `change_order_notes_`, which contain risk ratings and a flag indicating whether legal review is required for each order. Also read the vendor audit records from the text files whose names begin with `vendor_audit_`, which indicate whether each vendor carries an active penalty flag. Finally, read the amendment history YAML files whose names begin with `amendment_history_`, which record how many prior amendments each contract has undergone.

For every active change order, evaluate it against the four non-compliance conditions. A threshold breach occurs when the cost impact of the change order exceeds the amendment threshold of its linked MSA clause and the contracting vendor does not hold a valid, non-expired certification in the compliance category of that clause. A schedule violation occurs when the schedule impact in days exceeds the maximum allowed for the change order's stated priority level as defined in the compliance rules. A payment risk arises when a milestone payment linked to the same clause as the change order carries an overdue status and the change order has a risk rating at or above the configured threshold. A certification gap is identified when the vendor has an active penalty flag from an audit and the vendor's certification level in the relevant compliance category falls below the configured minimum.

Once you have determined which active change orders are non-compliant and classified their non-compliance types, determine the required signatory level for each. Start with the base level derived from the signatory matrix using the cost impact of the change order, then escalate by one level if the contract's count of prior amendments exceeds the escalation threshold, and further ensure the level is at least three if the change order's reviewer notes indicate that legal review is required. The signatory level is capped at four.

Save the results as a CSV file named `amendment_impact_report.csv` containing only non-compliant active change orders. The file must include the columns `order_id`, `contract_id`, `clause_number`, `vendor_name`, `change_description`, `cost_impact`, `non_compliance_types`, `required_signatory_level`, `vendor_signatory_name`, and `vendor_signatory_title`. The `cost_impact` column must be formatted to exactly two decimal places. The `non_compliance_types` column must list all applicable types for each order in alphabetical order, separated by `; ` (semicolon followed by a space). Sort the rows by `cost_impact` in descending order, breaking ties by `order_id` in ascending order.

Also save a JSON file named `non_compliance_summary.json` containing four keys: `total_non_compliant` (the integer count of non-compliant orders), `total_cost_impact` (the sum of their cost impacts as a number rounded to two decimal places), `highest_risk_order_id` (the order ID of the non-compliant order with the largest cost impact), and `by_type` (an object mapping each non-compliance type to the count of orders exhibiting that type).

In your final response, state the total number of non-compliant active change orders, the total cost impact formatted to two decimal places, and the order ID of the highest-risk change order.
