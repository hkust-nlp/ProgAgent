Following a confirmed security breach, you have been tasked with producing a comprehensive, priority-ranked remediation plan that determines exactly which asset-vulnerability combinations require immediate patching and in what order. The plan must integrate data from multiple sources: vulnerability scan results available through the scanning tools, asset criticality ratings stored in a series of CSV files, threat intelligence accessible through the intel-checking tool, and patch deployment records retrievable per asset. Several configuration files define the precise rules you must apply, including a YAML policy document that specifies the priority calculation formula, multiplier tables for criticality and threat levels, tier thresholds, SLA windows, and recommended actions, as well as a JSON configuration that maps each network zone to its risk multiplier. An output schema document describes the exact columns and formatting requirements for the deliverable.

Begin by collecting every detected vulnerability-asset pair from the scan results. These results are paginated, so you must retrieve all pages to ensure nothing is missed. For each unique CVE found in the scans, query the threat intelligence tool to determine whether that CVE is actively exploited in the wild and what its exploit maturity level is. For each unique asset appearing in the scan results, retrieve its patch deployment records to learn the current status of any patches that have been applied or attempted for the CVEs affecting that asset. Read all of the asset criticality batch CSV files to obtain the criticality score for every asset, and load the remediation policy and network zone configuration files to obtain the multiplier tables, tier definitions, and sorting rules.

Once all data has been gathered, compute a priority score for every scan finding that has not already been successfully patched. A finding is considered patched only when its patch deployment status is exactly "deployed"; findings whose status is pending, failed, scheduled, not_available, or that have no patch record at all must be included in the plan. The priority score is the product of four factors: the CVE's CVSS score, the criticality multiplier corresponding to the asset's criticality score, the threat multiplier determined by combining the CVE's actively-exploited flag with its exploit maturity level, and the zone multiplier for the asset's network zone. All multiplier values and the lookup keys for the threat multiplier come from the policy and configuration files. Round the resulting priority score to exactly two decimal places.

After computing the score for every qualifying finding, assign each one a priority tier. The tiers, their minimum score thresholds, recommended actions, and SLA windows are all defined in the remediation policy under the priority tiers section. A finding belongs to the highest tier whose minimum score it meets or exceeds. Sort the entire list by priority score in descending order, breaking ties first by CVSS score descending and then by asset identifier in ascending lexicographic order. Assign a one-based priority rank reflecting this sorted position.

Write the final remediation plan to a file called `remediation_plan.csv`. The CSV must contain the following columns in this exact order: `priority_rank`, `asset_id`, `hostname`, `cve_id`, `cvss_score`, `criticality_score`, `criticality_multiplier`, `threat_multiplier`, `zone_multiplier`, `priority_score`, `priority_tier`, `recommended_action`, `sla_hours`. The priority score column must show values rounded to exactly two decimal places. Every qualifying finding must appear in the file, and no patched findings may be included.

When you have finished, respond with a summary that begins on its own line with the text "REMEDIATION SUMMARY", followed on the next line by the total count of items in the format "Total items: N", then on the next line a tier breakdown in the format "P1: X, P2: Y, P3: Z, P4: W", and after a blank line list every item from the plan in rank order, each on its own line in the format "RANK. ASSET_ID | CVE_ID | PRIORITY_SCORE | TIER | ACTION", where PRIORITY_SCORE is shown to two decimal places and ACTION is the recommended action string from the policy.
