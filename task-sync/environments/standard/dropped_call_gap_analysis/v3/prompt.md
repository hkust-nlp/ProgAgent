You are a network optimization analyst at a telecommunications company that has been receiving a growing volume of dropped call complaints. Your objective is to systematically analyze these complaints alongside network performance data, maintenance records, third-party signal surveys, and device-level signal readings to identify which cell towers suffer from persistent coverage gaps, then produce a ranked list of towers most urgently in need of upgrading.

Begin by examining the configuration files available in your working directory. A YAML configuration file lays out the full scoring methodology: four scoring dimensions, each with its own formula, the weight assigned to each dimension, the thresholds a tower must meet before it even qualifies for assessment, a maintenance discount rule, instructions for determining the primary issue behind each tower's poor performance, the tier boundaries for categorizing urgency, and the exact output format you must produce. A CSV file provides a regional priority multiplier for each geographic region, which scales a tower's score up or down depending on where it is located. A JSON file maps each cell tower technology generation to the upgrade that should be recommended for that generation. A plain-text document describes the overall classification process in narrative form.

Once you understand the scoring framework, gather complaint data using the available query tools. A paginated complaint summary endpoint lets you retrieve, for every tower that has received at least one complaint, the total complaint count and the average severity. Use this to determine which towers meet the qualification thresholds defined in the scoring criteria. For each qualifying tower, retrieve its detailed record to obtain its geographic coordinates, current technology generation, and region. Also retrieve its aggregated network performance metrics and its maintenance history.

Separately, you must incorporate data from files in your working directory that are not reachable through the query tools. CSV files containing third-party signal strength measurements record latitude, longitude, and measured signal power at various geographic points. For each qualifying tower, find all measurements whose latitude differs from the tower's latitude by no more than 0.5 degrees and whose longitude differs from the tower's longitude by no more than 0.5 degrees, then compute the coverage gap score using the formula in the scoring criteria. JSON files containing call drop reports record the signal strength measured at the subscriber's device during actual dropped calls, keyed by tower identifier. Collect all device signal readings for each qualifying tower and compute the device signal score per the criteria.

With all four dimension scores in hand for every qualifying tower, multiply each score by its configured weight and sum the results. Multiply that sum by the tower's regional priority multiplier. If the tower has any maintenance record whose status is scheduled or in progress, apply the maintenance discount factor. Round the final priority score to exactly two decimal places. Determine the primary issue by identifying which dimension's weighted contribution is largest, breaking any ties alphabetically by the dimension's component name as specified in the configuration. Assign a priority tier based on where the final score falls relative to the tier boundaries.

Save your results as `tower_upgrade_priority.csv` with columns `rank`, `tower_id`, `tower_name`, `region`, `priority_score`, `priority_tier`, `primary_issue`, and `recommended_upgrade`. Sort the rows by `priority_score` in descending order, breaking ties by `tower_id` in ascending order. The `rank` column should be an integer starting at one reflecting this final ordering. The recommended upgrade for each tower comes from the technology upgrade paths configuration, based on the tower's current technology generation.

In your final response, state the total number of towers that appear on the upgrade list, report how many fall into each of the four priority tiers (critical, high, medium, and low), and identify the single tower with the highest priority score by giving both its tower_id and tower_name.
