You are a grants analyst preparing a pre-panel risk assessment for an upcoming review cycle. Every grant application currently awaiting review must be evaluated across four risk dimensions, and a consolidated report must be produced so that the review panel can prioritize its scrutiny.

Begin by retrieving all applications whose status is pending review. For each such application, obtain its itemized budget and aggregate the dollar amounts by expense category. The maximum allowable percentage of the total requested budget that each category may occupy is specified in a YAML configuration file that also lists a warning threshold; only the maximum threshold matters for flagging purposes. When multiple line items belong to the same category within a single application, their amounts must be summed before computing the percentage. Any category whose aggregate share of the total requested budget exceeds its maximum benchmark is considered a flag. The risk sub-score for the category-benchmark dimension equals the number of flagged categories multiplied by thirty divided by the total number of distinct categories present in that application's budget, capped at thirty.

Separately, each PI's publication-to-funding ratio must be computed. The necessary publication counts and cumulative funding figures are found in a set of JSON batch files stored under a subdirectory of the working directory named `pi_funding_records`. Each batch file contains an array of records keyed by PI identifier, with fields for total publications and total funding received. The ratio is defined as total publications divided by total funding received expressed in units of one hundred thousand dollars. A scoring configuration file in JSON format specifies two thresholds for this ratio: a low threshold and a critical threshold. If the ratio falls below the critical threshold, the full twenty-five points are assigned to the pub-funding component; if it falls below the low threshold but remains at or above the critical threshold, twelve and a half points are assigned; otherwise zero.

On top of this, examine each PI's historical financial reports through the available tools. For every report entry, compute the absolute percentage deviation as the absolute difference between actual spending and the budgeted amount, divided by the budgeted amount, times one hundred. Average these deviations across all of the PI's historical records. The same JSON scoring configuration file specifies a warning percentage and a critical percentage for this dimension. Exceeding the critical percentage yields twenty-five points; exceeding only the warning percentage yields twelve and a half points; otherwise zero.

Finally, check overhead rate compliance. Retrieve each application's institution details to obtain its overhead rate, then compare that rate against the approved maximum for the institution's type, which is recorded in a CSV file listing approved maximum rates and federal caps by institution type. If the institution's rate exceeds the approved maximum for its type, the full twenty points are assigned; otherwise zero.

The overall risk score for each application is the sum of the four component scores. A tier label is then assigned according to thresholds defined in the scoring configuration file under risk tiers, where each tier specifies a minimum (inclusive) and maximum (exclusive) score boundary, except that any score reaching or exceeding the Critical tier's minimum is labeled Critical.

Once every pending application has been assessed, save the results as `risk_assessment_report.csv`. The file must contain exactly these columns in this order: `app_id`, `pi_name`, `institution_name`, `total_requested`, `categories_over_benchmark`, `num_category_flags`, `pub_funding_ratio`, `pub_funding_flag`, `historical_variance_pct`, `historical_flag`, `overhead_rate`, `approved_max_rate`, `overhead_flag`, `risk_score`, `risk_tier`. The `categories_over_benchmark` column should list the flagged category names separated by a comma and a space, sorted alphabetically, or the word `none` if no categories were flagged. Boolean flag columns should contain `True` or `False`. Rows must be sorted by risk score in descending order; ties are broken by application ID in ascending order.

In your final response, summarize the assessment. State how many applications were reviewed and list every application that received a High or Critical risk tier, including its application ID, PI name, institution name, risk score, and tier. If no applications reached those tiers, state that explicitly.
