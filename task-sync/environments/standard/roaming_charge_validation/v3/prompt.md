You are a billing analyst at a telecommunications company tasked with resolving a backlog of international roaming charge disputes. Subscribers have filed tickets claiming they were incorrectly billed for roaming usage, and your job is to systematically investigate every open or pending-review dispute, determine whether the charge was indeed erroneous, and produce a validated refund list for the finance team.

To investigate each dispute you will need to pull together information from several places. Begin by retrieving all dispute tickets that are currently open or pending review. For each such ticket, look up the associated roaming log to obtain the full details of the charge, including the visited country, partner carrier, call duration, data usage, SMS count, and the amount that was billed. You will also need the subscriber's profile, particularly their home country, because one class of billing error involves charges levied while the subscriber was actually at home.

Three categories of billing error may be present. The first is a rate overcharge, where the billed amount exceeds the correctly calculated charge by more than a tolerance percentage. The correctly calculated charge is derived from the partner carrier's tariff agreement for the applicable billing zone on the date of the roaming event. To find the right tariff you must first determine which billing zone the visited country falls into by consulting the zone-mapping configuration file stored alongside the other reference data, and then query the tariff rate for that carrier, zone, and date. The formula is the sum of the call duration in minutes multiplied by the per-minute voice rate, the data usage in megabytes multiplied by the per-megabyte data rate, and the SMS count multiplied by the per-SMS rate. If the billed amount exceeds this calculated figure by more than the tolerance percentage given in the billing rules configuration, classify the charge as a rate overcharge and set the refund to the difference between the billed and correct amounts.

The second category is a charge applied when the subscriber was not actually roaming. Location tracking records are available in a set of files that log each subscriber's detected country at various timestamps. If at least one location record within the time window specified in the billing rules shows the subscriber in their home country around the time of the roaming event, the entire billed amount should be refunded, and the error type recorded as not roaming.

The third category is a duplicate charge. To detect duplicates, search for all roaming logs belonging to the same subscriber on the same date as the disputed charge. If another log entry is found with an identical event timestamp and identical usage figures (same call duration, same data usage, same SMS count), the two entries represent a single event billed twice. The entry with the higher log ID is the duplicate. The refund equals the full billed amount of the duplicate, and in the output you should reference the duplicate's log ID, not the original's.

When investigating a dispute, check for these three error types in the order described above: first determine whether the subscriber was not roaming, then whether the rate was overcharged, and finally whether a duplicate exists. If none of the checks reveals an error, the original charge stands and the dispute should not appear in the refund list.

Each entry in the refund list also requires a charge reference code, which can be found in the charge-reference data files alongside invoice identifiers. Make sure to look up the charge reference for the correct log ID, which in the case of duplicates is the duplicate entry's log ID.

Once you have processed every open or pending-review dispute, save the results to a file called `refund_list.csv`. This file must contain the following columns in this order: `ticket_id`, `log_id`, `subscriber_id`, `subscriber_name`, `error_type`, `billed_amount`, `correct_amount`, `refund_amount`, `charge_reference`. The error type values must be exactly `rate_overcharge`, `not_roaming`, or `duplicate_charge`. All monetary values must appear with exactly two decimal places. Sort the rows by refund amount from largest to smallest, breaking ties by ticket ID in ascending alphabetical order.

After writing the file, report a summary that states the total number of erroneous charges found, the total refund amount formatted to two decimal places, and a breakdown showing how many errors fell into each of the three categories.
