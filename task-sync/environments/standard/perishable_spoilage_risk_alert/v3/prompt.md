You are responsible for managing perishable inventory across a network of distribution warehouses. Your organization tracks product shelf life, daily sales movement, and promotional scheduling to minimize spoilage losses. A configuration file named `config.yaml` contains the current reference datetime that represents "now" for all calculations, along with a priority scoring formula and markdown discount tiers. A separate file named `category_risk_factors.json` holds per-category risk multipliers that feed into the priority calculation. Additional product supplement files in the working directory provide supplier reliability scores and unit weights for every product in the system — these are spread across multiple files in various formats and must all be consulted.

Your task is to identify every inventory batch that will expire within forty-eight hours of the reference datetime, then compute a priority score for each such batch and produce a consolidated markdown report. To find at-risk batches you must query each warehouse's inventory, compare each batch's expiry timestamp against the reference datetime, and retain only those whose remaining life is greater than zero but no more than forty-eight hours. For each at-risk batch you must also retrieve the product's category and unit price, pull the last seven days of sales history at that warehouse to establish an average daily sales velocity, and check whether any active or upcoming promotions overlap with the at-risk window.

The priority score for each batch is computed from five weighted components. The urgency component equals the fraction of the forty-eight-hour window already consumed, calculated as (48 minus hours to expiry) divided by 48. The overstock component equals the ratio of current batch quantity to average daily sales (days of stock), divided by the overstock threshold found in `config.yaml`, capped at 1.0; if average daily sales is zero, treat days of stock as twice the overstock threshold. The category risk component is the multiplier from `category_risk_factors.json` for the product's category. The supplier risk component equals one minus the supplier reliability score from the supplement files; if a product has no supplement entry, use a default reliability of 0.75. The promotion conflict component equals 1.0 if the product has any promotion whose date range overlaps the window from the reference datetime through forty-eight hours later, and 0.0 otherwise. Each component is multiplied by its respective weight from `config.yaml` and the five terms are summed to yield the final priority score, expressed to four decimal places.

The markdown percentage for each batch is determined by which tier its hours-to-expiry falls into, as defined in the markdown tiers list in `config.yaml` — the first tier whose maximum hours equals or exceeds the batch's remaining hours applies. The estimated loss for each batch equals quantity multiplied by unit price multiplied by the markdown percentage divided by one hundred, rounded to two decimal places.

Once all at-risk batches have been scored, sort them in descending order of priority score. Where two batches share the same score to four decimal places, break the tie by placing the batch with fewer hours to expiry first. Assign sequential ranks starting at one.

Save the result as `priority_list.md` in the working directory. The file must begin with a markdown table whose columns, in exact order, are: Rank, Product_ID, Product_Name, Category, Warehouse_ID, Batch_ID, Quantity, Hours_to_Expiry, Avg_Daily_Sales, Days_of_Stock, Has_Promotion, Markdown_Pct, Priority_Score, Estimated_Loss. Hours_to_Expiry should display one decimal place, Avg_Daily_Sales two decimal places, Days_of_Stock one decimal place, Priority_Score four decimal places, Estimated_Loss two decimal places, and Has_Promotion should read "Yes" or "No". After the table include a blank line followed by two bold summary lines stating the total number of at-risk items and the total estimated markdown loss formatted with a dollar sign and two decimal places.

In your final response, state the total number of at-risk items found, the total estimated markdown loss in dollars, and list the top three highest-priority items by name and batch ID along with their priority scores.
