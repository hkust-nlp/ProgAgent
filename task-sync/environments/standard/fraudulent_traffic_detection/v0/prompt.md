You are a fraud analyst responsible for monitoring international interconnect call traffic across a network of carrier routes. A set of traffic snapshot files has been collected during a recent monitoring window, each containing per-route, per-destination call volume data for that period. Your job is to identify anomalous traffic patterns that may indicate fraud, cross-reference those patterns against known threat intelligence, and produce a structured alert report along with a recommended route blocking list.

Begin by reviewing the detection thresholds configuration, which specifies the spike multiplier and minimum call count threshold used to determine when a route-destination combination's current traffic volume is abnormally high compared to its historical average. Also review the alert classification rules, which define how to assign severity levels based on combinations of spike ratio, destination country risk score, and the number of calls placed to known fraudulent numbers. Finally, review the route blocking policy, which maps each severity level to a recommended response action and describes the format and ordering requirements for the alert report and the recommended blocks file.

Once you understand the detection parameters and classification logic, aggregate call volumes across all available traffic snapshot files. Each snapshot covers the same monitoring window and reports call counts for a subset of routes and destinations. Sum the call counts for each unique route and destination country pair across all snapshots. For every such pair whose aggregated call count meets or exceeds the minimum calls threshold, retrieve the historical baseline for that route and destination, find the baseline average that corresponds to the hour of day indicated by the snapshots, and compute the spike ratio as the current aggregated call count divided by the baseline average. Any combination whose spike ratio meets or exceeds the configured multiplier should be flagged as a potential anomaly.

For each flagged route-destination combination, retrieve all call detail records and examine every destination phone number in those records. Check each unique destination number against the known fraudulent number database. Count the total number of individual call records whose destination number is confirmed as actively flagged in the fraud database — if the same fraudulent number appears in multiple call records, each occurrence counts separately toward the fraud call total for that combination. Separately, obtain the aggregated country-level risk score for each flagged destination country.

With spike ratios, fraud call counts, and country risk scores in hand for every flagged combination, apply the severity classification rules in the order specified — from the most severe level down — and assign the first matching severity to each alert. Then determine the recommended action for each alert according to the blocking policy.

Save the full alert report as `alert_report.csv` with the following columns in this exact order: `alert_id`, `route_id`, `destination_country`, `current_volume`, `baseline_avg`, `spike_ratio`, `fraud_call_count`, `total_calls`, `country_risk_score`, `severity`, `recommended_action`. The spike ratio column must contain values rounded to exactly two decimal places. Baseline average values should appear as they are returned by the baseline lookup. Alert identifiers, ordering, and formatting must follow the conventions described in the route blocking policy document.

Separately, save a file named `recommended_blocks.json` containing a JSON array of objects, one per alert whose severity qualifies for inclusion in the recommended blocks report as defined by the blocking policy. Each object must include the fields `route_id`, `destination_country`, `severity`, `action`, `spike_ratio`, `fraud_call_count`, and `country_risk_score`. The array must follow the same ordering rules as the alert report.

After writing both files, provide a summary stating the total number of alerts generated, the count of alerts at each severity level, and the total number of routes recommended for blocking.
