You are tasked with analyzing the recruitment performance of a multi-center clinical trial to identify sites experiencing bottlenecks and produce a prioritized intervention list. The trial spans multiple regions, each with distinct enrollment targets and screening benchmarks, and the data you need is distributed across several structured files and queryable records accessible through the available tools.

Begin by reviewing the configuration files that define how bottleneck severity is measured. A scoring configuration file specifies thresholds for four bottleneck dimensions along with the weights assigned to each, tier-based multipliers that adjust severity by site importance, and a reference date used to evaluate certification timelines. A separate regional benchmarks file lists the default monthly enrollment target and expected screening pass rate for each geographic region. An intervention catalog maps each bottleneck type to a specific recommended action. These files are essential because the thresholds, weights, multipliers, and intervention texts they contain are the sole authoritative source for all downstream calculations.

Supplementary site-level data is spread across multiple files in various formats including CSV, JSON, plain text, YAML, and Markdown. Each file covers a subset of sites and provides two critical values per site: a risk adjustment factor that multiplicatively scales the final severity score, and an optional custom monthly enrollment target that, when present, overrides the regional default for that site. You must read every such file to ensure complete coverage of all sites, since no single file contains all sites and the format varies.

Once you have absorbed the configuration and supplementary data, use the available tools to retrieve operational data for every site whose status is active. For each active site, obtain the screening outcome summary, the eligibility criteria breakdown by criterion code, the monthly enrollment history, and the investigator details. Only active sites should be analyzed.

For each active site, compute four bottleneck indicators. First, the screen failure rate equals the number of failed screenings divided by the total screened. If this rate exceeds the threshold specified in the scoring configuration, the site exhibits a screening failure bottleneck, and the severity component for this dimension equals the excess above threshold divided by one minus the threshold, then multiplied by the screening failure weight. Second, compute per-criterion failure rates from the eligibility breakdown, where each criterion's failure rate is the not-met count divided by the sum of met and not-met counts. The eligibility barrier index is the maximum failure rate across all criteria for that site. If it exceeds the eligibility barrier threshold, the site has an eligibility barrier bottleneck, with the severity component calculated analogously using the eligibility barrier weight. Third, compute the enrollment ratio as the average enrolled count over the last three reporting periods divided by the applicable monthly target, which is the custom target from the supplementary files if one exists for that site, or else the regional default. If the enrollment ratio falls below the enrollment ratio threshold, the site has an enrollment shortfall bottleneck, and the severity component equals the deficit below threshold divided by the threshold, multiplied by the enrollment shortfall weight. Fourth, compute the average investigator utilization as the mean of current weekly hours divided by maximum weekly hours across all investigators at that site. Additionally, check whether any investigator's certification expiry date falls on or after the reference date but within the certification expiry window in days from the reference date. If the average utilization exceeds the investigator utilization threshold or any certification is expiring within the window, the site has an investigator capacity bottleneck. The utilization severity component equals the utilization excess above threshold divided by one minus the threshold, multiplied by the investigator capacity weight, plus an additional five points if any certification is expiring.

After computing all four dimensions for a site, determine its bottleneck type. If exactly one dimension is flagged, the type is that single dimension. If two or more dimensions are flagged, the type is "multiple". Sites with no flagged dimensions should be excluded from the output entirely. The base severity is the sum of all four severity components. The final severity score equals the base severity multiplied by the tier multiplier for the site's tier and by the site's risk adjustment factor from the supplementary files, with the result capped at one hundred and rounded to two decimal places. If no supplementary data exists for a site, use a risk adjustment factor of one. The recommended intervention text comes directly from the intervention catalog, keyed by the bottleneck type.

Sort all sites that have at least one bottleneck by severity score in descending order, breaking ties by site identifier in ascending alphabetical order. Assign a priority rank starting at one for the highest severity. Save the results as `site_intervention_priorities.csv` with columns in this exact order: `site_id`, `site_name`, `region`, `bottleneck_type`, `severity_score`, `recommended_intervention`, `priority_rank`.

In your final response, state the total number of active sites analyzed, the number of sites requiring intervention, the top three most common bottleneck types across all flagged sites, and the details of the five highest-priority sites including their site identifiers, names, bottleneck types, severity scores, and ranks.
