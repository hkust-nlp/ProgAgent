You are tasked with analyzing a portfolio of Renewable Energy Certificates (RECs) to identify which portfolios are at risk of failing their annual compliance obligations for the year 2026. The reference date for this analysis is 2026-04-20.

Each portfolio has a compliance target expressed in MWh. However, the effective target may differ from the stored value because adjustment factors have been applied to many portfolios. These adjustment factors are recorded in CSV data files in your working directory and multiply the original target to produce an adjusted target. Portfolios without an explicit adjustment factor should be treated as having a factor of 1.0.

To determine what each portfolio currently holds, you must examine its certificates. Only certificates with an "active" effective status and a vintage year within the set of eligible vintage years (2024, 2025, 2026) contribute to current holdings. When summing certificate capacity, each certificate's MWh value is multiplied by a technology-specific credit multiplier found in a configuration file called technology_multipliers.csv in your working directory. Be aware that some certificates have had their status updated through YAML data files in the working directory; when an update exists for a certificate, the updated status supersedes the database status.

Pending contract deliveries also contribute to a portfolio's expected supply. Only contracts with a "pending" delivery status and a delivery date on or before the portfolio's annual compliance deadline count toward pending deliveries. Some contracts have been amended through structured text data files in the working directory, where each amendment block specifies a contract ID and an amended MWh value. When an amendment exists for a contract, the amended MWh replaces the original contracted amount entirely.

Grid injection credits provide additional supply. For each facility linked to a portfolio through its certificates, examine the facility's injection records. An injection counts toward credits only if its effective verified status is true and it has not already been credited. Injection verification overrides are stored in JSON data files in the working directory; when an override exists for an injection, it replaces the database verified flag.

The total available supply for a portfolio equals the sum of current holdings, pending deliveries, and injection credits. The shortfall is the adjusted target minus total available. A portfolio is considered at risk if its shortfall exceeds the minimum shortfall threshold of 0.5 MWh, as specified in the compliance_config.json configuration file.

For at-risk portfolios, compute a priority score using the formula: priority_score equals (shortfall divided by adjusted_target) multiplied by the jurisdiction's penalty rate per MWh, then divided by the number of days until the annual compliance deadline (with a minimum of 1 day). The penalty rates for each jurisdiction are found in penalty_schedule.yaml in the working directory. The days until deadline is calculated from the reference date to the annual compliance deadline date for the portfolio's jurisdiction.

For the recommended technology type: if the portfolio has a technology preference that is not null and not "any", use that preference. Otherwise, use the technology type that appears most frequently among the portfolio's active certificates. If there are no active certificates, default to the technology with the highest credit multiplier.

Produce a file called procurement_list.csv with exactly these columns: portfolio_id, owner_name, jurisdiction_code, adjusted_target_mwh, current_holdings_mwh, expected_incoming_mwh, shortfall_mwh, priority_score, recommended_tech, deadline_date, days_until_deadline, penalty_rate. Include only at-risk portfolios. Sort rows by priority_score in descending order, using portfolio_id in ascending order as a tiebreaker. Round shortfall_mwh to 2 decimal places, priority_score to 4 decimal places, and adjusted_target_mwh, current_holdings_mwh, and expected_incoming_mwh each to 2 decimal places.

Also produce a file called compliance_summary.json containing: total_portfolios_analyzed (count of all 2026 portfolios regardless of risk status), at_risk_count, total_shortfall_mwh (rounded to 2 decimal places), average_priority_score (rounded to 4 decimal places), and top_3_portfolio_ids (a list of the three portfolio IDs with the highest priority scores).

Your final response must state: "At-risk portfolios: {count}. Total shortfall: {X} MWh. Top 3 priority portfolio IDs: {id1}, {id2}, {id3}." replacing the placeholders with the actual computed values.
