A field service company needs to identify which technicians should be prioritized for retraining based on their recent performance. The analysis draws on several data sources that must be cross-referenced to produce a single ranked output.

GPS tracking logs are stored as weekly CSV files whose names follow the pattern `gps_log_week_NNN.csv`. Each row in these files records a technician arriving at an appointment site, with columns for the technician identifier, the appointment identifier, the date, the full arrival timestamp, geographic coordinates, and an event type. The arrival timestamp in these files is the ground truth for when a technician physically showed up. Only rows with event type "arrived" should be considered.

Scheduled appointment windows are not contained in those files. To obtain the scheduled start time for a given appointment, you must query the appointment records through the available tools. Retrieve all completed appointments for each technician, then match each appointment against the GPS logs by appointment identifier. An appointment is considered "tracked" only if a corresponding GPS arrival record exists. Technicians who have no tracked appointments, or who have no satisfaction survey data, should be excluded from the analysis entirely.

A technician is counted as arriving late to an appointment when the difference between the GPS arrival time and the scheduled start time exceeds a threshold defined in the scoring configuration file named `scoring_config.yaml`. That file specifies the late threshold in minutes, a satisfaction score threshold, a late rate flag threshold, weights for combining the three scoring components, and a retraining threshold that determines who gets flagged. Parse all values from that file rather than assuming them.

Separately, satisfaction survey scores for each technician are accessible through the survey retrieval tool. Compute each technician's average overall satisfaction score across all their surveys.

Each appointment references a service category. Look up the complexity rating of each category through the category retrieval tool. Then consult a file named `complexity_matrix.json`, which maps complexity ratings (as string keys from "1" through "5") to numeric weight multipliers. For every tracked appointment of a technician, convert the service category's complexity rating to its weight via that matrix, and compute the average complexity weight across all tracked appointments.

Once those three metrics are in hand for a technician, combine them into a single weighted priority score using the formula: the late-rate weight times the technician's late arrival rate, plus the satisfaction weight times the quantity one minus average satisfaction divided by five, plus the complexity weight times the average complexity weight. The three weights come from the `priority_weights` mapping inside `scoring_config.yaml`, keyed as `late_rate`, `satisfaction`, and `complexity` respectively.

Before finalizing that score, check a file called `penalty_adjustments.txt`. Lines that are not comments contain a technician identifier, a pipe separator, a numeric multiplier, another pipe, and a reason. If a technician appears in that file, multiply their weighted priority score by the listed multiplier to obtain the final priority score.

A technician is flagged for retraining when their final priority score strictly exceeds the `retraining_threshold` value from the scoring configuration. For each flagged technician, determine the primary issue as follows: if the late arrival rate exceeds the `late_rate_flag_threshold` and the average satisfaction is below the `satisfaction_threshold`, the primary issue is "both"; if only the late rate exceeds its flag threshold, the primary issue is "lateness"; if only the satisfaction is below its threshold, the primary issue is "satisfaction"; otherwise label it "complexity".

Save the results to a file named `retraining_priority.csv`. The file must contain exactly these columns in this order: `technician_id`, `technician_name`, `total_tracked_appointments`, `late_count`, `late_rate`, `avg_satisfaction`, `avg_complexity_weight`, `priority_score`, `primary_issue`. Express `late_rate` and `avg_complexity_weight` to four decimal places, `avg_satisfaction` to two decimal places, and `priority_score` to four decimal places. Rows should be sorted by `priority_score` in descending order, with `technician_id` in ascending lexicographic order as a tiebreaker. Only flagged technicians appear in this file.

In your final response, state how many technicians were evaluated in total, how many were flagged for retraining, and list the top three highest-priority technicians by identifier, name, and priority score.
