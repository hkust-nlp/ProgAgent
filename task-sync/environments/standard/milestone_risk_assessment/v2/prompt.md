You are preparing the risk briefing for the next sprint planning session. Your organization tracks project milestones across multiple teams and needs to identify which upcoming and in-progress milestones carry the highest delivery risk so that leadership can allocate mitigation resources before the next iteration begins.

To perform this analysis you must assess every milestone whose status is either upcoming or in progress across four risk dimensions: historical story point estimation accuracy, dependency risk drawn from Confluence documentation, bug escape rate from QA, and team member churn. Each dimension produces a score between zero and one, and these are combined into an overall weighted risk score that determines the milestone's risk level.

For estimation accuracy, retrieve the sprint history associated with each milestone and for every sprint pull the individual story records. Consider only stories marked as done; sum their estimated points and sum their actual points. Compute the ratio of total actual to total estimated, then take the absolute deviation from one. Divide this deviation by the normalization factor found in the risk configuration file to get the dimension score, capping at one. If a milestone has no completed stories, the estimation accuracy score is zero.

For dependency risk, retrieve all dependencies linked to the milestone (both as source and as target). Each dependency has a severity weight recorded in the Confluence dependency analysis documents; look up the weight by dependency identifier. For every dependency whose status is at risk, add its full severity weight to the risk sum. For every dependency whose status is active and whose type is blocks, add its severity weight multiplied by the active blocking factor from the configuration. The dimension score is this weighted sum divided by the product of five and the total number of dependencies for the milestone, capped at one. If no dependencies exist, the score is zero. When a dependency identifier is not found in the Confluence documents, use a default severity weight of three.

For bug escape rate, retrieve all bug records associated with the milestone. Count how many were found in phases classified as escaped according to the risk configuration (these escaped phases are listed there). The raw escape rate is escaped bugs divided by total bugs. Separately, look up the test coverage percentage for each of the milestone's sprints from the QA report files and compute their average; if no coverage data is available, default to seventy. Multiply the raw escape rate by a coverage factor equal to two minus the average coverage divided by one hundred. Divide the result by the bug escape normalization factor from the configuration, capping at one. If the milestone has no bugs, the score is zero.

For team churn, retrieve the team assignments for the milestone, then look up each assigned member's details. A member counts as churned if their status is departed or if they were hired within the churn window (in days, specified in the configuration) relative to the reference date. Compute the raw churn fraction as the number of churned members divided by total assigned members. Then retrieve each active (non-departed) assigned member's effective capacity percentage from the team capacity files and compute the average, dividing by one hundred to express as a fraction; default to one if no active members exist. The dimension score is the raw churn fraction divided by the product of the average capacity and the team churn normalization factor, capped at one.

Once all four dimension scores are computed for a milestone, calculate the overall risk score as the weighted sum using the weights from the scoring weights file. Classify each milestone as HIGH if its overall score meets or exceeds the high threshold, MEDIUM if it meets or exceeds the medium threshold, or LOW otherwise; thresholds are in the risk configuration file.

Save a file called `risk_assessment.csv` containing one row per assessed milestone with columns: milestone_id, milestone_name, estimation_accuracy_score, dependency_risk_score, bug_escape_score, team_churn_score, overall_risk_score, risk_level. All scores must be rounded to four decimal places. Sort rows by overall_risk_score in descending order; break ties by milestone_id in ascending order.

Separately, save a file called `mitigation_checklist.md` that covers every milestone classified as HIGH, presented in the same sort order as the CSV. For each high-risk milestone, include a markdown level-two heading with the milestone name and its ID in parentheses, followed by the overall risk score and the four dimension scores each on their own line prefixed with a dash. Then list concrete mitigation actions for every dimension whose score exceeds the mitigation action threshold from the configuration. Mitigation actions should reference specific data: for estimation accuracy state the historical ratio, for dependency risk list the at-risk dependency identifiers sorted ascending, for bug escape state the count of escaped bugs out of total bugs, and for team churn list the churned member identifiers sorted ascending.

In your final response, list all high-risk milestone names in descending order of their overall risk score (ties broken by milestone ID ascending), separated by commas, prefixed with the text "High-risk milestones: ". If no milestones are high risk, state that none were identified.
