You are conducting a compliance review of all approved prerequisite waiver petitions at a university. Your goal is to identify every petition whose approval violated institutional policy, then compile a complete dossier of exceptions for the registrar's office.

Begin by reading the compliance policy configuration file, which specifies the rules governing waiver approvals. The policy defines a minimum cumulative GPA that students must hold to be eligible for any waiver, a maximum number of approved waivers any single student may accumulate, a minimum credit equivalence ratio for course substitutions, and a maximum number of calendar days allowed for processing a petition from submission to decision. It also establishes an authority hierarchy for approvers and maps course levels to the minimum authority required to sign off on a waiver. Courses flagged as non-waivable require a specific override authority level that is also stated in the policy. Additionally, the policy stipulates that petitions must be submitted before the semester start date for the semester in which the waiver is applied, and it lists the start date for each semester.

For each approved waiver petition, you must cross-reference the following compliance checks. First, verify that the student's cumulative GPA meets or exceeds the threshold specified in the policy. Second, determine the degree audit rule for the course in question under the student's enrolled program, and confirm that the approver's actual authority level, as recorded in the approver registry file, meets or exceeds what the rule requires. Third, if the degree audit rule marks the course as non-waivable, confirm that the approver possesses the override authority specified in the policy, otherwise flag it. Fourth, calculate the number of calendar days between submission and decision, and flag any petition where processing time exceeds the policy maximum. Fifth, check whether the petition was submitted after the semester start date for its designated semester, flagging any that were late. Sixth, count the total number of approved waivers for each student across all records and flag every petition belonging to a student who exceeds the maximum allowed count. Seventh, for any petition that has an associated course substitution, verify that the credit equivalence ratio meets the policy minimum.

A single petition may trigger multiple violations simultaneously. Every violation discovered must be recorded individually.

Once all petitions have been audited, save the results as `compliance_dossier.csv` containing columns: `petition_id`, `student_id`, `course_id`, `semester`, `violation_type`, `detail`. Each row represents one violation instance. The `violation_type` field must use exactly one of these values: `gpa_below_threshold`, `insufficient_authority`, `non_waivable_without_override`, `processing_time_exceeded`, `late_petition`, `max_waivers_exceeded`, `credit_equivalence_below_minimum`. The `detail` field should contain a brief human-readable explanation of the specific violation. Rows should be ordered by petition ID.

Separately, produce a file named `violation_summary.json` containing a JSON object with three keys: `total_non_compliant_petitions` giving the count of distinct petitions that have at least one violation, `total_violation_entries` giving the total number of individual violation rows across all petitions, and `violation_type_counts` giving an object mapping each violation type to the number of times it appears.

In your final response, state the total number of non-compliant petitions identified and the total number of violation entries recorded.
