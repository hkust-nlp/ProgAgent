You are auditing incentive payout claims submitted by ride-hailing drivers. Each claim references a specific trip and a promotional campaign, and your job is to determine whether the claim is eligible for payout, compute the correct adjusted amount, and document every reason a claim fails validation.

Start by reading the configuration files available to you. A peak-hours configuration file defines which hours of the day count as peak for weekdays versus weekends, expressed as hour ranges. A zone tier mapping file assigns every zone identifier to a tier category such as premium, standard, or economy. A payout policy file specifies how the correct payout amount is calculated, which session statuses count toward online-hours requirements, what trip status is required for eligibility, and how duplicate claims are handled. An eligibility rules document describes each validation check in detail, including how driver ratings are sourced, how online hours are computed from session records with partial overlap, and how the per-driver payout cap is enforced once all eligible amounts have been determined.

Retrieve all pending incentive claims using the available tools. Each claim carries a driver identifier, a campaign identifier, a trip identifier, and a claimed dollar amount. For every pending claim, apply the following validation checks.

First, confirm that the referenced trip exists and was completed successfully. A trip that was cancelled or resulted in a no-show is ineligible. Second, verify that the trip's start time falls within the campaign's active date window, from the campaign start date through the end date inclusive. Third, look up the trip's zone in the zone tier mapping and confirm that the zone's tier is among the tiers the campaign designates as eligible. Fourth, if the campaign is flagged as peak-hours-only, check that the trip's start hour falls within one of the defined peak-hour windows for the appropriate day type. Fifth, count the driver's completed trips during the campaign period and ensure the count meets or exceeds the campaign's minimum completed-trips requirement. Sixth, retrieve the driver's online session records that overlap the campaign period, include only sessions whose status is among the counted statuses specified in the payout policy, compute total online hours counting only the portion of each session that overlaps the campaign window, and verify the total meets the campaign's minimum online-hours threshold. Seventh, read the daily operations log files to obtain the driver's daily ratings for every date that falls within the campaign period, compute the average of those ratings, and confirm it meets or exceeds the campaign's minimum driver rating.

Once all eligibility checks pass, compute the correct payout amount. The base is the campaign's bonus-per-trip value. Multiply it by the zone-tier multiplier for the trip's zone tier as specified in the payout policy. Then look up surge pricing records for the trip's zone on the trip's date, identify every surge window that was active at the trip's start time, take the highest surge multiplier among them, and multiply the interim amount by that factor. If no surge window covers the trip's start time the surge factor is one. Round the result to the number of decimal places specified in the payout policy. If the claim's stated amount does not match this computed amount within a tolerance of one cent, record an amount mismatch discrepancy, but only when no other eligibility failure was already found.

Duplicate detection is also required. If more than one pending claim shares the same driver, campaign, and trip combination, every instance in that group must be rejected with a duplicate-claim reason.

After determining eligibility and computing amounts for all claims, enforce the per-driver payout cap for each campaign. Sort a driver's approved claims under a given campaign by claim identifier in ascending order, accumulate their adjusted amounts, and when the running total would exceed the campaign's maximum payout per driver, reduce the current claim's amount to the remaining allowance. Any subsequent claims receive zero. Every claim whose amount is reduced or zeroed by the cap should carry the reason per_driver_cap_exceeded, and claims reduced to zero are marked ineligible.

Save the final results as `adjusted_payout_report.csv` with the following columns in this order: `claim_id`, `driver_id`, `campaign_id`, `trip_id`, `claimed_amount`, `eligible`, `adjusted_amount`, `discrepancy_reasons`. The eligible column should contain True or False. The discrepancy_reasons column should contain semicolon-separated reason codes when there are failures, or the word none when the claim is fully eligible and its amount is correct. Use these exact reason codes where applicable: duplicate_claim, trip_not_completed, trip_outside_campaign_period, zone_not_eligible, trip_not_in_peak_hours, insufficient_completed_trips, insufficient_online_hours, rating_below_minimum, amount_mismatch, per_driver_cap_exceeded.

After writing the report, respond with a summary that states the total number of claims processed, the number approved, the number rejected, and the total adjusted payout amount formatted to two decimal places.
