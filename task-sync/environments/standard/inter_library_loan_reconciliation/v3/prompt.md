You are a library systems analyst tasked with producing a comprehensive reconciliation of overdue inter-library loan materials. The analysis date for this reconciliation is April 15, 2026, and all overdue calculations must be performed relative to that date.

Begin by locating and reading the fine calculation policy file, which is in YAML format and specifies the report date, default grace period, tiered daily fine rates, the default maximum fine cap, the replacement cost threshold in days, and condition-based cost multipliers. Separately, read the institution-specific agreements file in JSON format, which contains overrides for certain partner institutions, potentially including a custom grace period, a maximum fine cap, and a fine rate multiplier that scales all tier rates for that institution. Where an institution has an override, it takes precedence over the defaults in the policy file; where no override exists, the defaults apply.

Next, gather all condition assessment reports, which are spread across multiple CSV files. Each row maps a book identifier to a condition grade and optional damage description. Also read all insurance record files in JSON format, each containing entries with a loan identifier, coverage amount, deductible, and policy status. Only records with an active policy status contribute insurance coverage, and the effective coverage is the coverage amount minus the deductible, floored at zero. Finally, read all patron communication preference files in plain text, which list each patron's preferred contact method, a do-not-contact flag, and any relevant notes.

Consult the recovery procedures document in Markdown format, which defines the recovery action categories based on adjusted days overdue. A loan's adjusted days overdue equals the raw number of days between the due date and the report date minus the applicable grace period, floored at zero. The categories are: one through fourteen adjusted days maps to courtesy_reminder, fifteen through thirty to formal_notice, thirty-one through sixty to final_warning, sixty-one through ninety to collection_referral, and anything exceeding ninety days or any loan marked lost maps to replacement_invoice. The document also explains that when the total liability (fine plus net replacement cost) exceeds one hundred dollars the item is high_priority, otherwise normal_priority. If a patron's do-not-contact flag is yes, the contact_hold field should be true; otherwise false.

Using the available tools, retrieve all loans currently in overdue status and all loans in lost status. For every such loan, retrieve the associated book details (title, base replacement cost), patron information (name, email), partner institution information (name), shipment tracking records, and contact history. The tools return data page by page where applicable, so be sure to iterate through all pages.

For each overdue or lost loan, compute the fine as follows. Determine the adjusted days overdue using the applicable grace period. Walk through the fine tiers defined in the policy, applying each tier's rate per day (multiplied by the institution's fine rate multiplier if one exists) for the number of days falling within that tier's range, accumulating the total. Cap the total fine at the applicable maximum fine cap. Round the fine to two decimal places.

A loan incurs replacement liability when its adjusted days overdue exceeds the replacement threshold specified in the policy, or when its status is lost. The gross replacement cost equals the book's base replacement cost multiplied by the condition multiplier corresponding to the book's condition grade from the assessment files. If no condition assessment exists for a given book, assume a grade of B. If the loan has an active insurance policy, the insurance coverage equals coverage amount minus deductible floored at zero, and the net replacement cost equals the gross replacement cost minus the insurance coverage floored at zero. For loans not liable for replacement, the gross replacement cost, insurance coverage, and net replacement cost are all zero. Round all monetary values to two decimal places.

Produce a file called `reconciliation_report.csv` containing one row per actionable overdue or lost loan (those with an adjusted days overdue of at least one, or status lost). The CSV must have these columns in this exact order: `loan_id`, `book_title`, `patron_name`, `partner_institution`, `days_overdue`, `fine_amount`, `replacement_liable`, `gross_replacement_cost`, `insurance_coverage`, `net_replacement_cost`, `total_liability`, `recovery_action`, `priority`, `contact_hold`. The `days_overdue` column holds the integer adjusted days overdue. The `fine_amount`, `gross_replacement_cost`, `insurance_coverage`, `net_replacement_cost`, and `total_liability` columns are formatted to exactly two decimal places. The `replacement_liable` column is either `yes` or `no`. The `contact_hold` column is either `true` or `false` in lowercase. Sort the rows by days_overdue in descending order, breaking ties by loan_id in ascending lexicographic order.

Also produce a file called `recovery_actions.json` structured as a JSON object whose keys are the recovery action category names (courtesy_reminder, formal_notice, final_warning, collection_referral, replacement_invoice) and whose values are lists of objects. Each object must include `loan_id`, `patron_name`, `patron_email`, `fine_amount`, `net_replacement_cost`, `total_liability`, `priority`, and `contact_hold`.

Once all files are saved, report the total number of actionable overdue and lost items, the total sum of all fines formatted to two decimal places with a dollar sign, and the total sum of all net replacement costs formatted to two decimal places with a dollar sign.
