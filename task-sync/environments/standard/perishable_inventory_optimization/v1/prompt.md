You are tasked with generating recommended purchase orders for a chain of grocery stores that sell perishable ingredients. The goal is to minimize waste of short-shelf-life items while ensuring each location has adequate stock to meet customer demand until its next scheduled delivery.

Begin by discovering all store locations and all ingredients tracked by the system. Store configuration files in JSON format contain each store's delivery schedule, specifying which days of the week that store receives shipments. Ingredient specification files in CSV format list every ingredient's shelf life, waste threshold percentage, and a reorder multiplier that adjusts the base order quantity for that particular item. A YAML policy file defines the global ordering parameters: the number of safety stock days to maintain, the waste reduction factor to apply when an ingredient's waste rate exceeds its threshold, and the priority classification thresholds expressed as days of supply remaining. A supplier ratings file in CSV format provides each supplier's reliability score, which serves as a tiebreaker when two suppliers offer the same unit cost for an ingredient.

For every store, retrieve its recent sales history covering the most recent fourteen-day window available in the system. Use this data to calculate each ingredient's average daily demand at that store, dividing total quantity sold by the number of days on which sales were recorded. Separately, retrieve each store's current inventory levels and its waste log data showing total quantities wasted per ingredient.

Once you have demand, inventory, and waste data for a store, compute the recommended order quantity for each ingredient the store carries. The base order quantity equals the average daily demand multiplied by the number of days until the store's next delivery, minus the current inventory on hand, plus a safety buffer equal to the safety stock days multiplied by average daily demand. Multiply this base quantity by the ingredient's reorder multiplier from the specification files. To determine days until next delivery, find the next occurrence of any of the store's scheduled delivery days strictly after the reference date, which is the day immediately following the last date with recorded sales. If the reference date itself falls on a delivery day, use the following week's occurrence instead.

Next, calculate the waste percentage for each store-ingredient pair as the total quantity wasted divided by the sum of total quantity sold and total quantity wasted over the available history. When this waste percentage exceeds the ingredient's waste threshold from the specification files, reduce the order quantity by multiplying it by one minus the waste reduction factor from the ordering policy. If the adjusted order quantity falls to zero or below, do not generate an order line for that combination.

For each ingredient requiring an order, identify the cheapest available supplier by querying supplier options for that ingredient. When multiple suppliers share the lowest unit cost, select the one with the highest reliability score from the supplier ratings file. Round the final order quantity up to the nearest multiple of that supplier's pack size, and compute the total cost as the rounded quantity multiplied by the unit cost.

Assign a priority level to each order line based on how many days of supply the store currently holds for that ingredient, calculated as current inventory divided by average daily demand. If days of supply is below the critical threshold from the ordering policy, mark it critical. If below the high threshold, mark it high. If below the medium threshold, mark it medium. Otherwise mark it low.

Save the complete set of purchase orders as `purchase_orders.csv` with the following columns in this exact order: `store_id`, `store_name`, `ingredient_id`, `ingredient_name`, `supplier_id`, `supplier_name`, `recommended_qty`, `unit_cost`, `total_cost`, `priority`. Sort the rows first by store_id ascending, then by priority in the order critical before high before medium before low, then by ingredient_id ascending within each priority group.

Separately, produce a `waste_reduction_report.csv` documenting every store-ingredient combination where the waste percentage exceeded its threshold and a reduction was applied. This file must contain columns: `store_id`, `store_name`, `ingredient_id`, `ingredient_name`, `waste_pct`, `waste_threshold_pct`, `adjustment_applied`, `original_qty`, `adjusted_qty`, `order_eliminated`. The `order_eliminated` column should be True when the adjustment drove the order quantity to zero or below, and False otherwise. Sort this file by store_id then ingredient_id.

In your final response, provide a summary that states the total number of purchase order lines generated, how many store locations are covered, the total cost across all orders, the count of critical-priority items, and the count of high-priority items.
