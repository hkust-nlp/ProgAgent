You are a payments operations analyst at an international bank responsible for reconciling failed cross-border wire transfers. A backlog of high-value payments has accumulated that could not be settled through normal straight-through processing, and each must now be investigated individually to determine what went wrong, what impact the failure had on the bank's nostro accounts, and exactly what the operations team needs to do to resolve each case.

Begin by consulting the reference files that define how the bank classifies payments and failures. A JSON file describes the monetary thresholds above which a payment in each currency is considered high-value; only payments meeting or exceeding their currency's threshold should appear in the final reconciliation. A separate JSON file maps every SWIFT rejection status code to a human-readable description, a root cause category, and a severity level. A YAML configuration file specifies the fee calculation method: for any payment the expected fee equals the greater of the payment amount multiplied by that currency's published rate, or the currency's minimum fee floor. Another YAML file lays out the rules for assigning each reconciled payment a priority of CRITICAL, HIGH, or MEDIUM, evaluated top to bottom with the first matching rule winning, followed by the prescribed sort order. Finally, a Markdown document explains the required manual intervention steps for each root cause category, and it also states the override rule: when the correspondent bank used for a payment is flagged as inactive, the root cause must be set to BANK_INACTIVE regardless of the SWIFT code.

Once you understand the rules, retrieve all payments whose status is FAILED. For each one that qualifies as high-value according to the currency thresholds, pull its full details including the sender and receiver BIC codes. Then obtain the SWIFT message trail for that payment, identify the rejection status code from the trail, and look up its meaning in the status code reference. Check whether the receiver's correspondent bank is active or inactive, because an inactive bank overrides the root cause to BANK_INACTIVE. Retrieve the fee record for the payment and note the expected and actual fees as recorded there, computing the fee discrepancy as actual minus expected, rounded to two decimal places.

Separately, you must determine the nostro account impact for each failed payment. Daily nostro account statement files are available in CSV format, each covering a date range and carrying a reconciliation flag for every entry. Locate the entries whose reference matches the payment and inspect their debit/credit indicators together with the reconciliation flag. If a debit exists with a flag of UNMATCHED, the nostro impact is STRANDED_DEBIT. If a debit exists but has been reversed with a matching credit so the flag reads MATCHED, the impact is REVERSED. If no debit was posted at all, the impact is NO_DEBIT.

On top of this, customer batch submission files in JSON format contain an urgency field for each payment that feeds into the priority rules. Read all batch files and note the urgency level recorded for each payment reference, then apply the priority determination rules in order: an inactive correspondent bank makes the payment CRITICAL, as does a root cause of INSUFFICIENT_FUNDS or a customer urgency of CRITICAL; an amount at or above twice the high-value threshold, a customer urgency of URGENT, or a fee discrepancy exceeding twenty percent of the expected fee makes it HIGH; everything else is MEDIUM. Sort the final results by priority with CRITICAL first, HIGH second, MEDIUM third, and within each priority group by amount in descending order.

Save the output as `reconciliation_report.csv` with the following columns in this exact order: `payment_id`, `payment_ref`, `customer_name`, `amount`, `currency`, `sender_bic`, `receiver_bic`, `failure_date`, `swift_status_code`, `root_cause`, `expected_fee`, `actual_fee`, `fee_discrepancy`, `nostro_impact`, `manual_intervention`, `priority`. The failure date should be the date portion of the timestamp on the SWIFT rejection message. Fee values must appear as numbers rounded to two decimal places. The manual intervention text for each row should be the full intervention description corresponding to its root cause as given in the escalation procedures document.

When you are finished, respond with a summary stating how many failed high-value payments were reconciled, how many have stranded debits and the total stranded amount, and the total absolute fee discrepancy across all reconciled payments.
