You work as a supply chain analyst at a manufacturing facility that operates multiple assembly lines producing different products. Recent disruptions have raised concerns about component stockouts that could halt production. Your objective is to analyze the current situation comprehensively and generate a prioritized list of purchase orders to prevent any stockout.

Start by examining the configuration files in your working directory. A YAML configuration file specifies how many days of safety stock should be maintained for each component category along with threshold values that classify shortage risk into severity levels. A JSON file defines the weights and scoring tables for calculating purchase order priority scores. A markdown document describes the procurement policy including supplier qualification rules, lead time adjustment factors, and order quantity rounding conventions. A CSV file maps each component to its criticality tier.

Historical consumption data is captured in weekly CSV log files that record daily component consumption for each assembly line. These logs reflect actual usage including waste and variance from standard rates. You should compute the average daily consumption per line and component from all available log entries and use those averages as the basis for demand projections rather than relying on standard rates alone. Supplier delivery performance is captured in JSON batch report files containing records of each delivery with its promised versus actual lead time. Compute each supplier's on-time delivery rate as the fraction of deliveries where the actual lead time did not exceed the promised lead time.

You will also need to query the system for current operational data: which assembly lines are active, what production schedules are running and their remaining duration, what components each line consumes and at what standard rate per product unit, current inventory levels for each component, and the available supplier offers for any given component.

For every active production schedule, determine the number of remaining production days from today (2026-04-20) through the schedule's end date. Estimate projected component demand using the average daily consumption from the historical log files for each line-component pair. When no historical consumption data is available for a given line-component combination, compute projected consumption as the remaining units to produce (remaining days multiplied by daily target) multiplied by the standard units-per-product rate. Sum projected demand across all active schedules for each component.

A component is at risk of stockout when its net need is positive. Net need equals projected total demand minus available inventory (quantity on hand minus reserved quantity) plus the required safety stock. The safety stock quantity is the number of safety stock days for the component's category (from the YAML configuration) multiplied by the component's total average daily consumption across all active lines. For each active line using the component, the daily consumption contribution is the average from the logs if available, or the standard units-per-product rate multiplied by the daily target of the active schedule on that line otherwise.

For each at-risk component, evaluate all supplier offers according to the procurement policy. Apply the lead time adjustment factor based on each supplier's on-time rate, calculate the adjusted cost as unit price times the adjustment factor, and select the supplier with the lowest adjusted cost among those meeting the qualification threshold. If no supplier qualifies, select the one with the highest on-time rate. Determine the order quantity and estimated lead time as the policy prescribes.

Calculate a priority score for each purchase order as a weighted sum of four factors using the weights from the JSON configuration. Shortage severity is the minimum of 1.0 and the ratio of net need to projected demand. Criticality uses the component's tier mapped through the scoring table in the configuration. Production priority takes the highest priority level among all active schedules whose lines use the component, mapped through the scoring table. Lead time urgency is the minimum of 1.0 and the ratio of estimated lead time to days until stockout, where days until stockout equals available inventory divided by total average daily consumption for the component. Round the final priority score to two decimal places.

Assign each component a risk level by comparing its shortage severity against the thresholds in the YAML configuration, checking from the highest threshold downward and assigning the first level whose threshold the severity meets or exceeds.

Save the output as `purchase_orders.csv` with columns in this exact order: `component_id`, `component_name`, `supplier_id`, `supplier_name`, `order_quantity`, `unit_price`, `total_cost`, `priority_score`, `risk_level`, `estimated_lead_days`. Sort rows by `priority_score` in descending order, breaking ties by `component_id` in ascending order. The `total_cost` column should equal `order_quantity` multiplied by `unit_price`, rounded to two decimal places.

In your final response, state the total number of at-risk components and the grand total cost across all purchase orders formatted with a dollar sign and two decimal places. Also name the three highest-priority components along with their priority scores and risk levels.
