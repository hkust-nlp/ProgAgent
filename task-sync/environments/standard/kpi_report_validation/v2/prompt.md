Your firm manages a diversified portfolio of SaaS companies across several investment funds. Each quarter, portfolio companies submit KPI reports covering key operating metrics, and these reports must be rigorously validated before they reach the partner review meeting. The current reporting period is Q4 2025, and the validated baseline quarter is Q3 2025. A manifest file in CSV format has been placed alongside the individual company report files; it lists every received submission together with its corresponding filename and company identifier. Several configuration documents govern how validation is performed: one YAML document defines per-metric tolerance thresholds (some expressed as relative percentages, others as absolute values), quarter-over-quarter growth rate caps for selected metrics, and rules for classifying the severity of any discrepancy that is found. A separate CSV file provides materiality thresholds broken down by sector and metric. A plain-text policy document describes fund-level review requirements, including whether any severity levels should be escalated for companies belonging to specific funds. A markdown reference document explains what each tracked metric represents and how it is measured.

For every company that filed a Q4 2025 submission, retrieve that company's details so you know its sector and fund assignment, then pull the matching figures from the SaaS monitoring platform, the signed board deck, and the previous quarter's validated baseline. Compare each metric in the submission against the SaaS platform value and, separately, against the board deck value. For metrics whose tolerance is specified as relative, compute the discrepancy as the absolute difference between the submitted value and the reference value divided by the absolute value of the reference. For metrics whose tolerance is absolute, use the raw absolute difference. If the computed discrepancy strictly exceeds the tolerance stated in the rules document, that pair constitutes an exception. Separately, for every metric that carries a quarter-over-quarter growth cap, compute the absolute percentage change between the submitted current-quarter value and the previous quarter's validated value (treating the previous value as the denominator), and flag it whenever that rate strictly exceeds the cap; the reference source for such entries is the previous-quarter baseline.

Once a discrepancy has been identified, classify its severity. Compute the tolerance multiple, which is the ratio of the actual discrepancy (in the same units used for the tolerance comparison, relative or absolute) to the tolerance value. If the tolerance multiple exceeds three and the absolute numerical discrepancy also exceeds the sector-specific materiality threshold for that metric, the severity is CRITICAL. If only one of those two conditions holds, the severity is HIGH. If the tolerance multiple exceeds two but neither the three-times nor the materiality condition is met, the severity is MEDIUM. Otherwise the severity is LOW. After assigning a base severity, consult the fund review policy document and apply any fund-level escalation that it prescribes.

Produce a file called `exception_report.csv` containing one row per flagged exception. The columns must appear in exactly this order: `company_id`, `company_name`, `metric_name`, `submitted_value`, `reference_source`, `reference_value`, `discrepancy_pct`, `severity`. The `reference_source` column must contain one of the strings `saas_platform`, `board_deck`, or `qoq_baseline`. The `discrepancy_pct` column holds the percentage-form discrepancy rounded to exactly two decimal places, so a five-and-a-quarter-percent deviation is written `5.25` and a sixty-point-three-percent quarter-over-quarter change is written `60.30`. Values in `submitted_value` and `reference_value` should appear exactly as sourced with no additional rounding. Sort the rows first by severity in descending criticality (CRITICAL first, then HIGH, then MEDIUM, then LOW), then alphabetically by company name within each severity tier, and finally alphabetically by metric name within each company, with ties on all three broken by reference source in alphabetical order.

In your final response, state the total number of exceptions found as "Total exceptions: N", provide the count for each severity level on its own line formatted as "CRITICAL: N", "HIGH: N", "MEDIUM: N", "LOW: N", and report the number of distinct companies that have at least one exception as "Companies with exceptions: N".
