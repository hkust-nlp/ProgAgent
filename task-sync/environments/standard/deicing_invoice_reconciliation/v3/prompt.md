You are the winter operations financial analyst for a major international airport. De-icing service providers have submitted their invoices for recent winter operations, and your task is to reconcile every pending invoice against the actual operational records before releasing payment. The airport contracts with multiple de-icing providers, each operating fleets of specialized trucks that spray anti-icing and de-icing fluids on aircraft before departure. Each provider's contracted per-liter rate varies by fluid type and is documented in a JSON file containing the rate schedules, effective dates, and provider identifiers. A YAML configuration file specifies the validation tolerances and business rules you must apply, including the acceptable percentage deviation between invoiced and actual fluid quantities, how to detect duplicate billing, and the relationship between service timing and aircraft pushback.

Your primary data sources are the truck fluid usage logs, which are CSV files recording every dispensing event with the service identifier, truck identifier, actual liters dispensed, fluid type, and the start and end timestamps of each service. These logs represent the ground truth for how much fluid was actually used. Separately, you can retrieve invoice details, service records, and flight information through the available query tools. Each invoice references a specific service event and claims a quantity of fluid at a particular rate. The service records link each de-icing event to the flight it served, the truck that performed it, and the ambient temperature at the time. Flight records provide the scheduled departure and the actual pushback timestamp, which is critical for verifying that de-icing service was completed before the aircraft moved.

To validate each invoice, you must perform several cross-checks. First, compare the quantity charged on the invoice against the actual dispensed quantity from the truck logs. If the charged quantity exceeds the actual quantity by more than the tolerance percentage specified in the validation policy, flag the invoice as a quantity overcharge. Second, verify that the rate charged matches the contracted rate for that provider and fluid type. Any deviation in the charged rate from the contracted rate constitutes a rate mismatch. Third, check the service timing: if the recorded service end time falls after the flight's actual pushback timestamp, flag this as a time anomaly, since de-icing must be completed before pushback. Fourth, detect duplicate billing by identifying multiple invoices referencing the same service identifier; the first invoice encountered (by invoice ID sort order) is the original, and any subsequent invoices for the same service are duplicates.

For every invoice that passes all checks with no discrepancies, set its status to approved, and its approved quantity, rate, and amount should match the invoiced values. For flagged invoices, compute the correct approved values as follows: if the invoice is a duplicate, set the approved quantity, rate, and amount all to zero. Otherwise, use the actual dispensed quantity from the truck logs as the approved quantity (or the charged quantity if no truck log entry exists), use the contracted rate as the approved rate, and compute the approved amount as the product of approved quantity and approved rate, rounded to two decimal places.

Once you have processed all invoices, produce two output files. The first is a file named `approved_payments.csv` containing one row per invoice with the following columns in this exact order: `invoice_id`, `service_id`, `provider_name`, `flight_id`, `fluid_type`, `approved_quantity`, `approved_rate`, `approved_amount`, `status`, `discrepancy_flag`. The status column must contain either `approved` or `flagged`. The discrepancy_flag column must contain `none` for approved invoices, or a pipe-delimited list of applicable discrepancy types for flagged invoices, using exactly these labels: `quantity_overcharge`, `rate_mismatch`, `time_anomaly`, `duplicate_billing`. When multiple discrepancy types apply to a single invoice, join them with the pipe character without spaces. The rows should follow invoice ID sort order.

The second output file is `discrepancy_report.csv` with columns: `invoice_id`, `discrepancy_type`, `charged_value`, `expected_value`, `difference`. Each row documents one specific discrepancy, so an invoice with two issues produces two rows. For quantity overcharges, the charged and expected values are the charged and actual liter amounts, and the difference is their numeric difference. For rate mismatches, the charged and expected values are the charged and contracted per-liter rates. For time anomalies, the charged value is the service end timestamp, the expected value is the pushback timestamp, and the difference is the gap in minutes. For duplicate billing, the charged value is the total charge, the expected value is zero, and the difference equals the total charge.

In your final response, state the total number of invoices processed, the number flagged with discrepancies, the total approved amount formatted to two decimal places, and a breakdown of how many discrepancies were found in each category: quantity_overcharge, rate_mismatch, time_anomaly, and duplicate_billing.
