Your organization operates a nationwide franchise network and recent internal reviews have raised concerns that some franchisees may be procuring goods from suppliers who are either absent from the approved vendor lists or whose vendor approvals have lapsed. You have been tasked with conducting a comprehensive procurement compliance audit across the entire franchise system to identify and document every instance of non-compliant purchasing activity.

Begin by determining which franchisees fall within the audit scope. A plain-text configuration file in your working directory specifies the audit period and which franchisee statuses are included in the review. Only franchisees whose status matches the filter defined in that file should be examined. For every in-scope franchisee, retrieve all of their purchase orders. Each franchisee operates within a designated region, and you will find CSV files in your working directory containing the approved vendor lists organized by region. These files list each approved supplier along with the start and end dates of their approval window. When a purchase order references a supplier that does not appear at all on the approved vendor list for the franchisee's region, that purchase constitutes an UNAPPROVED_SUPPLIER violation. If the supplier does appear on the regional list but the approval period had already ended before the date of the purchase order, that constitutes an EXPIRED_APPROVAL violation. These two violation types are mutually exclusive for any given purchase order: a supplier is either missing from the list entirely or present but expired.

Separately, examine quality complaint records for every supplier involved in purchase orders. A YAML-formatted compliance policy file in your working directory defines a complaint threshold as an integer count. Any supplier whose total number of quality complaints across the system meets or exceeds that threshold is considered quality-flagged, and every purchase order placed with such a supplier constitutes a QUALITY_FLAGGED violation. The severity score for a QUALITY_FLAGGED violation is computed by multiplying the base severity weight for that violation type, as defined in the compliance policy, by the highest applicable severity multiplier among all of the flagged supplier's complaint severity levels. The multiplier table mapping severity level names to their numeric multipliers is also found in the compliance policy file.

On top of this, central distribution center shipment logs are available as JSON files in your working directory. These logs document shipments that were routed through the organization's central distribution system. For each purchase order, check whether a matching shipment record exists by comparing the franchisee, supplier, and invoice reference fields. If no matching record is found, the purchase is considered to have bypassed central distribution, which constitutes a DC_BYPASS violation. A single purchase order can trigger multiple violation types simultaneously if it meets the criteria for more than one.

Once all violations have been identified, produce a file called `compliance_report.csv` containing one row for every individual violation instance. The CSV must contain exactly these columns in this order: `franchisee_id`, `franchisee_name`, `supplier_id`, `supplier_name`, `violation_type`, `invoice_number`, `order_date`, `total_amount`, `severity_score`, `evidence`. The severity score for any violation type other than QUALITY_FLAGGED equals the base severity weight for that type as specified in the compliance policy. All severity scores must be formatted to exactly two decimal places. The evidence column should contain a concise explanation of why the violation was flagged: for UNAPPROVED_SUPPLIER, mention the supplier name, its ID, and the region where it was not found; for EXPIRED_APPROVAL, include the supplier name, its ID, the approval expiry date, and the order date; for QUALITY_FLAGGED, state the supplier name, its ID, the complaint count, the threshold, and the highest severity level; for DC_BYPASS, note the invoice number for which no shipment record was found. Sort the entire report first by severity_score in descending order, then by franchisee_id in ascending order as the first tie-breaker, then by order_date in ascending order as the second tie-breaker.

In your final response, state the total number of violations found, break them down by each violation type with their respective counts, report how many distinct franchisees and how many distinct suppliers are involved in violations, and list the top three franchisees by total violation count along with their names and counts.
