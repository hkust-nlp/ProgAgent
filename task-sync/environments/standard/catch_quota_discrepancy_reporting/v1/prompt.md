You are responsible for reconciling the quarterly catch activity of a fleet of fishing vessels against their species-specific quota allocations. The objective is to identify every vessel-species combination where the total catch exceeds the effective quota by more than the allowed tolerance, and to flag any instances of restricted-species fishing in prohibited zones. The analysis period covers Q1 2026 (January through March).

To determine the total catch for each vessel and species, you must combine two sources. The first source is the electronic catch reporting system, which you can query through the available tools to obtain per-vessel, per-species catch totals. The second source is a set of CSV files containing manual landing supplements recorded at various ports. These supplement files follow the naming pattern starting with "landing_supplement_" and contain columns for vessel_id, species_code, and manual_landing_kg. The quantities from both sources must be summed together to arrive at the true total catch for each vessel-species pair.

Quota allocations are held in certificate records accessible through the tools. Each certificate specifies an allocated quota in kilograms for a vessel-species combination over a defined period. However, the raw allocated quota must be adjusted before comparison. A YAML configuration file contains seasonal adjustment factors keyed by month name. To compute the effective quota, take the allocated quota and multiply it by the minimum seasonal adjustment factor among all months that fall within the certificate's period. For instance, if the period spans January through March and the March factor is lower than the others, the entire allocation is scaled by the March factor.

The same configuration file specifies a tolerance percentage. A discrepancy exists only when the total catch exceeds the effective quota by more than this tolerance percentage. When a discrepancy is found, compute the overage in kilograms (total catch minus effective quota) and the overage as a percentage of the effective quota. If a vessel has catch for a species but no quota certificate exists for that species at all, the entire catch amount constitutes an overage at one hundred percent, classified under the most severe tier. The configuration file also defines overage tiers, each with a minimum and maximum percentage range and a tier name. Classify every discrepancy into the appropriate tier based on its overage percentage.

Separately, you need to detect zone restriction violations. The configuration file lists, for each fishing zone, which species are restricted from being caught there. AIS zone summary files in JSON format (named with the pattern "ais_zone_summary_vessel_" followed by the vessel identifier) indicate which zones each vessel spent time in during the quarter. For every vessel that has an AIS zone summary showing time in a zone where species are restricted, check whether that vessel filed any electronic catch reports for those restricted species in that zone. If so, record it as a zone violation with the vessel identifier, vessel name, species code, zone code, the total kilograms caught in that zone, and the hours spent in that zone.

Once you have completed the analysis, save the quota discrepancy results to a file called `discrepancy_report.csv` with the following columns in this exact order: `vessel_id`, `vessel_name`, `species_code`, `allocated_quota_kg`, `total_catch_kg`, `overage_kg`, `overage_pct`, `tier`. Sort the rows by overage_pct in descending order. Values for allocated_quota_kg, total_catch_kg, overage_kg, and overage_pct should be rounded to two decimal places.

On top of this, save the zone violation results to a file called `zone_violations.csv` with columns: `vessel_id`, `vessel_name`, `species_code`, `zone_code`, `catch_kg_in_zone`, `hours_in_zone`. Sort these rows first by vessel_id ascending, then by zone_code ascending, then by species_code ascending.

In your final response, state the total number of quota discrepancies found and the total number of zone restriction violations found, confirming that the two deliverable files have been written.
