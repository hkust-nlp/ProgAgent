You are tasked with validating and certifying subcontractor progress payment applications for a large construction project. The project involves multiple subcontractors across various trades, each with their own schedule items, and several of these subcontractors have submitted payment applications that are currently pending review. Your job is to process every pending payment application, cross-reference the relevant documentation, apply the governing payment policy, and produce a certified payment schedule.

Begin by retrieving all payment applications that carry a status of "pending." For each such application, you will need to gather several pieces of information from different sources. The application itself provides the claimed completion percentage and claimed dollar amount. You must then look up the corresponding schedule item to obtain the budgeted amount for that line of work, and retrieve the subcontractor's name for reporting purposes. An architect inspection report exists for each schedule item and provides a verified completion percentage along with a deficiency flag indicating whether quality issues were noted during the inspection.

In addition to the data available through queries, you must consult the files stored alongside this task. A set of work completion certificates can be found in a folder called `certificates`, each named according to the pattern `cert_XXXX.json` where the number corresponds to the payment application identifier. Each certificate contains a `certified_completion_pct` field representing the site supervisor's independent assessment of completion, and critically, a `supervisor_signed_off` boolean indicating whether the supervisor has formally endorsed the claimed work. A YAML file named `payment_policy.yaml` governs all approval thresholds and deduction rates, and you must read and apply every parameter it defines rather than assuming any default values.

The approved completion percentage for each application is determined by taking the minimum of three values: the claimed completion percentage from the application, the verified completion percentage from the architect inspection report, and the certified completion percentage from the corresponding work completion certificate. If the supervisor has not signed off on the certificate, the application must be rejected outright with all monetary fields set to zero. Likewise, if the approved percentage falls below the minimum threshold specified in the policy, the application is rejected.

For applications that pass these initial checks, the gross approved amount equals the schedule item's budgeted amount multiplied by the approved completion percentage divided by one hundred. Three categories of deductions may then apply. First, if the inspection report flags a deficiency, a deduction equal to the gross approved amount multiplied by the deficiency deduction rate from the policy is assessed. Second, material delivery verification requires comparing the total delivery amounts recorded in the system for that schedule item against the invoice line totals found in corresponding CSV files within the `invoices` folder, named as `invoice_SI-XXX.csv` where the identifier matches the schedule item code. If the absolute difference between the system total and the invoice total exceeds the tolerance fraction specified in the policy multiplied by the system total, a material discrepancy penalty is applied at the rate given in the policy. Third, daily site supervisor logs stored as markdown files in a `logs` folder must be examined for any lines referencing the schedule item code that contain the phrase "No activity" — each such log entry counts as one stoppage day, and if the total stoppage days for a given item exceed the maximum allowed in the policy, a delay penalty calculated as the gross approved amount times the delay penalty rate is added.

Once all applicable deductions are summed, subtract them from the gross approved amount to obtain the adjusted figure. Retention is then calculated as this adjusted amount multiplied by the retention rate from the policy. The net payable amount is the adjusted figure minus the retention. All monetary values must be rounded to two decimal places at each computational step.

Save the final output as a file named `certified_payment_schedule.csv` containing one row per pending application sorted by application identifier in ascending order. The file must use exactly these column headers in this order: `application_id`, `subcontractor_name`, `schedule_item_id`, `item_description`, `claimed_amount`, `approved_pct`, `gross_approved`, `total_deductions`, `retention`, `net_payable`, `status`. The status column should read "approved" for applications that pass all checks or "rejected" for those that fail due to missing supervisor sign-off or insufficient approved percentage.

Once the schedule is complete, state in your final response the four summary totals across all processed applications: Total Gross Approved, Total Deductions, Total Retention, and Total Net Payable, each formatted to exactly two decimal places.
