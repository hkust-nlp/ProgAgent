A municipal government has issued a tender for a large-scale infrastructure improvement program and received bids from numerous suppliers. Your job is to evaluate every bidder, apply a rigorous set of disqualification rules, compute multi-dimensional scores for each surviving vendor, and produce a ranked shortlist of compliant candidates.

Begin by reviewing the tender specification file, which is in YAML format and spells out the tender's required certificate types, the minimum average past-performance score, the minimum number of years a company must have been established before the evaluation date, and other contextual details. Alongside it you will find a JSON file listing all sustainability criteria, each marked as mandatory or optional, and a separate JSON file enumerating the disqualification rules that must be applied in order. A YAML file describing the scoring methodology lays out five evaluation dimensions, their weights, component breakdowns, normalization formulas, and the tie-breaking rule for the final ranking.

Once you understand the rules, retrieve the full list of suppliers who submitted bids for the tender. For every bidder, pull their company profile to learn when they were established, then retrieve their qualification certificates, their past project performance records, and their sustainability criteria responses. You will also need each bidder's itemized bid pricing for the tender.

Financial health data for suppliers is spread across several CSV files whose names start with "financial_batch_" followed by a sequential number. Each row carries a supplier identifier, the supplier name, annual revenue in millions, profit margin percentage, debt ratio, liquidity ratio, and credit score. Not every supplier in those files is necessarily a bidder, but every bidder's financial figures appear in exactly one of those files.

Client reference feedback is captured in a set of text files whose names start with "reference_summary_" followed by a sequential number. Inside each file, blocks of prose describe individual suppliers. Embedded within each block is a line containing a reliability rating expressed as a decimal out of ten. You must parse out each supplier's rating from these files. If a bidder does not appear in any reference file, treat their reliability rating as five out of ten.

Independent technical evaluations of each bidder's proposal are stored in JSON files whose names start with "technical_evaluation_" followed by a sequential number. Each entry contains a supplier identifier together with a technical score, an innovation score, and a methodology score.

Apply the disqualification rules strictly and in the order given. A bidder is disqualified if they are missing any of the certificate types required by the tender specification, or if any required certificate they hold has an expired status. A bidder is also disqualified if not every mandatory sustainability criterion received a "compliant" response. Separately, a bidder whose average past-performance score falls below the tender's minimum threshold, whose debt ratio exceeds the limit stated in the disqualification rules, or whose company was established fewer than the required number of years before the tender evaluation date must likewise be removed.

For each bidder who survives all checks, compute five dimension scores. The performance dimension blends the arithmetic mean of the bidder's past project performance scores with their reliability rating, using the component weights specified in the scoring methodology. The financial dimension is a weighted combination of four sub-components, each normalized according to the formula given in the methodology file. The pricing dimension scores each qualified bidder's total bid amount relative to the lowest total bid among all qualified bidders, following the inverse-normalization method described in the methodology. The sustainability dimension assigns a value of one for each criterion marked compliant, half for each marked partial, and zero for non-compliant, then divides by the total number of criteria and scales to a hundred-point range. The technical dimension combines the three technical-evaluation sub-scores using the weights in the methodology.

Multiply each dimension score by its weight and sum to obtain the composite score. Rank all qualified vendors in descending order of composite score. If two vendors share the same composite score, the one with the lower total bid amount ranks higher.

Save the ranked shortlist as `vendor_shortlist.csv` with columns in this exact order: `rank`, `supplier_id`, `supplier_name`, `composite_score`, `performance_score`, `financial_score`, `pricing_score`, `sustainability_score`, `technical_score`. All score values must be rounded to exactly two decimal places. Rows should appear in ascending rank order, with rank one being the top vendor.

Separately, save a file named `disqualification_report.json` containing a key `disqualified_vendors` whose value is an array of objects, each carrying `supplier_id`, `supplier_name`, and `reasons` (a list of strings describing why the vendor was disqualified). The same JSON object should also include keys `total_evaluated` (the total number of bidders assessed), `total_disqualified`, and `total_qualified`.

In your final response, state the total number of bidders evaluated, the number that were disqualified, the number that qualified for the shortlist, and the name and composite score (to two decimal places) of the top-ranked vendor.
