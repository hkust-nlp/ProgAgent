You are auditing a portfolio of podcast series to identify those suffering from meaningful listener retention decline. The central concern is that some shows have experienced a drop-off in how many listeners stay through an entire episode, and leadership needs a prioritized list so the content team can focus revision efforts where they matter most.

Begin by consulting the YAML configuration file that specifies the baseline period, the current period, the retention-drop threshold expressed as a percentage, the maximum number of revision segments to surface per podcast, and the weights used to compute a composite priority score. A separate JSON file describes the normalization ranges for each scoring dimension and the exact output format, column ordering, sort key, tie-breaking rule, and number of decimal places. A third file provides per-genre demographic baseline distributions that represent the ideal audience composition, and a fourth JSON file maps each genre to an ad-rate adjustment multiplier used when estimating advertising revenue.

For every podcast in the catalogue, retrieve its episodes for both the baseline and the current period. For each episode, obtain the retention rate, which represents the proportion of initial listeners who remained through the end. Compute the average retention rate across all baseline-period episodes and across all current-period episodes for each podcast, then determine the percentage drop as the difference divided by the baseline average, multiplied by one hundred. Any podcast whose retention drop exceeds the threshold specified in the configuration is flagged for review.

Once you have the set of flagged podcasts, gather additional information for each one. First, query competitor show data for the flagged podcast's genre and compute the average retention rate across all competitors in that genre. The competitor gap equals the competitor average minus the podcast's current-period average retention, floored at zero. Second, retrieve the podcast's demographic breakdown for the current period. For each age group, compute the fraction of listeners it represents, then measure the total demographic shift as the sum of absolute differences between each age group's actual fraction and the corresponding genre baseline fraction from the demographic baseline file. Multiply that sum by one hundred to express it in percentage points. If the result exceeds the demographic-shift threshold in the configuration, the demographic shift flag is "yes"; otherwise it is "no". Third, estimate the advertising revenue impact. For each episode in both periods, retrieve its ad placements and its initial listener count, then for every ad compute revenue as the ad's CPM times the genre multiplier from the ad-rate adjustment file times the episode's initial listeners divided by one thousand. Average the per-episode totals within each period, and define the ad revenue impact as the baseline average minus the current average divided by the baseline average, clamped between zero and one.

With all four metrics in hand, normalize each one into the zero-to-one range using the min and max bounds from the scoring rubric file. Compute the priority score as the weighted sum of the normalized retention drop, competitor gap, demographic shift, and ad revenue impact, using the weights from the configuration, then multiply by one hundred and round to two decimal places.

Separately, identify the episode segments most in need of revision. The segment-level CSV batch files contain per-segment listener counts for every episode. For each flagged podcast's current-period episodes, calculate the within-segment drop rate as the difference between the segment's starting and ending listener counts divided by the starting count. Rank all such segments across the podcast's current-period episodes by drop rate in descending order and select the top segments up to the per-podcast maximum specified in the configuration. Format each selected segment as the episode number prefixed by "Ep", a colon, the segment index prefixed by "Seg", a hyphen, and the content type, for example "Ep4:Seg2-interview". Join multiple segments with "; " as the separator.

Save the final deliverable as `priority_report.csv`. It must contain exactly these columns in this order: `podcast_name`, `genre`, `retention_drop_pct`, `priority_score`, `flagged_episode_count`, `top_revision_segments`, `demographic_shift_flag`. The `retention_drop_pct` and `priority_score` columns must each show exactly two decimal places. Rows must be sorted by `priority_score` in descending order, with ties broken by `retention_drop_pct` in descending order. The `flagged_episode_count` is the number of current-period episodes for that podcast.

After saving the report, respond with a brief summary stating how many podcasts were flagged and listing the top entries by name, genre, retention drop percentage, and priority score.
