You are a UX analytics specialist responsible for a comprehensive conversion-bottleneck audit of an e-commerce platform. The platform tracks user sessions across every page in its journey, logging JavaScript errors, API timeouts, rendering failures, validation problems, and network issues. It also captures rage-click events — bursts of rapid, frustrated clicks — with precise viewport coordinates and click counts. A multi-step purchase funnel records which sessions enter and complete each stage, and several concurrent A/B tests assign users to control or treatment variants on specific pages. Your working directory contains configuration files that fully specify the scoring methodology, including a document that walks through each component of the priority formula, a YAML file with the numerical weights, normalisation caps, zone-type multipliers, and a confirmed-issue bonus, a JSON file mapping error severity levels to point values, a CSV defining heatmap zones with bounding-box coordinates and criticality classifications for every page, a CSV laying out the funnel steps in order together with target conversion rates, and a YAML file describing each A/B test along with its target page and variant labels. Read all of these carefully before proceeding, because they dictate every constant and rule you will need.

Your working directory also holds a collection of session-replay annotation files in JSON format. Each file covers a batch of sessions that were manually reviewed; within each annotation entry you may find a list of confirmed UX issues, each tied to a specific page. You must parse every one of these files and tally the number of confirmed issues per page, as that count feeds directly into the priority calculation.

Begin by listing all pages tracked by the platform through the available tools, then retrieve the full error log for every page. Each error carries a severity level; look up its weight from the severity configuration and, for each page, sum the products of individual error weights to obtain a raw error score. Separately, retrieve all rage-click events for every page. Each event includes x and y coordinates and a click count. For every click, check whether the coordinates fall inside any of the heatmap zones defined for that page — a match occurs when x_min is less than or equal to x_coord which is less than or equal to x_max, and likewise for y — and use the first matching zone. Multiply the click count by the zone-type weight from the priority configuration. If a click lands outside all defined zones, treat its zone weight as one. Sum these weighted counts across all events on the page to form a rage-click score.

Next, obtain the ordered list of funnel steps and query the aggregate funnel data for each one. Compute the abandonment rate for a step as one minus the ratio of completed sessions to entered sessions. Only pages that correspond to a funnel step carry a non-zero abandonment rate; every other page uses zero.

For A/B-test impact, consult the test-hypothesis configuration to learn which test targets which page, then retrieve the per-variant metrics for each test. On the target page, compute a problem rate for each variant by dividing the sum of that variant's error count and rage-click count by its session count. The A/B impact for the page equals the absolute difference of the two variants' problem rates. Pages not targeted by any test receive an A/B impact of zero.

Combine these five components — error score, rage-click score, abandonment rate, A/B impact, and confirmed-issue count — into a single priority score for every page, following the formula and normalisation rules laid out in the methodology document and the priority configuration file. Round the final priority score to two decimal places.

Save the backlog as `ux_backlog.csv` whose columns, in this exact order, are `page_name`, `error_score`, `rage_click_score`, `abandonment_rate`, `ab_impact_score`, `confirmed_issues`, `priority_score`, `recommended_action`. Format error_score and rage_click_score with two decimal places, abandonment_rate and ab_impact_score with four decimal places, confirmed_issues as an integer, and priority_score with two decimal places. The recommended_action column should hold a short text describing the primary fix suggested for the page based on whichever scoring component contributes most. Sort rows by priority_score in descending order.

Separately, produce a file named `funnel_report.json` containing a JSON object with a key `steps` whose value is a list of objects, one per funnel step in their defined order. Each object must include `step_name`, `page`, `total_entered`, `total_completed`, `abandonment_rate` rounded to four decimal places, `target_conversion_rate` taken from the funnel definition, and `conversion_rate` equal to one minus the abandonment rate, also rounded to four decimal places. Add a top-level key `overall_conversion_rate` equal to the last step's total_completed divided by the first step's total_entered, rounded to four decimal places.

In your final response, state the three pages that received the highest priority scores, giving each page name together with its priority score to two decimal places, and briefly note which scoring component is the largest contributor to each page's result.
