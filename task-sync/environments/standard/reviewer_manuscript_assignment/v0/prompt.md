You are working as a decision-support system for a journal editor who needs to assign peer reviewers to every pending manuscript in the current submission round. The goal is to produce a conflict-free, quality-aware, and expertise-matched reviewer assignment that covers the full queue. Every manuscript must receive exactly the number of reviewers specified in the assignment policy configuration, and every assignment must respect the constraints laid out across the various policy and guideline documents you will find alongside the data files.

Start by identifying all pending manuscripts and all available reviewers through the provided query tools. For each manuscript you will need its field, submission date, and page count; for each reviewer you will need their institutional affiliation and the maximum number of reviews they are willing to handle in a single round. Separately, you must retrieve the declared conflicts of interest for every manuscript as well as the historical review-quality and timeliness records for every reviewer. These pieces of information are only available through the query tools and cannot be found in any file.

Alongside those tool-based lookups, you will find several data files that carry complementary information. Batched CSV files whose names begin with "manuscript_keywords_batch_" list the subject-matter keywords associated with each manuscript, one keyword per row, with columns `manuscript_id` and `keyword`. JSON files whose names begin with "reviewer_expertise_" contain, for each reviewer, a dictionary with keys `name`, `expertise_fields`, and `expertise_keywords`. You must read every one of these files in full to build a complete picture of keyword coverage, because the keyword-to-manuscript and keyword-to-reviewer mappings are partitioned across multiple files and no single file contains the complete set.

A JSON configuration file describes the assignment policy: how many reviewers each manuscript should receive, the minimum average quality score a reviewer must have to be eligible, the method of assignment (greedy), and the sort and tiebreak keys for ordering manuscripts and reviewers. A YAML file describes the scoring rubric, specifying the three components of the pair score formula, their weights, their sources, and their respective scale factors. The pair score for a manuscript-reviewer pair is computed as the keyword-match weight multiplied by the Jaccard similarity of the manuscript's keyword set and the reviewer's expertise-keyword set multiplied by the keyword scale factor, plus the quality weight multiplied by the reviewer's average historical quality score multiplied by the quality scale factor, plus the timeliness weight multiplied by the reviewer's average historical timeliness score multiplied by the timeliness scale factor. The Jaccard similarity of two sets is the size of their intersection divided by the size of their union, treating an empty-versus-empty comparison as zero. A plain-text guidelines file explains how to break ties among reviewers with equal pair scores: prefer the reviewer who has been assigned fewer manuscripts so far in this round, and if those counts are also equal, prefer the reviewer whose identifier comes first in ascending alphabetical order. A Markdown file defines quality tiers and reinforces that any reviewer whose average historical quality score falls below the minimum threshold stated in the policy must be excluded entirely.

To build the assignment, process manuscripts in the order dictated by the policy: sort them by submission date ascending, breaking ties by manuscript identifier ascending. For each manuscript in that order, identify every eligible reviewer, which means a reviewer who has no declared conflict of interest with the manuscript, whose average historical quality score meets or exceeds the minimum threshold, and who still has remaining capacity in this round. Score each eligible reviewer using the pair-score formula above, sort them in descending order of pair score with the tiebreakers described in the guidelines, and assign the top reviewers up to the number required per manuscript. Deduct one from the assigned reviewer's remaining capacity immediately before moving to the next manuscript.

Once the full assignment is computed, save the result as `assignment_matrix.csv`. This file must contain exactly the columns `manuscript_id`, `reviewer_1`, `reviewer_2`, `reviewer_3`, and `assignment_score`, in that order. Each row corresponds to one manuscript, listed in the same order used during assignment (submission date ascending, manuscript identifier ascending). The `reviewer_1`, `reviewer_2`, and `reviewer_3` columns hold the reviewer identifiers of the assigned reviewers in the order they were selected (highest pair score first). The `assignment_score` column holds the sum of the individual pair scores of the assigned reviewers for that manuscript, rounded to exactly two decimal places.

After writing the file, state in your final response the total number of individual reviewer assignments made across all manuscripts, the average assignment score per manuscript rounded to two decimal places, and whether all manuscripts were fully assigned or, if not, which manuscript identifiers could not receive the full complement of reviewers.
