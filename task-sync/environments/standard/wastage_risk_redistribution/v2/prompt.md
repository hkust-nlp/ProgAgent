You are a blood-bank network coordinator responsible for preventing wastage across a regional system of blood centers. Today's date is 2026-04-22. Your network maintains a shared inventory of blood products — red blood cells, platelets, plasma, and cryoprecipitate — each with different shelf lives and handling requirements. Units that expire before they can be transfused represent both a financial loss and a missed opportunity to save lives, so your job is to identify every unit that is at serious risk of going to waste and recommend where each one should be redirected.

Begin by familiarizing yourself with the configuration files that govern how risk is assessed. A YAML policy document describes the scoring model: each unit within the defined risk horizon receives a composite score built from three weighted factors — proximity to expiration, the ratio of available supply to contracted weekly demand at the unit's home bank, and how many outbound transfers are already active for that bank-and-product combination. The policy specifies numeric brackets and weights for each factor, as well as a minimum composite score below which a unit is not considered at risk. A separate rules document in Markdown format explains special handling for platelets, how quarantine and reserved statuses affect scoring, and the exact output format you must produce. A JSON configuration file maps each bank to the set of partner banks it is eligible to transfer to, based on regional adjacency.

Once you understand the scoring model, work through every blood bank in the network. For each bank, retrieve the units approaching expiration within the policy's horizon window, pull the active hospital contracts to determine weekly demand by blood type and component, and check for any pending or in-transit outbound transfers. Combine this information to compute a risk score for each eligible unit following the policy's formula precisely. Remember to apply the platelet urgency bonus and the reserved-status reduction described in the handling rules, and to exclude quarantined units entirely.

After scoring, filter out any unit whose composite risk score falls below the policy's redistribution threshold. For each surviving unit, determine the best recipient bank: among the source bank's eligible transfer partners, find the one whose unmet demand — contracted weekly demand minus current available inventory — is greatest for that blood type and component combination. If no partner has positive unmet demand, mark the unit for discard rather than transfer.

Sort the final list in descending order of risk score. Where two units share the same score, break ties by ascending unit ID. Save the result as `redistribution_list.csv` with the following columns in this exact order: `unit_id`, `bank_id`, `blood_type`, `component_type`, `expiration_date`, `days_to_expiry`, `risk_score`, `suggested_recipient_bank`. Days to expiry is the integer number of days from today to the expiration date. Risk scores must be integers. The suggested recipient bank column should contain the bank ID of the recommended destination, or the literal string DISCARD if no partner has positive unmet demand.

When you have finished, state clearly in your response how many units appear on the redistribution list.
