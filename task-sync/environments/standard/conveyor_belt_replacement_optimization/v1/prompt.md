You are responsible for producing a validated maintenance calendar that schedules conveyor belt replacements across an industrial facility. The facility operates multiple production lines, each carrying several conveyor belts of different types, and each belt is monitored by IoT vibration sensors whose latest readings are available through the system. Historical component failure records are also stored in the system, and production schedules specify which lines run which shifts on which days, along with each shift's priority level. Separately, a set of inspection report files contains visual wear assessments performed by on-site technicians, and several configuration files lay out the maintenance policy, supplier contract terms, cost parameters, a planning horizon, and downtime cost rates.

A belt qualifies for replacement when at least one of three criteria is satisfied. First, the latest vibration reading's RMS velocity exceeds the warning threshold defined for that belt's type in the maintenance policy configuration. Second, the visual wear score recorded in the inspection reports meets or exceeds the wear threshold specified in the same policy file. Third, the belt's accumulated operating hours surpass the product of the average historical hours-to-failure for its belt type and the safety factor given in the policy. The average hours-to-failure must be computed from the historical lifespan records retrieved through the system for each belt type. Any belt meeting none of these criteria should be excluded entirely.

Once the set of belts requiring replacement has been identified, each must be assigned an urgency tier. A belt whose vibration RMS velocity exceeds the critical threshold for its type, as specified in the maintenance policy, receives the CRITICAL tier. A belt that is not critical but satisfies two or more of the three replacement criteria receives HIGH. A belt satisfying exactly one criterion receives MODERATE. These tier labels must appear exactly as written, in uppercase.

For each belt requiring replacement, a supplier must be selected. Retrieve all available suppliers for the belt's type from the system. For each supplier, compute an adjusted score equal to its unit cost multiplied by the quantity one minus its reliability rating divided by ten. Then consult the supplier contracts file for the list of preferred suppliers and the preferred discount multiplier; if a supplier appears on the preferred list, multiply its adjusted score by that multiplier. Select the supplier with the lowest adjusted score. If two suppliers tie, choose the one with the shorter lead time. If they still tie, choose the one whose supplier identifier comes first alphabetically.

The replacement date is determined by the planning reference date and supplier lead time. The planning horizon file states the reference date and the scheduling rule. The earliest possible date for any replacement is the reference date plus the selected supplier's lead time in days. For belts with CRITICAL urgency, the replacement date equals that earliest possible date regardless of production activity. For HIGH and MODERATE belts, the replacement date is the first day on or after the earliest possible date on which the belt's production line either has no scheduled production at all or has no shift whose priority level exceeds the maintenance priority threshold from the policy file. If no such maintenance-eligible day is found within the planning window specified in the planning horizon file, the replacement date falls back to the earliest possible date plus thirty days.

The estimated cost for each replacement equals the selected supplier's unit cost plus the labor cost for the belt's type as listed in the cost parameters file, rounded to two decimal places. The production impact score equals the sum of throughput units per hour across all scheduled shifts on the replacement date for the belt's production line, rounded to one decimal place; if no production is scheduled on that date, the score is zero.

Save the complete calendar as `maintenance_calendar.csv` with columns in this exact order: `belt_id`, `replacement_date`, `supplier_id`, `estimated_cost`, `urgency_tier`, `production_impact_score`. Rows must be sorted by replacement date in ascending order, and within the same date, by urgency tier in descending severity, so that CRITICAL appears before HIGH and HIGH before MODERATE. Every numeric value must appear without extra padding or units.

In your final response, state the total number of belts scheduled for replacement, the total estimated cost formatted to two decimal places, and the count of belts in each urgency tier.
