You are a senior case officer analyst working in a consular operations center. Your task is to conduct a comprehensive review of all active visa applications across every embassy in the system, identifying those that have become stalled and require urgent intervention due to their high-priority status.

Begin by reviewing the configuration files available to you. One of these files specifies the criteria that determine when an application is considered stalled, including thresholds for processing time relative to standard service-level agreements, biometric expiry windows, minimum counts of unresolved document flags, appointment wait-time limits, and quota utilization percentages. Another file defines the scoring methodology used to rank applications by intervention urgency, including base scores per visa category, multipliers tied to the applicant's priority level, modifiers for escalation levels and sponsor tiers, and bonuses or penalties for specific stall conditions. A third file provides the standard processing SLA in days for each visa category. You must use the exact thresholds, multipliers, and formulas from these files rather than inventing your own.

An application is considered to be in an active state if its current status is one of the following: pending, in review, on hold, or awaiting documents. For each such application, you must determine whether it is stalled by checking five conditions in turn. First, if any of the applicant's biometric submissions has a status of expired, or if any biometric record's expiry date falls within the warning window defined in the stall criteria relative to the reference date, the application is stalled due to biometric issues. Second, if the number of the applicant's document verification records carrying a status of flagged meets or exceeds the minimum flag count specified in the stall criteria, the application is stalled due to unresolved document flags. Third, if the number of days between the reference date and the applicant's submission date exceeds the product of the SLA for the applicant's visa category and the processing time threshold multiplier from the stall criteria, the application is stalled because it has exceeded its SLA. Fourth, if any of the applicant's embassy appointments has a status of pending or scheduled and a wait time in days exceeding the appointment wait threshold in the stall criteria, the application is stalled due to appointment backlog. Fifth, if the current-quarter quota utilization percentage for the applicant's visa category at their embassy meets or exceeds the critical utilization percentage from the stall criteria, the application is stalled due to quota pressure. The current quarter to use for quota lookups is Q2. An application is stalled if it triggers any one or more of these conditions.

Once stalled applications have been identified, you must filter for those that are also high-priority. An application qualifies as high-priority if any of the following hold: the applicant's priority level is critical or high, the applicant's escalation level as recorded in the case dossier files is three or greater, or the applicant's sponsor tier as recorded in the case dossier files is platinum. The case dossier files are distributed across multiple batch files in various formats, and each contains the escalation level, sponsor tier, special circumstances, and last officer contact date for a subset of applicants. You must read all of these batch files to obtain complete coverage.

For every stalled high-priority application, compute an intervention priority score using the scoring rules from the configuration. Start with the base score for the applicant's visa category, multiplied by the priority level multiplier corresponding to the applicant's priority level. Then add the base score times the escalation multiplier times the applicant's escalation level. Add the number of days since submission times the days-stalled factor. If the application is stalled due to quota pressure, add the quota pressure bonus. If stalled due to biometric issues, add the biometric expiry bonus. Add the document flag penalty times the total number of flagged documents for that applicant. Finally, add the sponsor tier bonus corresponding to the applicant's sponsor tier. Round the resulting score to two decimal places.

Determine the recommended action for each entry by consulting the stall reason priority order and action mapping in the scoring rules. Whichever stall reason appears earliest in the priority order among the reasons that apply to a given applicant determines their recommended action.

Produce a file called `intervention_list.csv` containing exactly the following columns in this order: `applicant_id`, `full_name`, `visa_category`, `embassy_id`, `priority_score`, `stall_reasons`, `recommended_action`, `days_stalled`. The stall reasons column must list all applicable stall reason codes separated by a semicolon and a space. Sort the rows by priority score in descending order, breaking ties by days stalled in descending order, and further ties by applicant ID in ascending lexicographic order.

After writing the file, provide a brief summary stating how many stalled high-priority applications were found and listing the top entries with their scores, stall reasons, and recommended actions.
