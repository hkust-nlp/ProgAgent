You are responsible for producing a dynamic pricing recommendation for a podcast advertising network. The network runs campaigns that place ads into podcast shows across geographic regions, and historical impression data has been accumulating for months. Leadership now wants a comprehensive pricing schedule that adjusts each show-region pair's CPM rate based on how well inventory is actually selling, where the listeners are concentrated, which advertiser category dominates the revenue, and what seasonal demand looks like for the upcoming quarter.

Start by reading the configuration and policy documents stored alongside the data files. One file lays out the pricing adjustment rules, including the fill rate tiers and their corresponding multipliers, the geographic concentration brackets and their multipliers, and the exact column names and sort order expected in the final deliverable. Another file specifies the seasonal demand multipliers for each quarter and identifies which quarter the new pricing should target. A third document explains the overall pricing formula, the definition of the adjustment percentage, the eligibility criteria for which show-region pairs to include, and how to determine the dominant advertiser category when multiple categories contribute revenue to the same pair. Read all of these carefully before proceeding, because they govern every calculation.

Once you understand the rules, gather the list of all active campaigns using the available tools. Active campaigns tell you which show-region pairs are currently being sold. For each show-region pair that has at least one active campaign, you need to compute the current CPM as the average base CPM across all active campaigns targeting that pair. You also need to retrieve impression statistics for every such pair, because only pairs that have at least one impression log entry qualify for the final schedule. Pairs that have active campaigns but no recorded impressions must be excluded entirely.

Separately, you need to determine the fill rate for each qualifying pair. The impression statistics tool returns the aggregated fill rate directly. Using the fill rate thresholds from the pricing rules file, look up the corresponding fill rate multiplier. The thresholds define non-overlapping ranges: a rate at the exact boundary belongs to the tier whose minimum matches it, and a rate of exactly one point zero belongs to the highest tier.

The geographic concentration factor requires reading the listener profile data files. These files contain each show's listener distribution across regions, expressed as a share between zero and one. For a given show-region pair, find the listener share for that region within that show's profile. If the region does not appear in the show's profile, treat the share as zero. Then map that share to the geographic concentration multiplier using the brackets in the pricing rules file, following the same boundary convention as the fill rate tiers.

To determine the category factor, first identify the dominant advertiser category for each show-region pair. The dominant category is the one whose campaigns generated the highest total revenue in the impression logs for that pair. A dedicated tool returns the revenue breakdown by category for any show-region combination. Once you know the dominant category, look up its demand index from the category benchmark files stored among the data files. If a category is not present in those benchmarks, use a demand index of one point zero.

Finally, apply the seasonal factor for the target quarter as specified in the seasonal configuration file.

The recommended CPM for each pair equals the current CPM multiplied by the fill rate multiplier, then by the geographic concentration multiplier, then by the category demand factor, then by the seasonal factor. The adjustment percentage is the relative change from the current CPM to the recommended CPM, expressed as a percentage. Both the recommended CPM and the adjustment percentage should be rounded to two decimal places.

Save the output as `pricing_schedule.csv`. It must contain exactly these columns in this order: `show_id`, `show_name`, `region_id`, `region_name`, `current_cpm`, `fill_rate`, `fill_rate_multiplier`, `geo_concentration`, `geo_multiplier`, `category`, `category_factor`, `seasonal_factor`, `recommended_cpm`, `adjustment_pct`. Sort the rows first by show identifier in ascending order, then by region identifier in ascending order. Every qualifying show-region pair must appear exactly once. You will need to retrieve show names and region names from the appropriate tools.
