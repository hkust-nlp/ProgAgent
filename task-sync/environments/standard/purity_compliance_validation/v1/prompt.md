You are responsible for completing a regulatory compliance review of all seed lots currently awaiting certification. Every lot with a status of "pending_review" must be evaluated against a comprehensive set of quality, traceability, and inspection criteria before a final determination can be made. The goal is to produce a compliance certificate for each lot that passes every check, and a rejection report documenting the specific reasons for each lot that fails.

Begin by identifying all seed lots that are pending review. For each such lot, you will need to retrieve its detailed information, including the crop type, variety, the parent lot from which it was derived, the field where it was harvested, and the harvest date. These details form the basis for every subsequent check.

Traceability must be established through the parent seed stock certificate. Retrieve the parent certificate using the parent lot identifier found in the lot details. The certificate must have a status of "valid" — any certificate that is "expired" or "revoked" disqualifies the lot. Furthermore, the certificate's expiry date must fall on or after the lot's harvest date, the crop type and variety on the certificate must exactly match those of the lot under review, and the parent generation must be among the valid parent generations specified for the crop type. The rules governing parent stock validation, as well as all other compliance criteria, are documented in a rules file you will find among the available files. A configuration file in YAML format provides the numeric thresholds for each crop type, including minimum germination rates, minimum purity percentages, maximum moisture percentages, maximum weed seed and other crop seed counts, maximum inert matter percentages, minimum vigor scores, and maximum acceptable harvest temperature and rainfall values.

Germination and purity testing data must be retrieved for each lot. When more than one test exists, use the most recent result based on the test date. Compare the germination rate, purity percentage, moisture percentage, weed seed count, other crop seed count, and inert matter percentage against the crop-specific thresholds from the configuration file. Any value outside its threshold constitutes a failure, and the specific reason must be recorded.

Separately, each lot's vigor score must be checked. Vigor scores are recorded in lab analysis report files stored as JSON. Locate the entry matching the lot identifier and compare its vigor score against the minimum vigor score threshold for the crop type. If no matching entry can be found, the lot fails the vigor criterion.

Field conditions at the time of harvest must also be verified. Field condition reports are stored as CSV files and are keyed by field identifier. Find the record for the lot's field and check that the recorded temperature did not exceed the crop's maximum harvest temperature and that the rainfall did not exceed the crop's maximum harvest rainfall. If no field condition record exists for the field, the lot fails this criterion.

Government inspection records must be retrieved for each lot. If multiple inspections exist, use the most recent one based on inspection date. Only lots whose most recent inspection has an overall result of "passed" satisfy this criterion. Results of "failed" or "conditional" are disqualifying, and the specific result must be noted in the rejection reasons.

Once all criteria have been evaluated, a lot that passes every single check receives a compliance certificate. The certificate number follows the format CERT-NNNN-YYYYMMDD, where NNNN is the numeric portion of the lot identifier (for example, "0015" from "LOT-0015") and YYYYMMDD is the certification date, which is 2025-12-01 for this entire batch.

Save the results for all accepted lots to a file named `compliance_certificates.csv`. This file must contain the columns `lot_id`, `crop_type`, `variety`, `certificate_number`, `certification_date`, and `status`, where the status value is "certified". Rows should be sorted by lot_id.

Save the results for all rejected lots to a file named `rejection_report.csv`. This file must contain the columns `lot_id`, `crop_type`, `variety`, `rejection_reasons`, and `status`, where the status value is "rejected" and the rejection_reasons field lists all failure reasons for that lot separated by "; " (semicolon followed by a space), with the individual reasons sorted alphabetically. Rows should be sorted by lot_id. The reason codes to use are: "parent_cert_status_expired" or "parent_cert_status_revoked" for invalid parent certificate status, "parent_cert_expired_before_harvest" when the certificate expired before the harvest date, "parent_crop_mismatch" and "parent_variety_mismatch" for mismatches between the parent certificate and the lot, "invalid_parent_generation" when the parent generation is not in the allowed set, "no_parent_certificate" if no certificate is found, "low_germination_rate", "low_purity", "high_moisture", "excess_weed_seeds", "excess_other_crop_seeds", "excess_inert_matter" for germination test failures, "low_vigor_score" and "no_vigor_score" for vigor issues, "harvest_temperature_exceeded" and "harvest_rainfall_exceeded" for field condition failures, "no_field_condition_data" if the field record is missing, "inspection_failed" or "inspection_conditional" for inspection result issues, and "no_inspection_record" if no inspection exists.

In your final response, state the total number of seed lots that were pending review, how many were certified, and how many were rejected.
