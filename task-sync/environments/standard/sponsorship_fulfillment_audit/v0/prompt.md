You are responsible for auditing sponsorship asset delivery across a portfolio of events. Every sponsor holds contractual entitlements specifying how many impressions they are owed per event, broken down by asset type: broadcast camera exposure, in-stadium digital signage, and social media monitoring. Your job is to reconcile what was promised against what was actually delivered, flag any shortfalls, and compute the appropriate billing adjustments.

Begin by collecting the full roster of events and sponsors from the available retrieval tools, paging through all results. For each event, retrieve the entitlements that apply, which will tell you the sponsor, the asset type, the contracted impression count, and the penalty rate percentage associated with that line item. You must process every single entitlement across every event.

For broadcast entitlements, pull the camera-angle log entries for the relevant event and sponsor, then sum the raw impression figures across all logged segments to obtain the total delivered broadcast impressions. For signage entitlements, retrieve the digital signage schedule records for that event and sponsor. Each record shows how many displays actually ran on a given screen. However, not all screens deliver equal value: a set of venue inspection report files provide a visibility factor for each screen at each venue, and you must multiply each screen's actual display count by its corresponding visibility factor before summing to get effective delivered signage impressions. If a screen does not appear in any venue report, treat its visibility factor as one. For social media entitlements, retrieve the feed entries for the event and sponsor. Each entry carries a raw impression count and a platform identifier. A platform weight table stored in a CSV file maps each platform to a numeric multiplier, and a verification policy document explains how verified versus unverified posts are counted. Separate social verification batch files list individual feed entry identifiers alongside a verified flag and an audit date. If a feed identifier appears in one of these batch files marked as verified, its impressions count at full platform-weighted value; if it appears as not verified, or if it does not appear in any batch file at all, its impressions count at fifty percent of the platform-weighted value. Effective social media impressions for each feed entry equal the raw impressions multiplied by the platform weight multiplied by the verification factor.

Once you have the delivered impressions for every entitlement, determine compliance. A compliance thresholds configuration file specifies the minimum delivery fraction required for each sponsor tier. Retrieve each sponsor's tier, look up the threshold, and compare the ratio of delivered to contracted impressions against it. If the ratio meets or exceeds the threshold, the entitlement is compliant; otherwise it is non-compliant.

For non-compliant entitlements, calculate the billing adjustment. The shortfall in impressions equals contracted minus delivered, but only when delivered is less than contracted. The shortfall percentage equals that shortfall divided by contracted times one hundred. A billing adjustment rates configuration file defines bands of shortfall percentage ranges, each carrying an adjustment multiplier. Find the band in which the shortfall percentage falls, and compute the billing adjustment as the shortfall impression count multiplied by the penalty rate percentage divided by one hundred multiplied by that band's adjustment multiplier. If the entitlement is compliant or has no shortfall, the billing adjustment is zero.

Save the complete results as `compliance_report.csv` with columns in this exact order: `entitlement_id`, `sponsor_name`, `sponsor_tier`, `event_name`, `asset_type`, `contracted_impressions`, `delivered_impressions`, `delivery_pct`, `compliant`, `shortfall_impressions`, `shortfall_pct`, `billing_adjustment`. The `delivery_pct` column should express the percentage as a number such as 87.5 rather than a decimal fraction. The `compliant` column should read `True` or `False`. All numeric values should be rounded to two decimal places where applicable. Include one row per entitlement, covering every entitlement in the system.

In your final response, state the total number of entitlements evaluated, the count of non-compliant entitlements, and the total billing adjustment summed across all entitlements, formatted to two decimal places.
