You are a manufacturing quality analyst responsible for identifying systemic defects across a multi-line production facility. The facility operates several assembly lines, each equipped with a specific machine type and continuously monitored by sensors. Components arrive from various suppliers in tracked batches, and every finished product undergoes a final inspection. When an inspection fails, the associated photograph is analyzed to determine a root cause indicator that classifies the underlying problem as supplier-related, machine-related, or operator-related.

Your objective is to determine which suppliers require a formal rework program and which assembly lines require sensor recalibration, then produce a single prioritized corrective action list covering both categories. The rules, thresholds, formulas, and output format specifications you need are all defined in configuration files available alongside the data. Three configuration files govern the analysis: one defines the acceptable sensor reading ranges for every combination of machine type and sensor type, another maps root cause indicators from photo analysis to defect categories and specifies which categories are actionable, and a third contains the severity formulas, weight parameters, penalty rules, trigger thresholds, and required output format templates.

Begin by reviewing those configuration files to understand the precise definitions and formulas. A sensor reading is considered anomalous when it falls strictly outside the minimum-to-maximum range given in the calibration specifications for the corresponding machine type and sensor type. For each assembly line, retrieve all of its sensor readings and compute the anomaly rate separately for each sensor type as the number of anomalous readings divided by the total number of readings for that sensor type, expressed as a percentage. If any sensor type on a given line exceeds the anomaly rate threshold from the configuration, that line requires a machine recalibration action. Record the sensor type with the highest anomaly rate as the primary sensor, and use that highest rate as the basis for severity calculation.

Separately, retrieve the batch delivery records for every supplier and compute the incoming defect rate as the sum of all rejected quantities divided by the sum of all delivered quantities across that supplier's batches, expressed as a percentage. If a supplier's defect rate exceeds the threshold specified in the configuration, that supplier requires a rework action. Among that supplier's component types, identify the one with the highest ratio of rejected to delivered quantities as the primary component.

Once you have identified the lines and suppliers that exceed their respective thresholds, compute severity scores using the exact formulas in the configuration. For a supplier rework action, multiply the defect rate percentage by the defect rate weight, then add the audit penalty. The audit penalty equals the maximum of zero and the difference between the audit penalty threshold and the supplier's average audit score, that difference then multiplied by the audit penalty weight. Average audit scores are computed from all entries for that supplier found in the delivery report files. For a machine recalibration action, multiply the line's highest anomaly rate percentage by the anomaly rate weight, then add the drift penalty. The drift penalty equals the maximum drift ratio recorded for the line's primary sensor type across all calibration check files, multiplied by the drift penalty weight. Round every severity score to the decimal precision specified in the configuration.

To determine the number of affected products for each corrective action, examine all failed inspections and cross-reference them with the photo analysis records. Each failed inspection references a component batch, and through that batch you can identify the originating supplier. Each photo analysis record provides a root cause indicator. Using the defect severity rules, classify each failure into one of the defined categories. The affected product count for a supplier rework action is the total number of failed inspections attributed to the supplier category whose component batches trace back to that supplier. The affected product count for a machine recalibration action is the total number of failed inspections attributed to the machine category that occurred on that assembly line.

Rank all corrective actions in descending order of severity score. Where two actions share the same severity score, place the one with the lexicographically smaller entity identifier first. Save the complete list as `corrective_actions.csv` with columns in this exact order: `rank`, `action_type`, `entity_id`, `root_cause`, `severity_score`, `affected_products`, `recommended_action`. The `action_type` column contains either `supplier_rework` or `machine_recalibration`. Format the `root_cause` and `recommended_action` fields according to the templates in the action priority configuration file, substituting the computed values into the placeholders.

Conclude your response by listing every corrective action, stating for each the rank, entity identifier, action type, and severity score.
