You are working as a data analyst for a municipal waste-collection authority that needs to resolve a backlog of resident complaints about missed trash pickups. The authority operates a fleet of trucks across several service zones, each zone assigned a dedicated truck and specific collection days of the week. Residents subscribe to one of several service tiers, and the contractual terms governing response times, proximity thresholds, and compensation amounts differ by tier. Your goal is to determine which pending complaints represent genuinely missed pickups that warrant a financial credit, classify each validated miss, compute the correct refund amount, and produce a final deliverable file.

Start by familiarizing yourself with the configuration and policy documents available to you. A JSON file describes zone boundaries, including each zone's identifier, its assigned truck, and the weekdays on which collection is scheduled. A YAML file spells out the service-level agreement parameters for every tier, such as the proximity threshold in metres that a truck must come within, the minimum stop duration in seconds that counts as a valid service attempt, and a list of exception codes that may excuse a missed pickup when advance notice was provided. A CSV file contains the compensation rate schedule with the base credit for each tier, the rate applied to a full miss versus a partial miss, and a multiplier for repeat misses. Finally, a markdown document lays out the full eligibility and calculation rules; read it carefully, because every step of the evaluation logic is described there.

Once you understand the rules, retrieve all service requests that are classified as missed-pickup complaints still awaiting review. For every such request, look up the resident's information to learn their zone, service tier, geographic coordinates, and bin identifier. Confirm that the scheduled pickup date actually falls on one of the zone's designated collection days; if it does not, the complaint is not eligible.

Next, check the daily route log files. There is one log per operational day, in CSV format, recording each zone's truck activity for that date, including whether an exception occurred and whether advance notice was given. If the log shows that the resident's zone on the scheduled date had an excused exception, that complaint is not eligible for compensation either.

For each remaining complaint, you must verify the miss through sensor data. Query the GPS truck-stop records for the zone's assigned truck on the scheduled date and calculate whether any recorded stop falls within the proximity threshold of the resident's address and meets the minimum stop-duration requirement. Also query the bin-lift sensor logs for the resident's bin on that date to see whether a successful lift was recorded. If a valid GPS stop exists near the address with sufficient duration and the bin was successfully lifted, the complaint is invalid and should be skipped. If the truck stopped nearby but the bin lift was unsuccessful or absent, classify the miss as a partial miss. If no qualifying GPS stop is found near the address and no successful bin lift is recorded, classify it as a full miss. In the unusual case where a GPS stop does not qualify yet a successful bin lift was still recorded, treat the complaint as invalid since the service was ultimately rendered.

With the miss type determined, calculate the credit. Take the base credit for the resident's tier from the rate schedule. Multiply it by the full-miss rate or partial-miss rate as appropriate. Then determine whether this is a repeat miss: if the same resident has at least one other missed-pickup request that has already been resolved, and whose scheduled pickup date falls within the thirty calendar days preceding the current request's scheduled pickup date, apply the repeat-miss multiplier. Round the resulting credit to two decimal places.

After processing every pending complaint, save the validated results to a file called `refund_list.csv`. This file must contain a header row followed by one row per validated refund, with columns in exactly this order: `request_id`, `resident_id`, `resident_name`, `zone_id`, `service_tier`, `scheduled_pickup_date`, `miss_type`, `base_credit`, `final_credit`. Use the exact string `full_miss` or `partial_miss` for the `miss_type` column. Sort all rows by `request_id` in ascending order. Format `base_credit` and `final_credit` as numbers with exactly two decimal places.

In your final response, state the total number of validated refund entries and the total credit amount as a sum of all `final_credit` values, formatted to two decimal places.
