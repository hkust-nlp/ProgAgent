You are a catastrophe reinsurance analyst responsible for monitoring aggregate treaty exhaustion across the company's entire portfolio of active reinsurance treaties. The book contains treaties of three distinct types: Aggregate Excess of Loss contracts, Industry Loss Warranty contracts, and Catastrophe Excess of Loss contracts. Each treaty has an attachment point and a limit denominated in US dollars, but the underlying loss amounts reported by cedents may be in different currencies. Your job is to determine, for every active treaty, how much of its limit has been consumed by catastrophe losses and how much coverage remains.

Begin by reading the YAML file that maps each treaty identifier to its structural terms, including the treaty type, the USD attachment point, the USD limit, and, for Catastrophe Excess of Loss treaties only, a per-occurrence retention threshold in USD. Separately, load the JSON file that provides the industry-loss-index trigger threshold for every Industry Loss Warranty treaty; these thresholds are expressed in billions of USD. You will also need the CSV file containing loss development factors, which maps each development stage label to a numeric multiplier, and the JSON file that provides currency-to-USD conversion rates for every currency in the portfolio. Finally, read the plain-text file listing event identifiers that are currently under dispute; every line that is not a comment represents a disputed event, and all loss records associated with disputed events must be excluded from every treaty calculation.

For each treaty, retrieve the full set of cedent loss advices using the available retrieval tool. Multiple advices may exist for the same treaty-event pair, distinguished by an advice sequence number; only the advice with the highest sequence number for a given treaty-event combination is authoritative. Once you have identified the authoritative advice for each event, look up its development stage in the cedent bulletin CSV files found alongside the configuration files. Each bulletin covers a batch of advice identifiers and provides the development stage for that advice. Multiply the gross loss amount from the authoritative advice by the loss development factor that corresponds to its development stage to obtain the developed gross loss in the cedent's local currency, then convert that figure to USD using the currency conversion rate for the treaty's currency.

Separately, retrieve the inuring reinsurance recoveries for each treaty. Sum all recovery amounts per event and convert the total to USD using the same treaty currency rate. For each event, the net developed loss in USD equals the developed gross loss in USD minus the inuring recovery in USD, floored at zero.

After computing per-event net developed losses, apply the treaty-type-specific qualification filter. For Aggregate Excess of Loss treaties, every non-disputed event qualifies. For Industry Loss Warranty treaties, retrieve the industry loss index for each event and include only those events whose index value in billions of USD meets or exceeds the trigger threshold specified for that treaty. For Catastrophe Excess of Loss treaties, include only events whose individual net developed loss in USD meets or exceeds the per-occurrence retention threshold specified in the treaty terms.

Once qualifying events are identified, sum their net developed losses to obtain the aggregate qualified net loss. The erosion of the treaty limit equals the lesser of two quantities: the aggregate qualified net loss minus the attachment (floored at zero), or the treaty limit itself. The remaining limit is the treaty limit minus the erosion. The exhaustion percentage is the erosion divided by the limit, multiplied by one hundred and rounded to two decimal places. Assign a status label of EXHAUSTED when the remaining limit is zero or less, PARTIALLY_ERODED when the erosion is positive but less than the full limit, and ACTIVE when the erosion is zero.

Save the results as `treaty_dashboard.csv` with the following columns in this exact order: `treaty_id`, `treaty_name`, `treaty_type`, `currency`, `attachment_usd`, `limit_usd`, `gross_incurred_usd`, `inuring_recoveries_usd`, `net_incurred_usd`, `erosion_usd`, `remaining_limit_usd`, `exhaustion_pct`, `status`. Each row represents one treaty. The `gross_incurred_usd` column is the sum of developed gross losses in USD across every non-disputed event for the treaty (before any qualification filter is applied), and `inuring_recoveries_usd` is the corresponding sum of inuring recoveries in USD across those same events; `net_incurred_usd` is `gross_incurred_usd` minus `inuring_recoveries_usd`. The qualification filter is used only when computing `erosion_usd`, `remaining_limit_usd`, `exhaustion_pct`, and `status`. All USD monetary amounts must be rounded to two decimal places. The rows should be ordered by treaty identifier in ascending lexicographic order. In your final response, state how many treaties fall into each status category using the exact format: "X treaties EXHAUSTED, Y PARTIALLY_ERODED, Z ACTIVE" where X, Y, and Z are integers.
