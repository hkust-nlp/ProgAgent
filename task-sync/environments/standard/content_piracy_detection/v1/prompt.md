You are an anti-piracy analyst for a large online education platform. The platform offers lecture content gated by subscription tiers — free, basic, premium, and enterprise — and the mapping of which tiers grant access to which content levels is documented in a JSON configuration file you will find alongside your other reference materials. A YAML policy file specifies the numerical weights assigned to each piracy signal, the multipliers applied based on the content's access tier, the score thresholds that separate priority levels, the corresponding enforcement actions, and the minimum score below which a lecture should not appear on the takedown list at all. A supplementary severity guide further explains how these weights and multipliers interact. Read and internalize every parameter from these configuration files before proceeding, because the scoring formula and classification logic must follow them exactly.

Your primary data sources for identifying pirated content are two kinds of files. The first kind is a set of JSON scan reports produced by external monitoring services; each report contains an array of findings, and every finding includes a content fingerprint and the external URL where the material was discovered. The second kind is a set of plaintext DMCA complaint files, each containing one or more structured notices that specify a content hash, the infringing URL, and other metadata. Collect every content fingerprint and every associated external URL from both sources. Note that some fingerprints in the scan reports are false positives that will not match any lecture in the platform's catalogue — simply discard those after attempting the lookup.

For each fingerprint you have gathered, use the available lookup tool to find the corresponding lecture by its content hash. Once you have identified a pirated lecture, retrieve its full record to determine its access tier, duration, course association, and title. Then retrieve the parent course record so you can include the course title in your output.

Separately, load the IP watchlists — CSV files listing IP addresses flagged by the security team. Every IP that appears in any of these files is considered suspicious regardless of the threat level or source noted alongside it.

For every confirmed pirated lecture, pull its complete access-log history from the platform. For each access-log entry, look up the accessing student's subscription tier and check it against the tier-access rules you loaded earlier. An access is unauthorized when the student's subscription tier does not list the lecture's access tier among the tiers it is permitted to view. Count the total number of such unauthorized access events for the lecture. While inspecting access logs, also note every IP address that appears on the watchlist; collect the set of unique watchlist IPs seen across both the access logs and the download records for that lecture.

Once you have the three raw signal counts for a lecture — the number of unique external URLs referencing its fingerprint, the number of unauthorized access events, and the number of unique watchlist IP addresses found in its logs and downloads — compute the piracy score. Multiply each signal count by its respective weight from the policy file, sum the products, and then multiply the total by the tier multiplier corresponding to the lecture's access tier. Round the result to two decimal places. If the piracy score falls below the minimum threshold specified in the policy, exclude the lecture from the final list.

Classify every remaining lecture into a priority level using the threshold brackets in the policy: a score at or above the critical threshold is critical, a score at or above the high threshold but below critical is high, and anything at or above the medium threshold but below high is medium. Map each priority level to its recommended enforcement action as specified in the policy.

Produce a file called `takedown_list.csv` containing one row per pirated lecture that meets the score threshold. The file must have the following columns in this exact order: `rank`, `lecture_id`, `lecture_title`, `course_title`, `access_tier`, `piracy_score`, `priority_level`, `num_external_sources`, `external_urls`, `unauthorized_access_count`, `watchlist_ip_hits`, `recommended_action`. The `piracy_score` column should display the value to two decimal places. The `external_urls` column should contain all unique external URLs for that lecture joined by semicolons, sorted alphabetically. Sort the rows by piracy score in descending order; break ties by lecture identifier in ascending order. Number the ranks starting from one.

In your final response, include exactly these four summary lines, each on its own line, with the integer counts filled in: "Total pirated lectures requiring action: N", "Critical priority: N", "High priority: N", "Medium priority: N".
