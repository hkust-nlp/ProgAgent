You have been engaged by a retail buyer to perform a full organic certification compliance verification on an incoming batch of avocados. A batch manifest is available among your reference materials as a JSON file; it lists every processor lot code included in the shipment together with the expected delivery date, the buyer name, and the batch identifier. Your objective is to trace each lot back to its originating farm and evaluate compliance across four dimensions: pesticide history, soil quality, audit certification, and physical lot inspection.

Start by reading the batch manifest to identify the lot codes and the delivery date. For each lot code, use the lot-lookup tool to retrieve the processor lot record, which will give you the originating farm identifier and the declared shipment weight. Then, for every unique farm represented in the batch, gather farm details through the farm-query tool so you have the farm name on record.

For pesticide compliance, consult the organic standards configuration (provided as a YAML file among your reference materials) to determine the lookback period in months and the list of banned substances and banned categories. Counting backward from the delivery date by that many months (use thirty days per month) gives you the lookback start date. Retrieve pesticide application records for each farm for every calendar year that overlaps with the lookback window. If any application dated on or after the lookback start date involves a chemical whose name appears on the banned-substances list or whose category matches a banned category, the farm fails the pesticide check and every lot sourced from that farm is non-compliant on this dimension.

For soil quality, retrieve the soil test records for each farm and examine only the most recent test (by sample date, breaking ties by the highest test identifier). The test values must satisfy all thresholds given in the organic standards configuration: pH must fall between the minimum and maximum, lead must not exceed its limit, cadmium must not exceed its limit, and organic matter percentage must meet or exceed the minimum. Separately, the laboratory that performed the test must appear in the approved-laboratories registry, which is available as a CSV file in your reference materials. If the soil values are out of range the lot fails the soil-quality check; if the lab is not in the approved list the lot fails the lab-accreditation check. These are evaluated independently.

For audit certification, retrieve the audit certificate records for each farm and consider only the most recent certificate (by audit date, breaking ties by the highest certificate identifier). The certificate status must be among the valid statuses listed in the organic standards, and its expiry date must not be earlier than the batch delivery date. A certificate that is expired or carries a non-valid status causes the farm to fail the audit check.

For lot inspection, locate the physical inspection report file for each lot among your reference materials. These files are named with the lot code and contain measured weight, temperature, and defect rate data. Compare the measured weight against the declared weight from the lot record: if the absolute percentage difference exceeds the weight-tolerance percentage in the organic standards, the lot fails. If the recorded temperature exceeds the maximum allowed, the lot fails. If the defect rate exceeds the maximum allowed, the lot fails. Each of these is an independent inspection failure.

A lot is considered COMPLIANT only when it passes every one of the five checks: pesticide status, soil status, lab accreditation, audit status, and inspection status. If any check fails the lot is NON_COMPLIANT. For each failing check, record the applicable failure phrase from this exact set: "banned pesticide in lookback period", "soil quality threshold exceeded", "testing lab not accredited", "audit certificate invalid or expired", "storage temperature exceeded limit", "weight discrepancy beyond tolerance", "defect rate exceeded limit". Multiple failure phrases for a single lot are joined with "; " as separator. A lot that passes everything has the failure-reasons value "None".

Once analysis is complete, save a file called `compliance_report.csv` containing exactly one row per lot, sorted by lot code in ascending order. The columns must appear in this exact order: `lot_code`, `farm_id`, `farm_name`, `pesticide_status`, `soil_status`, `lab_accredited`, `audit_status`, `inspection_status`, `overall_status`, `failure_reasons`. Each of the five status columns contains either `PASS` or `FAIL`. The `overall_status` column contains `COMPLIANT` or `NON_COMPLIANT`.

Separately, save a file called `compliance_summary.json` containing an object with these keys: `batch_id` (from the manifest), `delivery_date`, `total_lots` (integer count of lots evaluated), `compliant_lots` (integer count), `non_compliant_lots` (integer count), `batch_status` which is `APPROVED` if every lot is compliant or `REJECTED` otherwise, and `non_compliant_lot_codes` which is a list of lot codes that are non-compliant sorted in ascending order.

In your final response, clearly state the overall batch status and list every non-compliant lot along with its failure reasons.
