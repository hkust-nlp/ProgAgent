You are a sports-science analyst responsible for identifying athletes who are at elevated risk of overtraining syndrome. Your organization tracks every athlete through four complementary data streams: daily wellness surveys, GPS-based training load telemetry, wearable sleep trackers, and historical injury records. None of these sources alone is sufficient to assess risk; a meaningful evaluation requires synthesizing information across all of them together with configuration parameters stored in several reference files.

Begin by consulting the configuration files that govern the analysis. A YAML file called `risk_thresholds.yaml` specifies the reference date on which the analysis is anchored, the number of days in the analysis window, the injury lookback period, and the minimum composite fatigue score thresholds that map to each risk level along with the rest protocol assigned to that level. A JSON file called `fatigue_weights.json` provides the decimal weights used to combine the four fatigue sub-components into a single composite score. A CSV file called `body_region_multipliers.csv` lists each anatomical region and its numeric multiplier, which scales the severity of injuries located in that region. Finally, a Markdown file called `rest_protocols.md` describes the clinical details of each protocol, though it is the YAML thresholds file that dictates which protocol is assigned to which risk tier.

The composite fatigue score for each athlete is assembled from four sub-components. The first, the wellness component, is calculated by retrieving each athlete's daily wellness survey data within the analysis window, computing the average of all five survey dimensions (fatigue rating, mood rating, soreness rating, stress rating, and sleep quality rating) on each day, averaging those daily averages across the window, and subtracting the result from ten. If no wellness data exists for an athlete, use a default value of five for this component.

The second sub-component, the training component, reflects the acute-to-chronic workload ratio. Acute load equals the sum of all session loads plus all GPS player loads that fall within the analysis window, where each session load is the product of its RPE score and its session duration in minutes; session-level data can be found in the daily training session CSV files stored alongside the other reference files. Chronic load equals the total of all session loads plus GPS player loads across every available day, divided by the number of weeks that span covers (total days divided by seven). The ratio of acute to chronic load is then multiplied by three point five and capped at ten. If no training data exists, use five as the default. Note that session files each cover a single calendar day and may contain multiple entries per athlete when an athlete trained more than once that day; every such entry must be summed. GPS player load for the same athlete and date range must be retrieved through the available query tools and combined with session loads before computing the ratio.

The third sub-component, the sleep component, is derived from sleep tracker records within the analysis window. For each recorded night, compute a deficit as the greater of zero and eight minus total sleep hours, plus the number of awakenings multiplied by zero point five, plus the greater of zero and eighty-five minus sleep efficiency multiplied by zero point one. Average these daily deficits across the window and cap the result at ten. Default to three if no records are found.

The fourth sub-component, the injury component, examines every injury that occurred within the injury lookback period ending on the reference date. For each such injury, determine a recency factor of one if the injury occurred within the last thirty days, zero point five if it occurred between thirty-one and sixty days ago, or zero point two five if it occurred between sixty-one and ninety days ago. Multiply the injury's severity by the body-region multiplier from the multipliers file and by the recency factor; sum these products across all qualifying injuries for the athlete and cap the total at ten. Athletes with no injuries receive zero for this component.

The composite fatigue score is the weighted sum of the four components using the weights from the weights file, rounded to two decimal places. Classify each athlete according to the risk thresholds: compare the score against the critical threshold first, then high, then moderate; the first threshold met or exceeded determines the risk level, and all athletes below the moderate threshold are classified as low risk.

Team membership information, needed for the final output, is recorded in a roster CSV file called `team_roster.csv` that maps each athlete identifier to a team name. This file is the sole source of team assignments.

Once all athletes have been scored and classified, produce two deliverables. The first is a CSV file named `rest_protocol_list.csv` containing only those athletes whose risk level is moderate, high, or critical. It must have exactly these columns in this order: `athlete_id`, `athlete_name`, `team`, `fatigue_score`, `risk_level`, `protocol`, `priority_rank`. Rows must be sorted by fatigue score in descending order, with ties broken by ascending athlete identifier. The priority rank column is an integer starting at one for the highest-risk athlete and incrementing sequentially through the list. Fatigue scores must appear exactly as computed, rounded to two decimal places.

The second deliverable is a JSON file named `risk_summary.json` containing an object with the keys `total_athletes_analyzed` (the count of all athletes regardless of risk level), `critical_count`, `high_count`, `moderate_count`, `low_count` (each an integer count of athletes in that tier), and `flagged_athletes` (a list of athlete identifiers for those at moderate risk or above, ordered by their priority rank).

After saving both files, state in your final response the total number of flagged athletes, the names and fatigue scores of the three highest-risk athletes, and the per-tier counts for critical, high, moderate, and low risk.
