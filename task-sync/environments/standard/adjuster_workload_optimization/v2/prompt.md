You are an operations analyst at a large insurance company responsible for producing the daily adjuster assignment schedule. Every morning a batch of pending claims must be matched to available independent adjusters so that the expected average settlement time across the portfolio is minimized. The matching process draws on several sources of information that you will need to pull together before making any decisions.

Start by reviewing the configuration files that govern the assignment logic. A YAML policy file specifies the four scoring weights (proficiency, proximity, capacity, and history), key numeric parameters such as the maximum allowable travel hours, maximum settlement days used for normalization, the minimum proficiency threshold an adjuster must meet, and the default settlement days assumed when no historical record exists. It also lists three bonus modifiers: a same-region bonus, an urgency multiplier, and a platinum bonus. A separate plain-text rules file explains, in precise prose, how the base score is assembled from its four weighted components, in what order the bonuses and multipliers are layered on top, and how ties and processing order are resolved. A JSON file defines severity tiers by mapping contiguous score ranges to tier names, and a CSV file maps each severity tier to the minimum certification level an adjuster must hold to handle claims in that tier.

Beyond the configuration, you will find supplementary claim data spread across a set of CSV files. Each row pairs a claim identifier with two fields: a priority flag (urgent, normal, or low) and a customer tier (platinum, gold, silver, or bronze). Current adjuster workloads are captured in a collection of JSON snapshot files, each listing adjuster identifiers alongside the number of active cases they are presently carrying. Finally, a set of YAML zone files maps every territory to its geographic region, which is needed to evaluate the same-region bonus.

Use the available tools to retrieve the full list of pending claims, the roster of active adjusters, each adjuster's specialty proficiency scores, their historical settlement performance per claim type, and travel times from claim territories to adjuster base territories. None of this information is available in the files, and none of the file-based data is available through the tools, so you must consult both.

With all data in hand, process the pending claims in the order dictated by the rules file. For each claim, determine its severity tier, identify every adjuster who satisfies every eligibility gate (active status, certification level, proficiency threshold, travel-time ceiling, and positive remaining capacity after accounting for both current active cases and any claims already assigned earlier in this same batch), compute each eligible adjuster's final assignment score following the layered formula (base weighted sum, then region bonus, then urgency multiplier, then platinum bonus, rounding to four decimal places), and assign the claim to the adjuster with the highest score, breaking ties by the lowest adjuster identifier.

Once every pending claim has been processed, save the result as `daily_assignment_schedule.csv`. This file must contain exactly the columns `claim_id`, `adjuster_id`, `adjuster_name`, `claim_type`, `severity_score`, `severity_tier`, `assignment_score`, `priority_flag`, and `estimated_settlement_days`, in that order. The assignment score column must show values rounded to four decimal places. The estimated settlement days value should reflect the adjuster's historical average for the relevant claim type, or the default settlement days from the policy when no history exists, rounded to one decimal place. Rows should appear in the order claims were processed (highest severity first).

In your final response, state the total number of claims that were assigned, the average assignment score across all assignments rounded to four decimal places, and whether any claims could not be assigned. If there are unassigned claims, list every such claim identifier. If all claims were assigned, explicitly note that zero claims were left unassigned.
