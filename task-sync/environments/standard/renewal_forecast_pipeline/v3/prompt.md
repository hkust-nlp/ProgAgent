Your organization manages a portfolio of SaaS platform subscriptions across dozens of client accounts, and leadership needs a prioritized renewal forecast for the upcoming quarter. The goal is to identify every contract set to expire in that window, assess the risk profile of each renewal, and produce a pipeline that tells account managers exactly which contracts need attention and what kind of action to take.

Begin by locating the configuration files that govern this analysis. A YAML configuration file specifies the target quarter's start and end dates, the five scoring components and their weights, and the normalization rules for each component. A JSON policy file defines per-tier thresholds that map a computed risk score to one of four action categories: auto_renew, standard_renewal, manager_review, or executive_escalation. A CSV schedule file lists the maximum discount percentage available for each combination of client tier and annual contract value range. Read and understand all three before proceeding.

Once you know the target quarter boundaries, retrieve every contract whose expiration date falls within that range. For each such contract, collect the full contract details and the associated client record, paying attention to the client's tier since it governs both the action thresholds and the discount caps. Gather the monthly usage metrics for each contract as well; these span a six-month window and you will need the average number of active users across the first three months and the last three months to compute the usage decline percentage. A positive decline means users dropped off; the normalization rule in the configuration converts that percentage into a zero-to-one-hundred component score. If usage actually grew, the decline percentage is zero.

Separately, pull the stakeholder feedback entries for each client. The sentiment risk component is the share of feedback entries marked negative out of all entries for that client, scaled to a zero-to-one-hundred range. If a client has no feedback on file, treat the sentiment risk score as fifty.

Three families of files in subdirectories contain information that is not available through any tool call and is equally essential. JSON batch files hold a strategic importance rating on a one-to-ten scale for every client; multiply by ten to get the component score. CSV files in another subdirectory record a competitor threat level on the same one-to-ten scale for every contract; again, multiply by ten. Markdown brief files capture a negotiation difficulty rating, also one-to-ten and scaled the same way, for every contract. You must read all of these files and match the values back to the contracts under analysis.

With all five component scores in hand, compute the weighted risk score for each contract using the weights from the YAML configuration. Round to two decimal places. Higher scores indicate greater risk and therefore higher renewal priority.

Using the risk score and the client's tier, look up the action thresholds in the JSON policy file. A score below the auto_renew ceiling means the contract can be auto-renewed; a score at or above the executive escalation floor triggers an escalation; the two middle bands map to standard_renewal and manager_review respectively.

For the projected discount, find the row in the CSV discount schedule whose tier and value range bracket the contract's annual value, then multiply the maximum discount percentage by the ratio of the risk score to one hundred. Round the result to two decimal places.

Also compute a usage trend percentage for each contract, defined as the percentage change from the average active users in the first three months to the average in the last three months, with a positive value meaning growth and a negative value meaning decline. Round to two decimal places.

After computing all fields, rank the contracts by risk score from highest to lowest. If two contracts share the same risk score, break the tie by sorting their contract identifiers in ascending alphabetical order. Assign integer priority ranks starting at one for the highest-risk contract.

Save the full results as `renewal_forecast.csv` with exactly these columns in this order: `contract_id`, `client_name`, `platform`, `expiry_date`, `annual_value`, `usage_trend_pct`, `sentiment_score`, `risk_score`, `priority_rank`, `recommended_action`, `projected_discount_pct`. Rows must be sorted by priority rank ascending. Numeric fields for annual_value, usage_trend_pct, sentiment_score, risk_score, and projected_discount_pct should appear as plain decimal numbers rounded to two decimal places.

In your final response, present a summary of the five highest-priority renewals. For each one, state its rank, the client name, the platform, the contract identifier, the risk score, and the recommended action. Also state the total number of contracts expiring in the target quarter.
