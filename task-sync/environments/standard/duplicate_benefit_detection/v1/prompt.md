You are tasked with conducting a comprehensive duplicate detection sweep across all benefit applications currently in the system. The goal is to identify pairs of applicants who may represent the same individual or household applying multiple times, which creates a risk of overpayment across public assistance programs. Your analysis must cross-reference applicant identity records, household composition data, identity documents, and income verification submissions to produce a single consolidated list of flagged cases for manual review.

Begin by reading the detection rules configuration file, which specifies which types of duplicates to search for, the confidence score assigned to each type, the thresholds that govern matching criteria, and the recommended action for each type. Every enabled rule in that configuration must be applied. The configuration also specifies the exact output format, column names, sort order, and formatting conventions you must follow when producing the final deliverable.

For each detection rule that is enabled, you must systematically examine all applicants in the system. To detect cases where two applicants share the same Social Security Number, retrieve the full roster of applicants and compare their SSN fields. To detect cases where two applicants share the same first name, last name, and date of birth but carry different SSNs, compare those identity fields across the full roster. For household overlap detection, retrieve the household member records for every applicant and identify pairs of applicants whose households contain shared members, where a shared member is defined as one whose SSN appears in both households; the minimum number of shared members required to trigger a flag is specified in the detection rules. For identity document matching, read all identity document verification files and look for cases where two different applicants presented documents bearing the same document number. For the address-and-income rule, find pairs of applicants residing at the same address who have both applied for at least one common program; then consult the employer-verified income reports to obtain each applicant's income figures, and determine whether the maximum reported income for each applicant falls within the percentage tolerance specified in the detection rules.

Once you have identified all duplicate pairs, you must determine which benefit programs are affected by each pair. For every flagged pair, retrieve the application records for both applicants and compile the set of programs to which both have submitted applications. The affected programs should be listed alphabetically, separated by semicolons.

After completing the detection sweep, save the results as `flagged_cases.csv`. This file must contain the columns `case_id`, `applicant_id_1`, `applicant_id_2`, `duplicate_type`, `confidence_score`, `programs_affected`, and `recommended_action`, in that exact order. Each row represents one flagged pair. The applicant with the lower ID must appear as `applicant_id_1`. Rows must be sorted by confidence score in descending order; where confidence scores are tied, sort by `applicant_id_1` ascending, then by `applicant_id_2` ascending. Case IDs must follow the pattern CASE-001, CASE-002, and so on, zero-padded to three digits and assigned sequentially after sorting. Confidence scores must be formatted to two decimal places. The recommended action for each case is determined by the duplicate type, as defined in the detection rules.

In your final response, provide a summary stating the total number of flagged cases and a breakdown by duplicate type showing how many cases were detected for each type.
