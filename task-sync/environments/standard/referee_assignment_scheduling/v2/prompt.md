You are tasked with producing a complete weekly referee assignment roster for an upcoming round of fixtures spanning Monday through Sunday. Every fixture scheduled for this period must have exactly one referee assigned to it, and the assignment must satisfy all governing constraints without exception. The fixtures, referee registrations, certification records, and historical conflict data are all accessible through the provided tools, while referee availability schedules, travel distance information, and the binding assignment policy reside in the files you have been given.

Begin by reading the policy configuration file, which is in YAML format, to understand the maximum allowable travel distance in kilometers, the precise order in which fixtures are to be processed during assignment, the tie-breaking criteria when multiple referees are equally eligible, the conflict policy distinguishing active from inactive records, and the rule that prevents a referee from being assigned to more than one fixture in the same day-and-time-slot combination. Separately, consult the JSON file that maps each match type to the minimum certification level a referee must hold in order to officiate that kind of match. The travel distance matrix, stored as a CSV, gives the distances in kilometers between every pair of cities relevant to the scheduling region, and you will need it to verify that a referee's home city is within the permitted range of the fixture's venue city. A plain-text scheduling notes file and a markdown output specification document together describe the exact output deliverable, the column schema, the sort order, and what to do when no eligible referee can be found.

Only referees who have an availability file on record should be considered part of the active pool for the week. Each such file, stored as JSON inside the availability subdirectory, details which days and which time slots that referee is free. Referees without a corresponding file are to be treated as entirely unavailable regardless of any other data. For every referee in the available pool, you must retrieve their profile information using the tools so that you know their home city, experience in years, and the maximum number of assignments they may accept in a single week. You must also retrieve each available referee's full set of certifications and any conflict history. Certifications specify the match type and the level attained, which should be compared numerically against the minimum required level for each fixture's match type. Conflict records include both active and inactive entries; only active conflicts disqualify a referee from officiating a fixture involving the flagged team.

Fixtures should be retrieved through the paginated fixture listing tool. For each fixture you will need the venue and both teams, obtainable through the respective lookup tools, so that you can determine the venue's city for the travel check and the team identifiers for the conflict check.

The assignment algorithm is strictly greedy: process fixtures in the order prescribed by the policy, and for each fixture, evaluate every referee in the available pool against the full set of constraints. A referee is eligible only if they have not yet reached their personal weekly assignment cap, are not already assigned to another fixture in the same day-and-time-slot combination, are listed as available on that day and in that time slot according to their availability file, hold a certification for the fixture's match type at or above the required level, have no active conflict with either the home team or the away team, and are located within the maximum travel distance of the venue city. From among the eligible referees, select the one who ranks highest under the tie-breaking criteria defined in the policy. If no referee qualifies, the fixture is left unassigned using the sentinel values described in the scheduling notes.

Once every fixture has been processed, save the result as `roster.csv`. The file must contain exactly the columns specified in the output format document, in the exact order listed there, with rows sorted by fixture_id in ascending order. No index column should be included. In your final response, state the total number of fixtures, how many were successfully assigned, and how many remain unassigned.
