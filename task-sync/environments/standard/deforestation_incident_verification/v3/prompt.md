You are tasked with producing a verified incident dossier that documents every confirmed case of illegal deforestation across the monitored territory. This dossier will serve as the primary evidentiary package for regulatory enforcement action, so accuracy and completeness are paramount. The analysis draws on satellite imagery change detection records accessible through available query tools, ground-truth field inspection reports stored as JSON files, species survey data stored as CSV files, and several policy and reference documents that govern how violations are classified.

Begin by identifying all satellite change detection events whose change type matches one of the types of interest listed in the policy configuration file (a YAML document containing thresholds and classification rules). Only events with a confidence score at or above the confidence threshold specified in that same policy file should be considered. Once you have assembled this initial set of candidate events, cross-reference each one against the field inspection reports. These reports are distributed across multiple JSON files and record a verification status for individual change identifiers. Any event explicitly marked with a verification status of "false_positive" by a field inspector must be excluded entirely. Events marked "confirmed" are considered field-verified, while events marked "inconclusive" or those lacking any inspection record are still included but are not considered field-verified.

For every remaining candidate event, you must determine whether the activity was legally permitted. Query the logging concession records for the parcel associated with each event. A concession is considered valid for a given detection date if the concession's granted date falls on or before the detection date, the expiry date falls on or after the detection date, and the concession status is neither "suspended" nor "revoked." If no concession record exists at all for a parcel, that constitutes a "no_permit" violation. If concession records exist but none satisfy the validity criteria at the time of detection, it constitutes an "expired_permit" violation. If a valid concession does exist, compare the event's affected area in hectares against the concession's permitted hectares, inflated by the area tolerance percentage from the policy file. When the affected area exceeds this adjusted permitted limit, the violation is classified as "area_exceeded."

Separately, assess each candidate event for conservation impact. Query the conservation reports for the parcel and determine whether any report designates the parcel with a conservation priority at or above the minimum level specified in the policy file and simultaneously records a biodiversity index at or above the corresponding threshold in that file. If such a report exists, check the species survey CSV files to determine whether any species observed at that parcel appears in the protected species registry (a JSON file listing protected species with their IUCN status). When both conditions are met, the event qualifies as a "conservation_violation."

Each event may trigger multiple violation conditions. Assign exactly one violation type to each incident, selecting the one whose severity tier ranks highest according to the severity reference file (a CSV document that maps each tier to a priority order, recommended action, and response deadline). If an event triggers no violation conditions whatsoever, it represents legal activity and must be excluded from the dossier.

For ownership attribution, query the land ownership registry for each incident's parcel, retrieving the current owner's name and type.

Compile all verified incidents into a file named `incident_dossier.csv` with the following columns in this exact order: `incident_id`, `change_id`, `parcel_id`, `owner_name`, `owner_type`, `detection_date`, `change_type`, `affected_area_hectares`, `violation_type`, `severity_tier`, `field_verified`, `recommended_action`. The `incident_id` column must contain sequentially assigned identifiers in the format INC-0001, INC-0002, and so forth, assigned after sorting. The `field_verified` column should be True if the corresponding field inspection confirmed the event and False otherwise. The `recommended_action` column should contain the action string from the severity reference file matching the incident's tier. Rows must be sorted first by severity tier in descending order of severity (the tier with priority order 1 comes first), and within the same tier by affected area in hectares from largest to smallest.

Once the dossier is complete, produce a summary document named `enforcement_summary.md` containing the total number of incidents, a breakdown of incident counts by severity tier, a breakdown by violation type, and the total affected area across all incidents rounded to two decimal places.

In your final response, state the total number of verified illegal deforestation incidents, the total affected area in hectares to two decimal places, the number of CRITICAL-severity incidents, and the parcel identifier associated with the single largest affected area among all incidents.
