The property management company has received a batch of rental applications that require comprehensive risk assessment before any approvals can be processed. Each applicant's risk profile must be evaluated across four dimensions: creditworthiness, income adequacy relative to the rent they would owe, any history of evictions, and the quality of references from previous landlords. The final deliverable is a prioritized review queue containing every applicant whose computed risk score meets or exceeds the designated review threshold defined in the risk configuration, sorted so the most concerning cases appear first.

To assess creditworthiness, retrieve each applicant's credit report and compute a credit risk sub-score. Start by taking the difference between the configured base threshold and the applicant's credit score; if this difference is negative, treat it as zero. Divide that difference by the configured score range, then multiply by one hundred to get the base credit risk value. Add the configured bankruptcy penalty if a bankruptcy filing is present. Add the per-item delinquency penalty for each delinquent account, up to the configured maximum delinquency penalty. Add the high-utilization penalty whenever credit utilization exceeds the configured high-utilization threshold. Cap the resulting credit sub-score at one hundred.

For income adequacy, determine each applicant's total monthly income by summing their base monthly income and any additional income sources documented in the financial records on file. Divide that total by the monthly rent of the property to which they applied, using the rental listing data available in the provided files. If the resulting ratio equals or exceeds the configured minimum ratio, the income sub-score is zero. Otherwise the sub-score equals the difference between the minimum ratio and the actual ratio, divided by the minimum ratio, then multiplied by one hundred, and capped at one hundred.

Eviction history is evaluated by retrieving each applicant's eviction records and applying the severity weight assigned to each eviction's reason category as defined in the severity classification data on file. If an eviction occurred within the configured recency window measured in years from the reference date specified in the risk configuration, multiply its severity weight by the configured recency multiplier. Sum all the weighted values, multiply the total by the configured base scale factor, and cap the result at one hundred to obtain the eviction sub-score.

Landlord reference assessment begins by retrieving all references on file for each applicant, then filtering to include only those references whose verification status is confirmed as verified in the reference verification records on file. For every verified reference, compute the mean of its three rating dimensions: payment timeliness, property care, and lease compliance. Average those means across all verified references to get a single aggregate rating. The reference sub-score is calculated as five minus that aggregate rating, divided by five, then multiplied by sixty. Add the configured penalty for each verified reference whose rental recommendation is negative, and add the configured uncertain-recommendation penalty for each verified reference whose recommendation is uncertain. Cap the total at one hundred. When an applicant has no verified references at all, assign the configured default score for missing references as the reference sub-score.

Combine the four sub-scores into a single risk score by multiplying each by its respective weight from the configuration and summing the products. Round the risk score to two decimal places. Assign a risk tier to each applicant according to the tier thresholds in the configuration: the tier whose lower bound the score meets or exceeds, choosing the highest qualifying tier.

Every applicant whose risk score meets or exceeds the review threshold belongs in the output queue. Save the queue as `review_queue.csv` with the following columns in this exact order: `applicant_id`, `full_name`, `risk_score`, `risk_tier`, `primary_flag`, `credit_score`, `income_to_rent_ratio`, `eviction_count`, `avg_reference_rating`. The `full_name` field concatenates first and last name separated by a single space. The `primary_flag` field names whichever of the four component sub-scores contributed the highest value for that applicant, using the labels `credit`, `income_ratio`, `eviction`, or `references`; break ties alphabetically. The `income_to_rent_ratio` should be rounded to two decimal places. The `avg_reference_rating` is the aggregate rating used in the reference sub-score computation, rounded to two decimal places; if no verified references exist, record it as `N/A`. Sort the file by `risk_score` descending; where scores are identical, sort by `applicant_id` ascending.

Once the file is written, provide a concluding summary stating the total number of applicants screened, the number placed into the review queue, the count of applicants in each risk tier across the entire applicant pool, and the full name and risk score of the single highest-risk applicant.
