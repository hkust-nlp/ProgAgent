The communications team needs a comprehensive brand reputation monitoring report that aggregates signals from multiple channels and produces a prioritised alert queue. Your task is to analyse every brand under monitoring by evaluating four distinct signal categories, then combine these signals into a unified severity score that determines which brands require immediate attention.

Begin by gathering the complete list of monitored brands. For each brand you will need to determine its assigned monitoring tier, which can be found in the brand tier assignment files stored alongside the data. These tier designations drive a multiplication factor that amplifies or dampens the final severity score for each brand, as specified in the priority configuration file.

The first signal to evaluate is social media volume anomaly. Retrieve each brand's recent daily social media mention counts across all tracked platforms. For each day, sum the mention counts across platforms to obtain a daily total, then compute the average daily total over the monitoring window. Compare this average against the brand's historical baseline statistics, which are provided in the baseline reference files. The anomaly is measured as a z-score: subtract the historical mean from the current average and divide by the historical standard deviation. Only positive z-scores contribute to the signal; if the current average falls at or below the baseline, the social anomaly value is zero.

The second signal is news headline sentiment. For each brand, retrieve all associated headlines from the monitoring period. Using the sentiment lexicon provided in the configuration files, count how many headlines contain at least one negative keyword, and separately count how many contain at least one critical keyword. A headline that matches any critical keyword should be counted only as critical, not also as negative. The headline risk for a brand is computed as the number of negative headlines plus twice the number of critical headlines, divided by the total number of headlines for that brand. If a brand has no headlines the headline risk is zero.

The third signal is support ticket sentiment. For each brand, retrieve all support tickets and examine the full content of each ticket by combining its subject line and body text. Classify a ticket as negative if the combined text contains any negative keyword from the sentiment lexicon. The base ticket negativity ratio is the fraction of tickets classified as negative out of the total ticket count for that brand. This base ratio must then be adjusted by the severity override assigned to that brand in the analyst ticket notes files, which provide an overall severity assessment for each brand's ticket trends. The override categories map to multipliers specified in the priority configuration under severity override multipliers. Multiply the base ratio by the appropriate override multiplier to get the final ticket negativity value.

The fourth signal is executive communications risk. For each brand, retrieve all executive communications and identify the spokesperson for each. Cross-reference these spokespersons against the executive watchlist files, which specify which executives at each brand are under elevated scrutiny and include a risk assessment level for that brand. If any communication is authored by a watched executive and its detailed content contains at least one crisis keyword from the sentiment lexicon, the executive risk flag for that brand is set to one; otherwise it is zero. The executive communications raw score is the risk flag multiplied by the risk assessment multiplier from the priority configuration.

To combine these four signals into a final severity score, apply the following procedure. Each signal has a raw value: the social anomaly z-score clamped to zero at the lower end, the headline risk fraction, the adjusted ticket negativity value, and the executive communications raw score. Multiply each raw value by its corresponding scaling factor found in the priority configuration to bring signals to a common scale. Then multiply each scaled value by the weight assigned to that signal category in the priority configuration. Sum these four weighted components. Finally, multiply the sum by the tier multiplier corresponding to the brand's monitoring tier as found in the priority configuration. Round the result to two decimal places to produce the brand's final severity score.

Any brand whose final severity score meets or exceeds the alert threshold specified in the priority configuration should be included in the output alert queue. The queue must be sorted in descending order of severity score, with ties broken by ascending brand identifier.

Save the alert queue as `alert_queue.csv` with the following columns in this exact order: `rank`, `brand_id`, `brand_name`, `monitoring_tier`, `severity_score`, `social_zscore`, `headline_risk`, `ticket_negativity`, `exec_risk_flag`. The rank column should be an integer starting at one, severity_score and social_zscore should be rounded to two decimal places, headline_risk and ticket_negativity should be rounded to four decimal places, and exec_risk_flag should be zero or one.

Separately, save a summary as `brand_risk_summary.json` containing a JSON object with two keys: `total_alerts` holding the integer count of alerts, and `alerts` holding the list of alert records in priority order where each record includes the fields brand_id, brand_name, monitoring_tier, severity_score, social_zscore, headline_risk, ticket_negativity, and exec_risk_flag.

In your final response, state the total number of alerts in the format "Total alerts: N" and list all alerted brand names in priority order separated by commas on a line beginning with "Priority order: ".
