Your organization is struggling with a growing backlog of unfilled positions. Several job requisitions have remained open well past their expected fill dates, and leadership wants a data-driven triage of where to focus recruiting resources. The reference date for all age calculations is April 15, 2026.

Begin by retrieving the full list of departments and then querying all open requisitions across every department. For each open requisition, compute how many calendar days it has been open as of the reference date. A requisition is flagged for intervention only when its age in days strictly exceeds the department-specific threshold defined in the department thresholds configuration file stored alongside the data files you have access to. That configuration file maps each department name to several threshold values; the relevant one here is the days-open flag.

Once you have the set of flagged requisitions, you need to determine which bottleneck types apply to each one. There are five possible bottleneck categories, and their definitions, conditions, and severity weights are documented in a JSON classification file available in the same directory as the thresholds. A separate plain-text file describes how to compute the overall priority score for each flagged requisition from a base component and additive modifiers tied to those bottleneck severity weights.

To evaluate each bottleneck for a given requisition, gather the following information. Retrieve the full list of candidate applications for the requisition through the available tools. Also retrieve the recruiter assignment history and all hiring-manager feedback entries. Additionally, read the weekly pipeline snapshot files that reside alongside the configuration files; each snapshot covers one week and records, for every requisition, the number of new applications received that week along with per-stage candidate counts. You will also need the pipeline stages reference file, which lists each stage name together with the expected number of days a candidate should spend in that stage.

The first bottleneck, low application flow, is triggered when the average number of new weekly applications across all available weekly snapshots falls below the department-specific minimum weekly application rate from the thresholds file. The second, high stage stagnation, fires when more than forty percent of the requisition's currently active candidates (those in the applied, phone screen, technical interview, onsite interview, or offer extended stages) have been in the pipeline longer than the expected duration defined for their current stage. To check this, compare each active candidate's total days since application date against the expected days for their current stage listed in the pipeline stages file. The third bottleneck, low feedback scores, applies when the mean of all hiring-manager feedback scores recorded for that requisition falls below the department minimum acceptable feedback score. The fourth, recruiter instability, triggers when the number of completed recruiter reassignments (assignments that have an unassignment date) exceeds the department maximum allowed recruiter changes. The fifth, feedback delay, is flagged when fewer than half of the candidates who have reached the onsite interview stage or beyond (onsite interview, offer extended, or hired) have received at least one piece of hiring-manager feedback.

For each flagged requisition compute a priority score. The base score equals the number of days open divided by ten, rounded down to the nearest integer, capped at ten. Then add the severity weight of every bottleneck that applies; those weights are specified in the bottleneck classification file. The bottlenecks should be evaluated in the fixed order listed above. The first triggered bottleneck becomes the primary bottleneck, the second triggered becomes the secondary bottleneck, and if none trigger, record both as "none".

Compile all flagged requisitions into a CSV file named `priority_intervention_list.csv` saved alongside the data files. The file must contain exactly these columns in this order: `requisition_id`, `title`, `department`, `days_open`, `priority_score`, `primary_bottleneck`, `secondary_bottleneck`. Sort all rows by priority score in descending order; break ties by requisition ID in ascending order.

After writing the file, respond with a brief summary stating the total number of flagged requisitions and the requisition ID of the single highest-priority entry.
