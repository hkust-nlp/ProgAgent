Your organization operates a shared mobility network spanning several districts, with stations offering bikes, scooters, and e-bikes. Leadership has requested a thorough evaluation of station performance to identify those that should be considered for decommissioning or relocation to areas with higher demand. This assessment must synthesize data from multiple sources, combining file-based records with information retrieved through available tools, to produce a definitive ranked list of underperforming stations.

Begin by reviewing the reference documents available to you. A YAML configuration file describes the scoring methodology in detail, including the weights assigned to each of four performance dimensions, the normalization parameters and caps used for each component, the hourly cost rate applied to equipment downtime, and the precise formulas for computing component scores and the overall composite score. A separate JSON criteria document specifies the eligibility requirements that determine which stations should be evaluated, the rules that distinguish between a decommission and a relocation recommendation, and the exact structure and format of the output deliverable. Familiarize yourself thoroughly with both documents before proceeding with any calculations.

Several data files contain station-level information organized across different formats. CSV files hold monthly ridership records for each station, with chronological entries showing total rides and unique user counts. JSON files present survey results quantifying the number and types of points of interest located near each station within a defined radius. Plain-text summary files report complaint volumes at each station, broken down by category, and indicate how many complaints remain unresolved. YAML files document maintenance activity, listing incident counts and cumulative equipment downtime hours by issue type for each station. Each of these sources covers a distinct aspect of station health, and all must be consulted to assemble the complete performance picture.

In addition to file-based data, you have access to tools that supply information not found in the documents. One tool provides a paginated listing of all stations with their district assignments, types, capacities, installation dates, and operational statuses. Another returns the financial cost breakdown of maintenance activities for a given station, including total expenditure, average cost per incident, and per-issue-type cost totals. A third reports complaint severity statistics for a given station, including the distribution of severity ratings across a one-to-five scale and a weighted severity score computed as the sum of all individual severity values. The financial cost data is available exclusively through the maintenance tool, and the severity-weighted score is available exclusively through the complaint tool, so both must be queried for every station under evaluation.

To carry out the assessment, first determine which stations are eligible by applying the operational tenure requirement specified in the criteria document. Then, for each eligible station, compute four component scores following the formulas laid out in the scoring configuration. The usage decline component compares average ridership in the earliest three months of data against the latest three months. The maintenance burden component combines the total financial cost obtained through the maintenance tool with total downtime hours found in the maintenance notes files, valuing each downtime hour at the rate specified in the configuration. The complaint index multiplies the tool-reported weighted severity score by an adjustment factor of one plus the ratio of unresolved complaints to total complaints, where total complaints and unresolved counts come from the summary text files. The point-of-interest sparsity component reflects how few nearby amenities surround the station, measured against the maximum defined in the configuration. Each component is normalized to a zero-to-one-hundred scale using the caps from the configuration, then combined using the stated weights to produce a composite score rounded to exactly two decimal places.

A station qualifies as a relocation or decommissioning candidate when its composite score meets or exceeds the minimum threshold defined in the criteria. Among those candidates, any station whose nearby point-of-interest count falls at or below the critical threshold and whose usage decline percentage strictly exceeds the severe decline threshold should be recommended for decommissioning. All remaining candidates should be recommended for relocation.

Save the final output as `relocation_candidates.csv` containing the columns `rank`, `station_id`, `station_name`, `district`, `composite_score`, and `recommendation`, in exactly that order. Rows must be sorted by composite score in descending order, with ties in composite score broken by station identifier in ascending order. The rank column should reflect this ordering starting from one. Composite scores must be written with exactly two decimal places. The recommendation column must contain either `DECOMMISSION` or `RELOCATE` in uppercase letters.

Once the file has been written, respond with a summary stating the total number of candidate stations identified, how many are recommended for decommissioning versus relocation, and the station identifier and name of the top five candidates ranked by composite score.
