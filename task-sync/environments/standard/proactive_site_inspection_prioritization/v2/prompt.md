You are assisting a municipal building safety division that needs to generate a weekly prioritized inspection list for construction sites. The goal is to identify which active construction projects pose the greatest risk and should be inspected first, based on a composite risk score derived from multiple data sources.

Begin by locating and reading the configuration file that defines the scoring parameters for this task. It contains the risk component weights, severity multipliers, project value tier definitions, risk tier boundaries, penalty values for license issues, and various scoring constants you will need throughout the process. There is also a policy document that describes the full methodology for computing each component score, assigning risk tiers, handling license penalties, determining primary risk factors, and establishing the final sort order. Read both of these documents carefully before proceeding, as they govern every calculation you will make.

The permits you must evaluate are those with a status of "active" or "pending_review". Use the available search tools to retrieve all such permits, handling pagination as necessary to capture every qualifying record. For each qualifying permit, you will need to gather information from several sources. Query the contractor associated with the permit to obtain their license expiry date and other details. Then retrieve that contractor's full violation history. Also obtain the zone information for the permit's zone, and search for all complaints filed against that permit.

In addition to the tool-based queries, you must read several collections of files that contain data not available through the tools. A CSV overlay file provides four hazard metrics for each zone: flood risk, seismic factor, environmental sensitivity, and infrastructure proximity. Separate batches of site survey files contain structural, safety, and environmental scores for each surveyed permit. Detailed complaint report files in JSON format include an escalation flag for each complaint that affects the complaint severity calculation. Finally, contractor audit report files in text format contain a safety audit score for each audited contractor, which feeds into the contractor reliability component.

Once you have gathered all data, compute the six component risk scores for each qualifying permit following the methodology described in the policy document. The violation history score aggregates per-violation contributions using the base score, severity multiplier, unresolved multiplier, and recency bonus, capped at the configured maximum. The zone hazard score is the simple average of the four hazard metrics from the overlay file. The complaint severity score aggregates per-complaint contributions using the base score, severity multiplier, and escalated complaint bonus where applicable, again capped at the configured maximum. The project scale score maps the permit's project value to the matching tier. The contractor reliability risk score equals one hundred minus the safety audit score from the audit files, defaulting to fifty when no audit data exists for that contractor. The site condition risk score equals one hundred minus the average of the three survey scores, defaulting to fifty when no survey data exists for that permit.

Combine these six components using the configured weights to produce a weighted sum. Then apply license penalties: if the contractor's license has expired relative to the reference date defined in the configuration, add the expired license penalty; otherwise, if the license expires within the configured window of days from that reference date, add the expiring license penalty. Cap the final risk score at one hundred and round it to two decimal places.

Assign each permit a risk tier based on where its final score falls within the configured tier boundaries, where the lower bound is inclusive and the upper bound is exclusive, except for the highest tier where one hundred is included. Determine the two primary risk factors by identifying the two components whose weighted contributions (weight multiplied by component score) are largest, listed in descending order of that weighted value, separated by a semicolon and a space, using the exact component key names from the configuration.

Sort the complete list by risk score in descending order. Break ties by submission date in ascending order, with earlier submissions ranked higher. Break any remaining ties by permit ID in ascending lexicographic order. Assign sequential integer ranks starting from one.

Save the final output as `inspection_priority_list.csv` with columns in this exact order: `rank`, `permit_id`, `site_address`, `contractor_name`, `risk_score`, `risk_tier`, `primary_risk_factors`. Every qualifying permit must appear in this file.

In your final response, present the five highest-risk sites from the list, including for each one its permit ID, site address, contractor name, risk score, risk tier, and primary risk factors.
