You are tasked with conducting a comprehensive duty-time compliance audit and fatigue risk assessment for an airline's pilot roster covering the month of January 2025. The airline maintains records of crew pairings, actual flight logs, and pilot rest declarations in its operational database, accessible through the provided query tools. Separately, historical duty-hour records from December 2024 have been archived into a set of CSV files stored in a directory called prior_hours, and these must be consulted when calculating rolling cumulative limits that extend back into the prior month. Schedule amendments that modify the originally planned release times of certain pairings have also been issued and are stored as JSON files in a directory called amendments; each amendment record specifies a pairing code and its revised release time, and these adjusted times must be used in place of the original values whenever they exist.

All regulatory parameters governing this audit are contained in configuration files. A YAML file named regulatory_limits.yaml specifies the maximum allowable flight duty period depending on when the duty begins: duties starting between 05:00 and 06:59 are classified as early starts, those starting between 07:00 and 13:59 are normal, and all others fall under the late-start category, each with its own hour cap. The same file defines the minimum rest period between consecutive duties, the maximum cumulative duty hours permitted in any rolling seven-day and twenty-eight-day window, and the fatigue risk score threshold above which a pilot is considered at elevated risk. A JSON file named duty_type_rules.json indicates, for each duty type, whether that type counts toward the flight duty period check and what multiplier to apply when accumulating hours toward rolling limits. Only duty types flagged as counting toward the flight duty period should be evaluated for FDP violations, but all types contribute to cumulative totals according to their respective multipliers.

To determine whether a pilot's rest between consecutive duties is adequate, sort that pilot's pairings chronologically by report time and measure the gap in hours between each pairing's release time and the next pairing's report time, using amended release times where applicable. Any gap that is positive yet falls below the regulatory minimum constitutes an insufficient-rest violation.

For the rolling seven-day and twenty-eight-day checks, compute each pilot's daily duty hours by summing the duration of every pairing whose report time falls on that calendar day, multiplied by the duty-type cumulative multiplier, then for every day in January evaluate the total across the preceding seven and twenty-eight days respectively, including December records from the prior-hours files. If either total exceeds its regulatory cap, record the single worst-excess day per pilot per limit type as a violation.

Severity classification for each violation type is governed by a YAML file called severity_thresholds.yaml. For FDP violations, the excess hours determine severity: values at or above the HIGH threshold are HIGH, at or above MEDIUM are MEDIUM, and anything less is LOW. For rest violations, it is the actual rest hours that are compared against descending thresholds: rest below the HIGH figure is HIGH, below MEDIUM is MEDIUM, and otherwise LOW. Cumulative violations follow the same excess-based logic as FDP.

Once violations are identified, compute a fatigue risk score for every pilot who had at least one pairing in January. The scoring model is defined in fatigue_risk_weights.json, which provides five component weights that sum to one, penalty tables for time-of-day effects keyed by hour ranges, a rest-quality baseline, a maximum consecutive-early-start count for full penalty, and a reference sector count per week. For each pilot, derive the time-of-day component by averaging the penalty value corresponding to each pairing's report hour, then scaling to a 0–100 range. The cumulative-hours component is the ratio of the pilot's highest seven-day rolling total to the regulatory seven-day limit, expressed as a percentage capped at one hundred. The rest-quality component uses the average self-reported quality from that pilot's rest declarations relative to the baseline: specifically, the baseline minus the average, divided by the baseline, times one hundred, floored at zero. The consecutive-early-starts component counts the longest run of chronologically adjacent pairings whose report hour is before seven, divided by the configured maximum, capped at one, and multiplied by one hundred. The sectors component takes the maximum number of flight-log entries in any seven-day window during January divided by the reference count, capped at one, and multiplied by one hundred. Each component is multiplied by its weight and the products summed, with the total capped at one hundred. Pilots whose score exceeds the configured threshold plus ten are CRITICAL, those above the threshold are HIGH, those above sixty are MODERATE, and all others are LOW. Only pilots at MODERATE level or above should appear in the fatigue output, and each entry should note the primary contributing factor, which is the component with the largest weighted contribution.
