A fleet of gas turbines is approaching a scheduled overhaul window, and before any outage work can begin the operations team needs a thorough regulatory compliance assessment. Your job is to determine, for every turbine currently flagged with a "scheduled_overhaul" status, whether it meets emission limits, has the necessary spare parts on hand, and can be serviced by properly certified technicians. The final output is a compliance checklist and a gap report, both saved as CSV files.

Start by reading the configuration files that govern this analysis. A YAML file named `compliance_rules.yaml` contains the evaluation parameters: an emission evaluation window defined by a reference date and a lookback period in days, a tolerance threshold for how many exceedances trigger non-compliance, severity classification rules for exceedance percentages, minimum stock multipliers for parts, the date through which technician certifications must remain valid, and whether higher certification levels satisfy lower-level requirements. A JSON file called `overhaul_policy.json` specifies the exact column names and sort orders for the two output files, as well as the allowed status values. A markdown document called `certification_requirements.md` explains how technician qualifications are matched against task requirements.

For each scheduled-overhaul turbine, begin with the emission compliance check. Retrieve the permits associated with the turbine's site to find the regulatory limit for each pollutant. Then pull that turbine's emission logs and filter them to the evaluation window (from the reference date back by the number of days specified in the rules). Count how many readings exceed the permit limit for each pollutant. If the number of exceedances for any pollutant reaches or exceeds the threshold defined in the rules, that turbine's emission status is NON-COMPLIANT. For every pollutant that triggers non-compliance, compute the exceedance percentage as the difference between the highest violating reading and the limit divided by the limit, multiplied by one hundred, then classify the severity according to the percentage brackets in the rules. Record each such finding as a gap with gap_type EMISSION, using "N/A" as the task_id, and include a detail string that names the pollutant, the limit, the count of readings above the threshold, and the maximum violating value.

Separately, assess spare parts readiness for each overhaul task assigned to the turbine. Each task lists the part IDs it requires. For every required part, look up its current quantity on hand through the tool, then add any incoming quantities found in the pending-orders text files stored alongside the other data files (these files list part IDs, incoming quantities, and estimated arrival dates for parts that are in transit). The effective available quantity is on-hand stock plus pending incoming stock. If that total is less than the minimum required (the stock multiplier from the rules, treated as an integer quantity), the part is short. Severity depends on whether on-hand stock is zero with no pending orders (HIGH), total available is below the part's reorder point (MEDIUM), or otherwise LOW. Each shortage produces a gap entry of type PARTS, tied to the specific task_id, with a detail string stating the part ID, on-hand quantity, incoming quantity, and the required amount.

On top of this, verify that qualified technicians are available for each overhaul task. Every task specifies a required certification type and a minimum certification level. Search for technicians holding that certification type at the required level or above. A technician qualifies only if they are marked active, their certification does not expire before the validity date stated in the rules, and they appear in the technician schedule JSON files with at least one available window. If no qualifying technician can be found for a task, flag it as a TECHNICIAN gap. The severity of this gap mirrors the task's priority: a HIGH-priority task missing a technician is a HIGH-severity gap, and so on.

Once all three dimensions have been evaluated for a turbine, determine its overall status. A turbine is COMPLIANT only if its emission status is COMPLIANT, its parts status is AVAILABLE, and its technician status is COVERED. Any other combination results in NON-COMPLIANT.

Save the compliance checklist as `compliance_checklist.csv` with exactly the columns specified in the policy file, sorted by turbine_id in ascending order. Save the gap report as `gap_report.csv` with the columns the policy file requires, sorted first by severity in descending order of importance (HIGH before MEDIUM before LOW), then by turbine_id, then by task_id. Both files must be written alongside the existing data files.

After writing both files, provide a brief summary stating the total number of turbines assessed, how many are fully compliant versus non-compliant, and the total count of gaps identified.
