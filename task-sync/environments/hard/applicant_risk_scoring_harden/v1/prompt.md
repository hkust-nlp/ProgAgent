The property management company has received a batch of rental applications that require comprehensive risk assessment before any approvals can be processed. Each applicant's risk profile must be evaluated across four dimensions: creditworthiness, income adequacy relative to the rent they would owe, any history of evictions, and the quality of references from previous landlords. The final deliverable is a prioritized review queue containing every applicant whose computed risk score meets or exceeds the designated review threshold defined in the risk configuration, sorted so the most concerning cases appear first.

The screening policy and configuration documents stored alongside the data are the authoritative specification for the assessment: they define the exact sub-score formulas for all four dimensions, the weights that combine them, every penalty, threshold, cap, and default value, the severity classification and recency treatment for eviction records, which landlord references count toward the reference evaluation, the risk tier boundaries, and the review threshold itself. The financial records, rental listings, and verification records stored in the same location supply the supporting facts those formulas consume. Nothing beyond those documents should be assumed, and every calculation must follow them.

Every applicant whose risk score meets or exceeds the review threshold belongs in the output queue. Save the queue as `review_queue.csv` with the following columns in this exact order: `applicant_id`, `full_name`, `risk_score`, `risk_tier`, `primary_flag`, `credit_score`, `income_to_rent_ratio`, `eviction_count`, `avg_reference_rating`. The `full_name` field concatenates first and last name separated by a single space. The `primary_flag` field names whichever of the four component sub-scores contributed the highest value for that applicant, using the labels `credit`, `income_ratio`, `eviction`, or `references`; break ties alphabetically. The `income_to_rent_ratio` should be rounded to two decimal places. The `avg_reference_rating` is the aggregate rating used in the reference sub-score computation, rounded to two decimal places; if no verified references exist, record it as `N/A`. Sort the file by `risk_score` descending; where scores are identical, sort by `applicant_id` ascending.

Once the file is written, provide a concluding summary stating the total number of applicants screened, the number placed into the review queue, the count of applicants in each risk tier across the entire applicant pool, and the full name and risk score of the single highest-risk applicant.
