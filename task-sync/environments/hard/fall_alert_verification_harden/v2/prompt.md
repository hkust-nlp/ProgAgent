You are the on-call analyst at a residential care facility that uses wearable and room-mounted motion sensors to generate automatic fall alerts for elderly residents. The system is known to produce a significant number of false positives, and every pending alert must be investigated before the nightly report goes out to emergency contacts. Your job is to review every alert currently marked as pending, determine whether it represents a genuine fall or a false alarm, and produce a clean incident report ready for distribution.

The verification methodology document and the configuration files stored in the working directory are the authoritative specification: they define how each alert's room and baseline profile are identified, how the peak acceleration and motion threshold are computed, how caregiver presence and audio evidence determine the verification outcome, and how severity levels are assigned. Every classification in your report must follow those definitions exactly — nothing beyond them should be assumed.

In addition to the report file, the final disposition of every pending alert must be recorded in the facility's incident management register: the verification outcome together with the assigned severity level, with false positives recorded at severity `n/a`.

Write an output file called `incident_report.csv` into the working directory. It must contain one row per pending alert, and the columns, in this exact order, must be `alert_id`, `resident_name`, `room_number`, `alert_timestamp`, `peak_acceleration`, `baseline_max`, `severity_level`, `verification_status`, `contributing_factors`, `emergency_contact_name`, `emergency_contact_phone`. The peak acceleration value must be rounded to exactly four decimal places. The severity level column should read `critical`, `high`, `medium`, or `low` for verified incidents, and `n/a` for false positives. The verification status column must contain exactly `verified` or `false_positive`. The contributing factors column must list three assessments in the fixed order of motion assessment, caregiver assessment, and audio assessment, separated by a semicolon and a space. The motion token is `motion_exceeded` when the peak exceeded the threshold or `motion_within_baseline` otherwise. The caregiver token is `caregiver_exempt_present` when an exempt visit overlapped or `no_caregiver_overlap` otherwise. The audio token is `audio_confirmed` when a qualifying event was found or `no_audio_confirmation` otherwise. Emergency contact name and phone come from the contacts reference file in the working directory, using the primary contact for the resident linked to each alert. Rows must be sorted first by severity rank in ascending order, using the rank numbers from the severity tiers file, with false-positive rows assigned rank five, and then by alert timestamp ascending as a tiebreaker.

After writing the report, state in your final response the total count of alerts you reviewed, the count you confirmed as true fall incidents, and the count you classified as false positives.
