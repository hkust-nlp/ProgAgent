## Task Topic

Optimize shift assignments by cross-referencing real-time machine maintenance logs, operator certification matrices, production line throughput targets, and historical absenteeism patterns to generate a daily staffing plan that minimizes downtime.

|---------|---------------|---------------------|
| v0      | 30            | 8                   |
| v1      | 60            | 16                  |
| v2      | 120           | 24                  |
| v3      | 240           | 32                  |

Scaling ratios: rows follow 1×/2×/4×/8×; workspace files follow N/N+N/N+2N/N+3N where N=8.

### Structural Dimensions

- **Conditional Constraints**: Assignment eligibility depends on certification level (with a stricter threshold for critical/high-priority lines), absence rate caps, and maintenance severity thresholds — all configured via workspace files rather than hard-coded.
- **Information Scattering**: Production targets and operator availability live exclusively in workspace CSV/JSON files, while machine details, certifications, maintenance logs, and absenteeism history are only accessible through tool calls. Solving the task requires merging both sources.
- **Multi-Hop Reasoning**: The dependency chain runs at least four hops deep: list production lines → retrieve line machines → check maintenance status to filter operational machines → fetch certifications and cross-reference with workspace availability and absence rates → apply ranking rules → assign.

## Hardening (M0 + M1 + M4)

Applied on top of `environments/standard/shift_optimization_daily_plan`. `_compute_ground_truth()` is byte-identical to SOURCE; `step()` is unchanged except for one added M4 DB-state criterion (`db_assignments_recorded`, 15 pts — original six criteria and weights untouched; reward is normalized over 115).

- **M1 JSON-string parameters**: two query tools take a single `filter` parameter that must be a JSON-encoded string.
  - `query_maintenance_logs` (replaces `get_line_maintenance`): supported filter properties `line_id`, `resolved` (boolean), `min_severity` (integer); same columns as SOURCE, unfiltered superset reachable.
  - `list_operators`: supported filter properties `skill_tier` (junior|mid|senior), `department`; pagination unchanged.
  - Malformed JSON returns `invalid_json` with line/column/char position; an object passed instead of a string, unsupported keys, and wrong-typed values return recoverable API-style errors, one at a time.
- **M4 nested write payload**: new write tool `create_shift_assignment(payload)` with a Notion-style body (`parent.type="shift_roster"` + `parent.shift_id`, `properties.Machine.reference.machine_id` + `properties.Operator.reference.operator_id`, optional `Note` rich_text). Validation is layered, one error per call (`body should be defined, instead was 'undefined'.` → parent → shift_id → properties → Machine → Operator → Note), followed by business checks (404 unknown shift/machine/operator, 400 duplicate shift+machine slot). The write INSERTs into a `shift_assignments` roster table (created lazily); SOURCE had no write tool, so the "record via the write API" deliverable was added per the M4 exception and `prompt.md` gained one recording sentence.
- **Error contract**: tools never raise; all failures return `{status, object:"error", code, message, request_id}` which shares no keys with any success shape (verified programmatically). Not-found → `404/object_not_found`; bad input → `400/validation_error` / `400/invalid_json` / `400/invalid_request`. `get_operator_info`, `get_line_machines`, `get_line_certifications`, `get_operator_absence_rates` upgraded from ad-hoc `{"error": ...}` / empty returns to this contract.
- **Return shapes (no M2 assigned — all success returns native)**: `list_production_lines` list; `get_line_machines` list; `query_maintenance_logs` list; `get_line_certifications` list; `get_operator_absence_rates` list; `get_operator_info` dict; `list_operators` paginated dict; `create_shift_assignment` deep-echo dict (`object:"assignment"`, `created:true`).
- **verify()**: ports the SOURCE computation 1:1, consuming the hardened surface (JSON-string filters incl. `resolved:false` maintenance query, nested write payloads, error branching on `object=="error"`). Reward **1.0 at v0 (52 tool calls)** and **1.0 at v3 (418 tool calls, 115/115)**.
- **Negative-path smoke tests** (all pass): malformed M1 JSON (`invalid_json` with position), dict-instead-of-string, unsupported/wrong-typed filter keys, unknown line 404; full M4 ladder exercised one error at a time (undefined body, string body, missing parent, wrong parent.type, missing shift_id, missing properties/Machine/Operator, wrong property type, missing reference, empty id, bad Note, unknown shift/machine/operator 404s, duplicate slot 400).
