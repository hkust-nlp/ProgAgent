A national health authority has just released a set of updated clinical trial safety guidelines for the current year, introducing requirements across several categories including adverse event reporting, dosage monitoring, informed consent, biospecimen handling, patient monitoring, and data integrity. Each new guideline specifies which trial phases and therapeutic areas it applies to, along with its severity classification and whether it mandates a consent form update. Your task is to produce a comprehensive compliance action plan by cross-referencing these new guidelines against all currently active clinical trials. For each active trial whose phase and therapeutic area fall within the scope of a new guideline, you must compute a priority score and determine the appropriate amendment type and compliance deadline.

The policy and configuration documents stored alongside the data are the authoritative specification: they define the new guidelines and their scope, the assessment methodology, the scoring parameters and formulas, the amendment type precedence rules, the deadline brackets, and how missing or edge-case inputs are handled. Nothing beyond those documents should be assumed, and every determination must follow them.

The resulting action plan must be saved as `compliance_action_plan.csv` with the following columns in this exact order: `trial_id`, `trial_name`, `site_id`, `guideline_code`, `guideline_category`, `severity`, `priority_score`, `amendment_type`, `deadline_days`. The action plan CSV must be sorted in descending order by priority score. Where two entries share the same priority score, sort them by trial identifier in ascending alphabetical order, and if those also match, by guideline code in ascending alphabetical order.

Separately, you must produce a consent update report saved as `consent_update_report.json`. This is a JSON array of objects, one per trial that is affected by at least one guideline requiring a consent update. Each object must contain the fields `trial_id`, `trial_name`, `current_form_version` (the version string of the trial's most recent consent form by approval date, or the string `none` if no consent exists), and `affected_guideline_codes` (a sorted list of the guideline codes that require consent updates for that trial). The array itself must be sorted by trial identifier in ascending order.

Once both files are written, provide a brief summary stating how many entries appear in the action plan, how many distinct trials are affected, how many distinct guidelines are involved, and how many trials require consent form revisions.
