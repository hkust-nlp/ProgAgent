You are preparing the risk briefing for the next sprint planning session. Your organization tracks project milestones across multiple teams and needs to identify which upcoming and in-progress milestones carry the highest delivery risk so that leadership can allocate mitigation resources before the next iteration begins. Every milestone whose status is either upcoming or in progress must be assessed across four risk dimensions, and the dimension scores combine into an overall weighted risk score that determines each milestone's risk level.

The methodology and configuration documents stored alongside the data are the authoritative specification: they define the four risk dimensions and their exact formulas, every normalization factor, default value, and threshold, the dimension weights, and how the overall risk score and risk level are determined. Nothing beyond those documents should be assumed, and every calculation must follow them.

Save a file called `risk_assessment.csv` containing one row per assessed milestone with columns: milestone_id, milestone_name, estimation_accuracy_score, dependency_risk_score, bug_escape_score, team_churn_score, overall_risk_score, risk_level. All scores must be rounded to four decimal places. Sort rows by overall_risk_score in descending order; break ties by milestone_id in ascending order.

Separately, save a file called `mitigation_checklist.md` that covers every milestone classified as HIGH, presented in the same sort order as the CSV. For each high-risk milestone, include a markdown level-two heading with the milestone name and its ID in parentheses, followed by the overall risk score and the four dimension scores each on their own line prefixed with a dash. Then list concrete mitigation actions for every dimension whose score exceeds the mitigation action threshold from the configuration. Mitigation actions should reference specific data: for estimation accuracy state the historical ratio, for dependency risk list the at-risk dependency identifiers sorted ascending, for bug escape state the count of escaped bugs out of total bugs, and for team churn list the churned member identifiers sorted ascending.

In your final response, list all high-risk milestone names in descending order of their overall risk score (ties broken by milestone ID ascending), separated by commas, prefixed with the text "High-risk milestones: ". If no milestones are high risk, state that none were identified.
